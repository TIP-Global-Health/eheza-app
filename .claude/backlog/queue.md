**LIVE IMPLEMENTATION GOTCHAS (learned implementing B-025 + B-037, 2026-07-05):**
- **The main working tree `/var/www/html/ihangane` is often on the USER's parallel-terminal branch** (was `readability-if-conditions`), NOT develop, and origin/develop advances during a session (e.g. PR #1885 merged mid-session). ⇒ ALWAYS `git fetch origin develop` then create an ISOLATED WORKTREE off `origin/develop` per finding (`git worktree add <scratchpad>/wt-bNNN -b bNNN-slug origin/develop`). Do NOT switch the main tree's branch (disrupts the user) and do NOT assume the checkout is on develop.
- **Elm builds in a fresh worktree need 4 gitignored/generated inputs symlinked from the main tree's `client/`:** `node_modules`, `elm-stuff` (877M — symlink, don't copy), `src/generated` (gulp-generated zscore/version), and `src/elm/LocalConfig.elm`. Without them `elm make` fails (Main imports LocalConfig + generated modules). Symlink is safe (read-mostly); the one caveat is elm-stuff is shared so a concurrent user compile could thrash the cache (recoverable).
- **⚠ elm-stuff SYMLINK BREAKS elm-test (discovered 2026-07-06, B-052):** elm-test writes its generated project under `elm-stuff/generated-code/.../elm.json` with RELATIVE source-directories (`../../../../../src/elm`) that resolve THROUGH the symlink into the MAIN tree — so `elm-test` in a symlinked-elm-stuff worktree silently compiles/tests the MAIN tree's sources, not the worktree's (passes are vacuous; new worktree-only Test modules break the build with confusing MODULE NOT FOUND). Fix: `rm elm-stuff && mkdir elm-stuff` in the worktree before running elm-test (cold compile ~1-2 min; elm make also fine after). `elm make` alone IS safe with the symlink (runs from worktree cwd).
- **elm/elm-format are HOST-GLOBAL** (`~/.nvm/.../bin`, elm 0.19.1); **elm-test/elm-review are PROJECT-LOCAL** (`client/node_modules/.bin/`). The host `elm-test` is too new — use the project-local one.
- **elm-test needs the glob:** `./node_modules/.bin/elm-test "src/elm/**/Test.elm"` — a bare `elm-test` fails with "tests/ directory does not exist" (project keeps tests as `src/elm/**/Test.elm`, not `tests/`).
- **`elm make` floods stdout** with hundreds of `Compiling (N)` lines — pipe to `tail` / redirect. A clean run ends `Success! Compiled N modules.` (currently 548).
- **JS changes:** `node --check <file>` only (no JS unit framework); do a forced-throw sanity/discrimination snippet in scratchpad instead.
- **Copilot review (ASK FIRST — never automatic, 2026-08-02):** `gh api repos/.../pulls/N/requested_reviewers -X POST -f "reviewers[]=copilot-pull-request-reviewer[bot]"`, verify via `gh api .../pulls/N --jq '.requested_reviewers[].login'` (returns `Copilot`).
- **⚠ SimpleTest fixtures: some bundles need their fields AT CREATE, not after (learned 2026-08-03, cost a CI cycle).** `drupalCreateNode(['type' => 'pmtct_participant'])` followed by wrapper `->set()` calls throws `EntityMetadataWrapperException: Invalid data value given. Value at node():` — the insert hooks read `field_person` / `field_adult` / `field_clinic` while they run. `HedleyWebTestBase::createPMTCT()` already solves this by passing the fields into node creation, and says so in a comment; `createClinic()`, `createHealthCenter()` and friends exist too. **Look for a base-class helper before hand-rolling a fixture.** Measurement bundles (e.g. `whatsapp_record`, `acute_illness_trace_contact`) tolerate bare-create-then-set because they have no insert hooks — but populate their required fields anyway, or the fixture only stands up because Drupal 7 skips field validation on programmatic save. CI reports this as "N passes, 0 fails, and 2 exceptions" — an exception count, not a failure count, so **grep the log for `exception`, not just `fail`**.
- **For mechanical 1-line fixes** (list append, sign flip, key swap): elm make + elm-test regression is sufficient — don't build heavy fixtures/expose View helpers just to unit-test a trivial change (matches R5-1/R6-1 precedent). Reserve discrimination tests for subtle logic (inversions, extractable pure helpers).
