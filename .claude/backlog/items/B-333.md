### B-333 — Admin lists: the "E-ledger viewer" role, which the ledger scopes to the user's own health centres, can open every health centre's children, mothers, measurements, sessions and CSV exports through the sibling views, whose access is left at the Views default `access content` — READY · CONFIRMED (both view exports, the Views plugin default, the permission export and the ledger gate read; live role count) · MED-LOW · tier 3 · R29 unit 5 · 3 active E-ledger viewer users on ihangane (other sites not counted)
- **Mechanism.** The ledger is guarded by the health-centre plugin (`hedley_admin.module:318-350`: administrator → TRUE; E-ledger viewer / nurse → `in_array($child_center_nid, $account->field_health_centers)`), but the two listing views leave the permission plugin at its default: `display_options['access']['type'] = 'perm'` at `hedley_admin.views_default.inc:29` (`admin_views`) and `:1749` (`historical_child`) with no `['access']['perm']` key anywhere in the file and no display overriding it — Views' default is `access content` (`contrib/views/plugins/views_plugin_access_perm.inc:45-49`), and `hedley_admin.features.user_permission.inc:15-22` grants exactly that to `E-ledger viewer`, `administrator`, `sync` (this feature is the only owner of the permission, so `fra` on every deploy keeps it so).
- **Reachability.** An E-ledger viewer attached to HC X opens by URL `admin/content/children`, `admin/content/mothers`, `admin/content/measurements`, `admin/content/sessions`, `admin/content/clinics`, `admin/content/nurses`, `admin/measurement-historical-mother`, `admin/measurement-historical-child` (child name, DOB, gender, nurse, z-scores, parent) and the CSV displays `admin/content/{childs,mothers,measurements,sessions,clinics}/csv` — all unscoped; only `admin/ledger/N` is limited to X. Live ihangane: 3 users hold the role, all active.
- **Impact.** Staff-facing data scoping across health centres; all sites. Not device-trust/PIN/IDOR — an HC-scoped human role reading other HCs' patients.
- **Fix shape (guess).** Give the two listing views an explicit permission the role does not hold (or extend the health-centre plugin to them). Ask first whether the role is still meant to exist.
