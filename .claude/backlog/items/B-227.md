### B-227 — Prenatal lab results: the Blood Smear row never shows a result, so a malaria diagnosis made by smear has no lab-results entry at all — ✅ **IMPLEMENTED 2026-09-09, issue #2227, PR #2229** (branch `B-227-blood-smear-lab-results-row`, base `B-338-smear-order-memory` — stacked behind #2224 and #2228) · CONFIRMED (anchor + commit diff verified) · MED · tier 3 · R24 unit 7
- **Mechanism.** `Pages/Report/View.elm:973-987` builds `bloodSmearTestResults` from `data.malaria` with the predicate `(not <| testPerformedByExecutionNote value.executionNote) && bloodSmearResultNotSet value.bloodSmearResult`. `bloodSmearResultNotSet` (`Measurement/Utils.elm:2671-2678`) is `List.member value [BloodSmearPendingInput, BloodSmearNotTaken]`, so the filter KEEPS the entries with no result and DROPS `BloodSmearNegative/Plus/PlusPlus/PlusPlusPlus`. Commit `5d553d346` ("Add ability to identify ordered Blood Smear test", 2024-01-16) rewrote the original `value.bloodSmearResult /= BloodSmearNotTaken` into `bloodSmearResultNotSet …` — the opposite meaning; its sibling `bloodSmearResultSet` (:2671) is what the other callers use. The row is then wrapped in `showIf (not <| List.isEmpty bloodSmearTestResults)` (:999-1000), so it is never rendered. ⚠ The scout's second leg ("executionDate is always Nothing on the smear path") is only half true: the nurse's immediate-result handler `Pages/Prenatal/Activity/Update.elm:2553-2563` DOES set `executionDate = Just currentDate`; the lab-tech result path (`RecurrentActivity/Update.elm:993` + `malariaResultFormWithDefault` `or form.executionDate value.executionDate`) does not, and neither does the pending/ordered state. Net: resulted entries are dropped by the predicate, un-resulted ones by the missing date — the list is `[]` in every state.
- **Reachability.** Prenatal progress report → lab results pane (`Pages/Prenatal/ProgressReport/View.elm:~2155` supplies `malaria`); NCD passes `malaria = []`. The RDT row (`LabResultsHistoryMalaria`) also excludes smear entries because `testPerformedByExecutionNote` is False for them — so a smear-diagnosed malaria appears in NEITHER row. Live since v1.14-era; identical on `origin/main`.
- **Impact.** Nurses reviewing a pregnancy's labs cannot see blood-smear malaria results; the Translate/Model plumbing for `LabResultsHistoryBloodSmear` is dead in practice. All sites.
- **Evidence.** `git show 5d553d346 -- Pages/Report/View.elm` shows the one-line inversion; predicate and both date paths read at anchors. A live count (blood-smear rows by result value × has-execution-date) was blocked by the auto-mode classifier — `SELECT r.field_blood_smear_result_value, COUNT(*), SUM(d.field_execution_date_value IS NOT NULL) FROM field_data_field_blood_smear_result r LEFT JOIN field_data_field_execution_date d ON d.entity_id=r.entity_id WHERE r.bundle='prenatal_malaria_test' GROUP BY 1` would size it.
- **Fix shape (guess).** Filter on `bloodSmearResultSet`; for the date, fall back to the measurement's `dateMeasured` when `executionDate` is Nothing (lab-tech path). Decide whether pending smears should show (the pre-5d553d346 code showed them).
