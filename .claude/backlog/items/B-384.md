### B-384 — Un-enrolling a nurse from the resilience programme hides the Wellbeing card but leaves the reminder modals firing and the pages routable, because three entry points test three different things — READY · CONFIRMED (orchestrator read all three gates) · LOW · tier 4 · R33 unit 5 · latent (no nurse is in the mismatched state today) · ihangane only
- **Mechanism — three gates for one programme.** The main-menu card tests the flag:
  ```elm
  -- client/src/elm/Pages/PinCode/View.elm:297
                          ++ (if nurse.resilienceProgramEnabled then
                                  [ MenuWellbeing ]

                              else
                                  []
                             )
  ```
  Both main-menu modals in the same file test the start date instead (`:419` `nurse.resilienceProgramStartDate`, `:439` `if notificationTimeReached && isJust nurse.resilienceProgramStartDate then`). The page renderers test neither — `App/View.elm:1216` `MessagingCenterPage` and `:1235` `WellbeingPage` read `loggedInModel.nurse` and render unconditionally, and `Pages/Router.elm` maps `#/messaging-center`, `#/wellbeing` and `#/messaging-guide` with no check.
- **Consequence.** `field_resilience_program` is the only admin lever, and turning it off removes the entrance while the pop-ups keep firing with a working way in — the notification modal's "Read" button dispatches `SetActivePage <| UserPage MessagingCenterPage`. The other conceivable lever, clearing `field_resilience_start_date`, is not an alternative: it resets the nurse to the kick-off survey and strands her message blob. A nurse reaching `MessagingCenterPage` without a start date is shown the kick-off survey, and saving it sets `resilienceProgramStartDate` — arming the modals for a nurse the admin never enrolled.
- **Reachability.** Admin unchecks Resilience Program on a nurse who has already kicked off. The self-enrolment half is weaker: no UI path reaches `#/messaging-center` for a never-enrolled nurse other than typing or restoring the URL.
- **Evidence.** All 20 nurses with a start date on ihangane.live also have `field_resilience_program = 1`, so nothing is in the mismatched state today — latent, not currently firing.
- **Context, not a finding.** The notification modal has no programme-end bound: `SetLoggedIn` re-arms it via `SetNextNotification`, so it shows on the first main-menu render after every login whenever unread > 0, and unread is computed over the generated 93-message inbox with any message absent from the stored blob defaulting to unread. ~10 of the 20 enrolled nurses still have unread messages ~17 months after their programme ended. That may be the intended nudge; recorded so it is not re-found as a defect.
- **Fix shape (guess).** Make one predicate the programme gate and apply it at every entry point — card, both modals, page renderers — instead of card-on-flag / modals-on-start-date.
