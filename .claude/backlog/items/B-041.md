### B-041 — Dashboard HIV undercounts known-positive patients: the "dedicated" execution-note query reuses `$query` instead of cloning → demands BOTH test_result AND execution_note rows — ✅ IMPLEMENTED 2026-07-05 (issue #1892, PR #1893, branch `b041-hiv-execution-note-dedicated-query`, base develop @91fb401fb, CI running, Copilot requested). Fix: `$query = clone $base_query;` before the execution-note block in `hedley_stats_get_ncd_data` (anchor was :1384 comment block). php -l + phpcs Drupal/DrupalPractice clean.
- `hedley_stats.module` ~:1363-1391: after running the test-result query (`$query` with `leftJoin field_data_field_test_result` + `condition('test_result.bundle','ncd_hiv_test')`, ~:1363-1369, executed :1371), the code adds MORE joins to the SAME `$query` (`leftJoin field_data_field_test_execution_note` + `condition('test_execution_note.bundle','ncd_hiv_test')`, ~:1391) and re-runs it. The comment explicitly says a "dedicated query is mandatory" — intent was a fresh query, but `$query` was reused.
- Fix: `$query = clone $base_query;` (or rebuild) before the execution-note joins. Severity HIGH (clinical dashboard undercount of exactly the known-positive cohort). Companion to the deleted-filter gaps in the same builders (B-032).
