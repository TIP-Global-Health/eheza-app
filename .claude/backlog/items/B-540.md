### B-540 — Statistical Queries demographics and the aggregated NCDA scoreboard treat the person node's UPLOAD day as the registration date, so a child registered on a tablet in one month and synced in the next is missing from the earlier month's column and from "registered between FROM and TO" — READY · LOW-MED · tier 4 · CONFIRMED (code; sized on the 2026-11-02 ihangane copy) · DEPLOYED · data-model gap (no registration date on `person`) · R49 unit 1
- **Mechanism.** Both admin apps receive `person.node.created`:
  ```php
  -- server/hedley/modules/custom/hedley_reports/hedley_reports.module:516-518
    $data = [
      'id' => $person->nid,
      'created' => date("Y-m-d", $person->created),
  ```
  ```php
  -- server/hedley/modules/custom/hedley_ncda/hedley_ncda.module:424-425
      $decoded = json_decode($r->field_ncda_data_value);
      $decoded->created = date('Y-m-d', $r->created);
  ```
  and read it as the registration date:
  ```elm
  -- server/elm/src/Pages/Reports/View.elm:268-269
          ( males, females ) =
              List.filter (\record -> Date.compare record.created startDate /= LT) records
  ```
  (plus `Pages/Reports/Utils.elm:815-816`, "Patient was created not after the TO date"), and on the scoreboard
  ```elm
  -- server/elm/src/Pages/Scoreboard/Utils.elm:483-485
  registeredBy : NominalDate -> { a | created : NominalDate } -> Bool
  registeredBy targetDateForMonth record =
      Date.compare record.created targetDateForMonth /= GT
  ```
  used at `Pages/Scoreboard/View.elm:126, 204, 284, 431, 555, 662, 821` to decide whether a child belongs in each month column. `person` carries no clinical registration date (`field_birth_date` and `field_birth_date_estimated` only; `hedley_person.features.field_instance.inc`), so `created` is the only date there is.
- **Reachability.** Reports: as B-539. Scoreboard: `hedley_ncda_generate_results_data_for_restful` → aggregated NCDA scoreboard, `hedley_admin_feature_ncda_enabled` (ihangane in practice).
- **Size.** Proxy, since no true registration date exists: of 37,402 persons created since 2025-01-01, 1,911 (5.1 %) already hold a measurement dated in an EARLIER month than the month the person node arrived — a measurement cannot precede registration clinically (orchestrator re-ran the count). B-503 fixed the boundary of `registeredBy`; this is the value it compares.
- **Fix shape (first guess).** Short term, where the JSON is built: floor the shipped `created` at the earliest clinical date the person's own data carries (earliest `field_date_measured`, encounter `field_scheduled_date`, participant `field_expected`). Proper fix: a client-sent registration date on `person` — a new FIELD, safe in one release, unlike a new enum value.
