### B-411 — `server/scripts/setup-dev` writes Drupal's settings files to the repository root instead of the docroot — READY · CONFIRMED (orchestrator read the script and its siblings) · LOW · tier 4 · R34 unit 4 · dev-only, unreferenced script
- **Mechanism.**
  ```bash
  -- server/scripts/setup-dev:14-19
  ROOT=$(git rev-parse --show-toplevel)
  OLD_DIR=`pwd`
  cd $ROOT
  if [ ! -d www ]; then
    mkdir -p www/sites/default/
  fi
  ```
  Every sibling resolves the server root as `cd ${0%/*}/..` (`server/scripts/build:8`, `server/install:15`, `server/scripts/reset:14`). `--show-toplevel` gives the **repository** root, so this creates `<repo>/www/sites/default/` and writes `settings.php` and `settings.local.php` there — while the docroot is `server/www` (`.ddev/config.yaml:3`).
- **Impact.** A developer running it gets a Drupal install with no `settings.php` in the docroot, plus a stray untracked `www/` at the repo root. The script is referenced nowhere — not in the repo, CI, the ddev commands or the docs — so it is effectively dead for the native (non-ddev) DB setup path.
- ⚠ **It corrects a coverage verdict:** `coverage.md`'s R18 deploy/build row lists `setup-dev` as clean. That verdict is wrong.
- **Fix shape (guess).** Resolve the root the way its siblings do, or delete the script if the native path is no longer supported — a question for the user, since "unreferenced" and "unused" are not the same thing here.
