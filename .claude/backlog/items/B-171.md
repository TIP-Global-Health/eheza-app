### B-171 — Dashboard's "Last updated" always reads as just now, whatever the age of the figures beside it — ❌ **CLOSED 2026-08-16 by user: "Close this item. I see no value in it."** ⛔ DO NOT RE-PITCH in any form (per-section timestamps, oldest-section label, relabelling). Mechanism below is CONFIRMED and stays only so nobody re-finds it and files it again.
- `Pages/Dashboard/View.elm:212` renders `assembled.stats.timestamp ++ " UTC"` under a *"Last updated"* label. The server sets that field at SERVE time — `hedley_stats_pull_stats_for_health_center()` does `$now = time(); $stats['timestamp'] = date('d-m-Y, H:i', $now - date('Z'))` — and is called from `HedleyRestfulSync.class.php:338` on every sync, while the sections themselves come out of `cache_get`. **So the label reports when the device fetched the page, never when the numbers were computed.**
- Impact: it asserts freshness the figures do not have. Live 2026-08-16: **12 of 22 case-management cache entries on ihangane were computed the PREVIOUS month** (oldest 40 days), all with `expire = 0`, and every one of those dashboards said it was up to date. This is why B-163's month shift went unreported for so long — the page told everyone the data was current.
- ✅ The true generation time IS recorded per section (`HEDLEY_STATS_CACHE_SET` stores `['timestamp' => time(), 'value' => …]`) and B-163 added **`HEDLEY_STATS_CACHE_GET_TIMESTAMP`** to read it. The plumbing exists.
- ⛔ **Why B-163 did NOT fix it, and why a naive fix is wrong (review finding on PR #2090):** sourcing the label from any ONE cache misreports the rest. `hedley_stats_clear_caches_for_health_center()` returns EARLY for prenatal, acute illness, NCD, PMTCT, SPV, child scoreboard and group education (`hedley_stats.module:521-549`), so those refresh WITHOUT touching the case-management entry. A health centre with daily prenatal activity and no nutrition activity would show a months-old timestamp beside current prenatal figures — a new lie replacing the old one.
- Fix shape (**a decision, not a mechanism — present before building**): (a) per-section timestamps, each page showing its own; (b) one label showing the OLDEST section, so it never overstates freshness; (c) keep serve time but re-label it as what it is. (a) is the honest one and the most work; (b) is small and never overstates. ⚠ The label is also the only place a user could ever notice staleness, so whatever ships should make an old cache VISIBLE rather than merely accurate.
