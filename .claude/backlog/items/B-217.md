### B-217 — Patient consolidation: the tool accepts original == duplicate (and unloadable / already-deleted ids) and then soft-deletes the patient's whole history — CONFIRMED (orchestrator-read `_consolidate_patients_validate` — only bundle + health-centre checks exist) · MED (admin-tool guard) · tier 3 · both sites · R23 unit 6
- **Mechanism.** `hedley_patient.drush.inc:133-198` `_consolidate_patients_validate()` checks `getBundle() === 'person'` for both and equal `field_health_center`, nothing else: no `$original == $duplicate`, no node-exists, no `field_deleted` check on either side. With the same id on both sides validation passes (same HC; session validate: original participates in all its own clinics; single-participant validate: ≤1 participant). `_consolidate_patients_execute()` then: `_consolidate_single_participant_content_execute` (`:1235-1274`) re-points P's encounters to P and marks the "duplicate" participant `field_deleted` → `hedley_person_process_deleted_update` cascades encounters → measurements (same shape for prenatal `:839-846`, incl. an ongoing pregnancy, and family nutrition); `_consolidate_patient_relationships` (`:293-349`) finds every key already in `$existing` → all soft-deleted; `_consolidate_patient_group_participations` (`:563-608`) likewise; finally the person is marked deleted (the presave guard at `hedley_person.module:~1163` only refuses if live measurements remain, which after the cascade is true only for group-session measurements).
- **Reachability.** Admin UI `admin/content/consolidate-patients` (two free-text id fields, `hedley_patient.module:322-342`) and `drush consolidate-patients`. A paste/typo of the same id is the trigger. Nonexistent ids: `entity_metadata_wrapper()->getBundle()` throws `EntityMetadataWrapperException` uncaught in the form submit → WSOD rather than a message. A deleted ORIGINAL silently receives live content under a soft-deleted person.
- **Impact.** One wrong submission soft-deletes participants, encounters, measurements, relationships and the group enrolments the person brings children to. Reversal is itself broken (B-218). No evidence it has happened (B-120's census found 18 merge pairs, all distinct) — this is a guard, not a repair.
- **Fix shape (first guess):** in `_consolidate_patients_validate`, before anything else: reject equal ids, ids that do not load as `person`, and a `field_deleted` original or duplicate. The test file (`tests/HedleyPatientConsolidation.test`) has no such case — add one.
