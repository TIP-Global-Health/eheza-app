### B-314 — Growth charts: on three charts the y-axis gridlines and labels are spaced by tick index while the points are plotted by value, so a label like "45 cm" sits where 46.75 cm data is drawn — READY · CONFIRMED (tick builder + `plotPoints` read; tick lists reproduced) · MED-LOW · tier 3 · R28 unit 6 · ⭐ DEPLOYED (all sites)
- **Mechanism.** `yAxisLinesAndText` (`client/src/elm/ZScore/View.elm:1589-1604`) builds the tick list as `Float.Extra.range {start = minY, end = maxY, steps = round (maxY - minY)}` filtered to `minY`, `maxY` and multiples of `yAxisIntervals`, then places them at `spaceBetweenLines = height / (listCount - 1)` per index. Points and reference curves go through `plotPoints` (`:586-599`), linear in value (`plotY y = out.maxY - (y - in.minY) * scaleY`). When `minY`/`maxY` are not multiples of the interval, the tick VALUES are uneven but the tick POSITIONS are even, so every gridline is at the wrong value.
- **Affected configs.** `heightForAgeConfig` (length-for-age 0–2, `:194` `minY = 42, maxY = 99`, interval 5) → ticks `[42,45,50,…,95,99]`: "45" drawn at 46.75 cm, "50" at 51.5, "60" at 61.0, "95" at 94.25 — up to **1.75 cm** off. `weightForHeightConfig` (0–2, `:368` `1..25`, interval 2) → "2" at 2.85 kg, "24" at 23.15 — up to **0.85 kg**. `weightForHeight0To5Config` (`:397` `1..32`, interval 2) → "2" at 2.94 kg, "16" at 16.5 — up to **0.94 kg**. The other nine configs have evenly valued tick lists and align (`weightForAgeConfig` 1.4–17.8 yields odd labels like "2.43" but at correct positions).
- **What is NOT wrong.** Reference z-curves and the child's dots are mutually consistent (both via `plotPoints`), so the z-band a point falls in is right; only the numeric grid lies.
- **Reachability.** `viewGrowthPane` → `heightForAge` / `weightForHeight` (children < 26 months) and `weightForHeight0To5` (26–60 months) (`Pages/WellChild/ProgressReport/View.elm:1356-1371`); reached from every child progress report — WellChild, Nutrition (`Pages/Nutrition/ProgressReport/View.elm:88`), ChildScoreboard (`:111`), group session (`Pages/ProgressReport/View.elm:59`), PatientRecord (`Pages/PatientRecord/View.elm:180`), and the WhatsApp-sent report image. No site split.
- **Impact.** A clinician reading a value off the grid reads it ~1–2 cm / ~0.5–1 kg wrong near the bottom of the two most-used charts.
- **Fix shape (guess).** Place y ticks with the same `plotY` mapping the data uses instead of `height / (listCount - 1)`; or choose `minY`/`maxY` that are multiples of the interval for those three configs.
