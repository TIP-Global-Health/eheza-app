### TH-35 — Offline-saves cold-worker e2e (#2422): the "worker stopped" wait can pass on the previous round's status, so a round may run against a warm worker — READY · L · unit
- **Gap.** `client/e2e/offline-save-cold-worker.spec.ts:49-60` tracks `workerStatus` only through `ServiceWorker.workerVersionUpdated` events and never resets it. Round 0 starts from `''` and really waits for `stopped`. From round 1 the variable still holds `stopped` from the previous round, so the `expect.poll` after `stopAllWorkers` passes at once unless the `starting`/`running` events for the worker that answered the previous round's fetches already arrived. In practice they do (the browser emits them before the worker can answer), so the loss is at most a warm round, never a vacuous test; the 20-round loop keeps the test discriminating (8/20 failures on pre-fix `nodes.js` in the recorded control).
- **Evidence.** Read at develop `739f67ef3`; the spec runs once in CI, in `e2e_playwright_1`'s second command (`playwright --list` run by the R46 scout). No CI failure traced to this.
- **Shape.** Reset `workerStatus = ''` immediately before each `stopAllWorkers`, so every round waits for a fresh `stopped` event. One line, no behaviour change in the app.
- **Related.** B-168 (the fix the spec guards), B-511 (per-request reopen while `verno != dbVerno`), B-478 (non-atomic node-then-row write).
