### B-410 — `generateReleaseNotes` drops all GitHub enrichment when `origin` is an HTTPS remote, because it reads the org and repo from fixed split indices — READY · CONFIRMED (orchestrator ran the split) · LOW · tier 4 · R34 unit 4
- **Mechanism.**
  ```php
  -- server/RoboFile.php:311-317
      if (!empty($remote)) {
        $origin_parts = preg_split('/[:\/]/', str_replace('.git', '', $remote));
        if (!empty($origin_parts[1]) && !empty($origin_parts[2])) {
          $github_org = $origin_parts[1];
          $github_project = $origin_parts[2];
        }
      }
  ```
  The indices assume the SSH form (`git@github.com:ORG/REPO`). Verified by running it:
  ```
  $ php -r 'var_export(preg_split("/[:\/]/", str_replace(".git","", "https://github.com/ORG/REPO")));'
  array ( 0 => 'https', 1 => '', 2 => '', 3 => 'github.com', 4 => 'ORG', 5 => 'REPO', )
  ```
  so `[1]` and `[2]` are empty strings and `$github_org` is never set.
- **Impact.** Release notes degrade to bare `- Issue #N` lines with no issue titles, no contributors section and no code-statistics section — the whole changelog for that release. It does print `No GitHub project or GitHub organization found`, so it is not silent, but an operator following `deploy-release/SKILL.md` Step 6 on the happy path pastes the degraded output into the GitHub release.
- **Fix shape (guess).** Take the last two non-empty segments rather than indices 1 and 2.
