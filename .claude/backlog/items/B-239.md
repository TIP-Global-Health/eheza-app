### B-239 — Prenatal recurrent labs: the Partner HIV follow-up form has no Save button, so the answers can never be recorded and the encounter can never be ended — READY · CONFIRMED (anchors verified; not reproduced in a browser) · MED-HIGH · tier 3 · R25 unit 2
- **Mechanism.** In `viewLabResultFollowUpsContent` (`Pages/Prenatal/RecurrentActivity/View.elm:~713-790`), `formHtmlAndTasks` renders three tasks — `TaskHIVTest`, `TaskSyphilisTest` and `TaskPartnerHIVTest` (:734-737) — but the `saveMsg` case below (:769-780) handles only `TaskHIVTest` and `TaskSyphilisTest` and drops `TaskPartnerHIVTest` into `_ -> Nothing`. `Maybe.map (\msg -> viewSaveAction …) saveMsg |> Maybe.withDefault emptyNode` then draws nothing. ⚠ Do not confuse this with the **other** `saveMsg` in the same file (:338-341), which belongs to the ordinary Lab Results content and *does* handle `TaskPartnerHIVTest` — that is the sibling that was updated. `git show 80fa884d4` added the follow-ups render arm and left this save arm untouched.
- **Reachability.** Partner HIV test ordered at the initial phase without an immediate result → lab tech enters `Positive` in the recurrent encounter → `toPartnerHIVResultValue` with `isLabTech = True` (`Measurement/Utils.elm:8193-8202`) writes `hivSigns = {PrenatalHIVSignPendingInput}` → `Backend/Update.elm:9128` adds `TestPartnerHIV` to `labsResults.testsWithFollowUp`. The nurse then finds the task hidden in Lab Results (`expectLaboratoryResultTask` needs `isLabTech || followUpWasNotScheduled`) and shown in Labs Results Follow Ups (`expectLaboratoryResultFollowUpsTask TaskPartnerHIVTest`, `RecurrentActivity/Utils.elm:322-329` = follow-up scheduled + result positive), rendering "Is the partner taking ARVs?" with no way to save it.
- **Impact.** `hivSigns` stays `{PrenatalHIVSignPendingInput}` forever, so `laboratoryResultFollowUpsTaskCompleted` (`Utils.elm:281-282`) is permanently False → the activity never completes → `pendingActivities` is never empty → `Pages/Prenatal/RecurrentEncounter/View.elm` only ever offers "Leave Encounter", never **End Encounter**, so `ConcludeEncounter` never runs and the pregnancy stays in the labs-review queue. Every reader of the partner signs (`resolveDiscordantPartnershipSet` `Pages/Prenatal/Utils.elm:1829-1834`; `partnerSurpressedViralLoadByPartnerHIVTest` :4523-4535; `ProgressReport/View.elm:1004`) sees nothing. All sites.
- **Fix shape (guess).** Add `TaskPartnerHIVTest -> SavePartnerHIVResult personId measurements.partnerHIVTest nextTask |> Just` to that `saveMsg` case. `SavePartnerHIVResult` already exists in the recurrent `Msg` and its `update` branch already stores and navigates, so the fix is one arm.
