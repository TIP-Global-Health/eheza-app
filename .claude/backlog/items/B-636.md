### B-636 — Deploy: a `drush` step on Pantheon is retried after ANY failure, so an update hook that fails part-way is run from the start three times — READY · CONFIRMED as code (orchestrator read the loop and its docblock; nothing run) · ⚠ assumes `drush updb -y` exits non-zero when a hook fails — not checked · LOW · tier 4 · R65 unit 1 · deploy tooling, all sites incl. Test and Live · not sized (no such failure is known)
- **Mechanism.** The retry loop tests success only; the exit code is printed, never read:
  ```php
  // server/RoboFile.php:248-267
  protected function drushOnPantheon(string $environment, string $drushCommand) {
    for ($attempt = 1; $attempt <= self::DEPLOY_STEP_ATTEMPTS; $attempt++) {
      $result = $this
        ->taskExec("terminus remote:drush $environment -- $drushCommand")
        ->run();

      if ($result->wasSuccessful()) {
        return;
      }
      ...
      $this->say("`drush $drushCommand` failed on $environment with exit code {$result->getExitCode()}. Retrying in $delay seconds ...");
      sleep($delay);
    }
  ```
  The docblock above it gives the reason for the retry as a memory kill (exit 137), and names the risk itself:
  ```php
  // server/RoboFile.php:233-237
   * idempotent, and `uli` just mints another login link. `updb -y` is the one
   * to watch. An update hook is recorded as run only once it finishes, so a
   * hook killed part-way is never recorded and the retry runs it from the
   * start - and update hooks are not written to be idempotent. Read the update
   * output before trusting a retried `updb -y`.
  ```
  The loop retries after 15 and 30 seconds, before anyone can read that output.
- **Reachability.** `ddev robo deploy:pantheon` and `deploy:pantheon-sync test|live` run `updb -y` through this function (scout's call path; the orchestrator read the function and its one call site at `:216`).
- **Impact.** A hook that throws at the same point every time repeats its partial writes three times on that environment. For the kill case the retry is the design and is documented; this item is only about failures that are not a kill.
- **Fix shape (first guess).** Retry only on exit 137, or never retry `updb` without a human reading the output.
