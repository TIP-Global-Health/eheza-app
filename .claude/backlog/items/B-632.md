- **How the state arises.** The presave stores each indicator through its own plausibility limits, so one can be cleared while the other stays:
  ```php
  // server/hedley/modules/custom/hedley_activity/hedley_activity.module:120-126, :351, :389
  const HEDLEY_ACTIVITY_ZSCORE_LIMITS = [
    ...
    'weight_for_age' => [-6, 5],
    'weight_for_length' => [-5, 5],
  ];
  ...
  $wrapper->field_zscore_age->set(hedley_activity_plausible_zscore($zscore_for_age, 'weight_for_age'));
  ...
  $wrapper->field_zscore_length->set(hedley_activity_plausible_zscore($zscore_for_length, 'weight_for_length'));
  ```
  The typical case is a child with a wrong birth date: weight-for-age is beyond the limits, weight-for-length (which uses age only to choose the length or height table) is plausible. `clear-implausible-zscores.php` made the same state in bulk at the release ([[B-437]]). A child past the weight-for-age table (over 121 months) who is still under 120 cm is a second, rarer route (scout's table ranges).
- **Reachability.** Any weight save → presave → reports queue job rebuilds `field_reports_data` → Admin › Statistical Queries nutrition report (prevalence and incidence) and its CSV.
- **Impact.** That encounter has no weight-for-length value in the Statistical Queries nutrition report, while the dashboard and the NCDA scoreboard count it. The three server copies disagree for these children. No clinical decision reads this. All sites.
- **Evidence.** Read only. Not sized: [[B-437]] records 2,800 weight-for-age and 3,189 weight-for-length values cleared on ihangane, but how many weighings lost only weight-for-age is unknown — one query on `field_data_field_zscore_age` / `field_zscore_length` over the weight bundles answers it.
