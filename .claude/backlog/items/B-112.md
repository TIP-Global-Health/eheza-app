### B-112 — Geolocation term-builder: stale by-name parent cache on revisited prefixes → children can attach to the wrong parent — ✅ SUPERSEDED by PR #2095 (B-151, open 2026-08-17; close this when it merges) · was READY · CONFIRMED-hazard · LOW
- **Verified against #2095's diff 2026-08-17 (R20 wave 1): the mechanism is structurally eliminated, not patched.** `_hedley_migrate_process_column` now keys BOTH `$data` and `$locator` by the full escaped path (`_hedley_migrate_geo_path_key`), and resolves the parent by path key (`array_slice($row, 0, $index)`) instead of by the last-created tid for a bare NAME — so a revisited prefix can never see a stale entry, and same-named locations under different parents stay apart. The early return no longer needs a refresh because path keys are written once at creation and never go stale. Nothing remains to do if #2095 merges; if #2095 is abandoned, this reverts to READY with the original 1-line fix below.
- Original entry: `hedley_migrate.module:366-394` `_hedley_migrate_process_column`: early return on existing term skips refreshing `$data[$index][$name]` (last-created-tid by NAME); rwanda CSV is NOT contiguity-sorted (prefix blocks recur, e.g. :63 vs :165-168) so the hazard is structurally reachable on future CSVs; feeds the generated Elm GeoLocation data. Fix was: refresh `$data[$index][$row[$index]] = $locator[$locator_index];` before the early return.
