### B-524 — Prenatal participant and encounter: a device's whole-copy PATCH sends `null` for fields it did not change, so a second writer's EDD, newborn, conclusion date or encounter end date is erased — READY · LOW · tier 4 · CONFIRMED (encoders + server null handling read; 4 + 2 + 2 + 4 device-caused instances on ihangane) · DEPLOYED · R47 unit 4
- **Mechanism.** `Backend/IndividualEncounterParticipant/Encoder.elm:13-31` sends `expected_date_concluded`, `date_concluded`, `outcome`, `outcome_location`, `newborn` through `maybe` (an explicit `null` when the device's copy holds `Nothing`); `Backend/PrenatalEncounter/Encoder.elm:31-45` does the same for `scheduled_date.value2` (end date) and sends the copy's diagnosis sets whole. Every participant message (`ClosePrenatalSession`, `SetEddDate`, `SetNewborn`, … `Backend/IndividualEncounterParticipant/Update.elm:30-91`) and every encounter message (`CloseEncounter`, `SetPrenatalDiagnoses`, `SetLabsHistoryCompleted`, `SetNextVisitDate`, `SetGWGIndicator`, … `Backend/PrenatalEncounter/Update.elm:28-57`) goes through `sw.patchFull` with the full encoding of the cached copy. The queued body is frozen at save time (`nodes.js:260-290` `patchNode` queues `data: json`) and uploaded verbatim even if a newer server copy was downloaded meanwhile. Server side `HedleyRestfulSync.class.php:471-508` copies every present key — `null` falls through the `!empty` guards into `$data[$key] = $value` — and RESTful's `setPropertyValues` sets any key present; there is no `vid`/`changed` check.
- **Writers that collide.** The nightly `populate-edd.php` (`hedley_prenatal/scripts`, Jenkins H 23) writes `field_expected_date_concluded`; the nurse's device sets `newborn`/`date_concluded`/`outcome` at the outcome page; the lab tech's device PATCHes the encounter's diagnoses (`Backend/Update.elm` recurrent-phase paths) from a copy that may still show the encounter open; a CHW device holds the same participant.
- **Live counts (`ihangane_post`, device uids only).** Participant: `expected_date_concluded` present in an earlier revision and absent now 2, `newborn` 2, `date_concluded` 4, `outcome` 0. Encounter: end date present earlier and `null` now 4 (21 more by uid-0 scripts), diagnosis set shrunk by a device 2 (same device; 74 by server remapping scripts). An encounter with `endDate = Nothing` reads as active again (`Pages/Prenatal/Participant/View.elm:215-221, 346-352`). Small today; the mechanism is the one B-493 sized at 15 entries in one backlog burst.
- **Fix shape (first guess).** `encodeIfSet` for the fields a message does not change, or a server-side rule that a PATCH never nulls a populated EDD/newborn/end date.
