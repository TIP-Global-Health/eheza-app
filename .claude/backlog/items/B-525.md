### B-525 — Acute Illness CHW first visit: the encounter is classified as "subsequent" and shown the LATER encounter's diagnosis whenever any other encounter of the illness exists — even an empty same-day duplicate — so the first-visit activity set, the diagnosis path and the stored diagnosis are wrong — READY · MED · tier 1 (diagnosis determination, standing rule) · CONFIRMED (code + orchestrator's own elm-test 3/4 failing + live signal 8–34 encounters, control 0) · DEPLOYED (all sites) · R47 unit 2
- **Mechanism.** The CHW "initial encounter" flag and the fallback diagnosis both read the illness's whole encounter list minus the current id:
  ```elm
  -- client/src/elm/Pages/AcuteIllness/Encounter/Utils.elm:66-84
                          AcuteIllnessEncounterCHW ->
                              -- For CHW, it's only the first encounter at illness.
                              List.isEmpty previousEncountersData

                  currentDiagnosis =
                      if initialEncounter || isJust diagnosisByCurrentEncounterMeasurements then
                          diagnosisByCurrentEncounterMeasurements

                      else
                          getAcuteIllnessDiagnosisByPreviousEncounters id db data.encounter.participant
  ```
  `generatePreviousMeasurements` (`:155-180`) keeps every encounter whose measurements are fetched (`Fetch.elm:31-33` fetches all of them, so an empty sibling is `Success emptyMeasurements`) and excludes only `encounterId == currentEncounterId` — no date or sequence bound. `getAcuteIllnessDiagnosisByPreviousEncounters` (`:183-200`) takes the DESC head of the same list, i.e. the newest diagnosed encounter, later ones included. Nurse encounters are typed (`AcuteIllnessEncounterNurse`/`NurseSubsequent`), so only CHW encounters are affected. Prenatal and NCD bound their history (`Pages/Prenatal/Encounter/Utils.elm:323-331`, `Pages/NCD/Utils.elm:65-74` — the B-364 / B-339 fixes); this is the unbounded sibling.
- **What flips when a real first visit reads as subsequent.** `expectActivity` (`Pages/AcuteIllness/Activity/Utils.elm:62-72`): Symptoms and Prior Treatment vanish, Danger Signs appears, Physical Exam / Next Steps take the subsequent task sets; `resolveAcuteIllnessDiagnosis` (`:2472-2500`) takes the malaria-RDT-only branch so the Covid/non-Covid path never runs; the shown diagnosis is the LATER encounter's; on save `generateSuspectedDiagnosisMsgs` (`Backend/Update.elm:9780-9797`) dispatches to the subsequent-encounter writer, which stores the RDT-derived diagnosis or `none` on the encounter; `allowEndingEncounter` and the progress report follow the same flag.
