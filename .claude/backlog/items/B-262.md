### B-262 — Person-counting cards that count participants or measurements instead of people (three siblings, one family) — READY · CONFIRMED (anchors verified; live prevalence unmeasured) · LOW · tier 4 · R25 units 4+8
- **The same family as B-206 (children seen counted as visits) and B-208 (well-child duplicate participants), both already accepted.** Recorded as one item because the fix is one idiom applied in three places.
- **(a) NCD cards count participants.** `Pages/Dashboard/Utils.elm` `countTotalNumberOfPatientsWithHypertension` (:1562), `countNewlyIdentifieHypertensionCasesForSelectedMonth` (:1582), `countTotalNumberOfPatientsWithDiabetes` (:1635), `countNewlyIdentifiedDiabetesCasesForSelectedMonth` (:1653) all end in `List.filter (…) >> List.length` over `List.NCDDataItem`; `generatePatientsWithHIV` (:1730) returns `List.map .identifier` with no dedupe and `View.elm:2671-2672` takes its length. An `NCDDataItem` is one individual **participant** (`hedley_stats_get_ncd_data()` keys `$items` by participant nid while emitting `'id' => $row->field_person`). ⭐ 240 lines below the first of them, `countTotalNumberOfPatientsWithGestationalDiabetes` (:1671-1693) ends with `List.map .identifier >> EverySet.fromList >> EverySet.size` and carries a comment explaining why — so the intent is a person count, and these five are the ones that were not updated. All are named "…NumberOfPatients…".
- **(b) "New Beneficiaries" counts group enrolments.** `hedley_stats_get_children_beneficiaries_group_stats` (`:2543-2562`) pushes one item per `pmtct_participant` row and `…_individual_stats` (`:2618-2642`) one per `individual_participant` row, so a child enrolled twice yields two items with the same `id`. `Pages/Dashboard/View.elm:1619-1621` (the "New Beneficiaries" card) and `:1906-1907` (`getBeneficiariesCount`, the "New" row by age band) both take `List.length`. The third consumer *does* dedupe — `Utils.elm:1285-1300` ends in `EverySet.fromList |> EverySet.size` with the comment *"We want to get unique participants"*. ⚠ **B-199 measured 1,101 children double-enrolled in the same clinic on ihangane**, and the duplicates were created in the same burst so both land in the same month bucket — this one has a measured producing population.
- **(c) The family-planning donut counts measurements.** `Pages/Dashboard/View.elm:2229-2241`: `totalWomen = List.length stats.familyPlanning`, where each element is one `family_planning` node (one per woman per FBF session). A woman with two measurements inside the period is counted twice in both the total and the percentage, under the label `FamilyPlanningOutOfWomen`. Exposure is small (the period is one month and FBF sessions are monthly), and ⚠ **the payload carries no person id for these rows**, so deduping needs a server change — which is why it is recorded rather than fixed blind.
- **Impact.** Upward-only inflation of nurse-facing counts. Unmeasured for (a) — whether NCD participants duplicate is unverified, unlike the well-child and prenatal cases B-195/B-208 document.
- **Fix shape (guess).** Apply the `List.map .identifier >> EverySet.fromList >> EverySet.size` tail the gestational-diabetes counter already uses (or reuse `dataItemMergeDuplicates` once B-208 lands) for (a) and (b); (c) needs the server to emit a person id first.
