## ✅ Implemented 2026-09-16 — issue #2254, PR #2255

Three branches reordered in `acuteIllnessDiagnosisFromMapping` so `j`/`k`/`l` read as
`hedley_reports_ai_diagnosis_mapping()` writes them; the committed admin bundle
(`hedley_general/js/elm-main.js`) rebuilt, and the reporting e2e's assertion moved to
`diagnosis-respiratory-uncomplicated`, the row its encounter actually produces.

**No recalculation.** The stored `field_reports_data` letters were always correct — only the
reader was wrong — so the rows are right as soon as the new bundle is served. This is the same
resolution [[B-129]] reached for the swapped WASH rows, and for its reason: renumbering the
backend would create a window where some people carry the old codes and some the new, and the
pane sums across both.

**Verified locally:** the mapping tables cross-checked letter by letter after the change (all 15
agree; `z`/`none` unmapped by design); the committed bundle proven in sync with develop's sources
*before* the rebuild, so its 3-line diff is exactly this change; `ci-scripts/test_server_elm_bundle.sh`
green; `elm-format --validate` and server `elm-review` clean; the e2e spec compiles
(`playwright test reporting --list`). The e2e itself runs in CI's own `e2e_reporting` job — not
run locally, and it is a real discriminator: on develop the encounter's count lands in
`-complicated`, so the moved assertion fails there.

⭐ **Root cause, from the blame.** `de8458842` (PHP writer) and `65520b837` (Elm reader) are
parent and child, 16 seconds apart on 2024-06-24 — the reader's letters were assigned by walking
the `AcuteIllnessDiagnosis` union declaration in `Backend/Reports/Model.elm` top to bottom instead
of reading the table just written. The two orders differ in exactly these three positions; the
other twelve agree by coincidence. Shipped in **v1.11.3 (2024-07-28)** and wrong every day since.
