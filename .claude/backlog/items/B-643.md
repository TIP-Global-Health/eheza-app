### B-643 — Completion report › Nutrition Group: Mother FBF is expected only for Ubudehe 1 or 2, a condition the app dropped in September 2024 — ✅ IMPLEMENTED · CONFIRMED (orchestrator read both rules and the commit) · LOW · tier 4 · R72 unit 2 · report figure only, not sized
- **What is wrong.** The group-session builder expects `mother_fbf` only when the mother's Ubudehe is 1 or 2, with no date condition:
  ```php
  -- server/hedley/modules/custom/hedley_reports/hedley_reports.module:3578-3587
            // Mother FBF activity is shown if Lactation activity indicated
            // that mother is breastfeeding, and mother Ubudehe is 1 or 2.
            if (!empty($measurements_by_type['lactation'])) {
              $lactation_sign = $measurements_by_type['lactation']->field_lactation_signs[LANGUAGE_NONE][0]['value'];
              $ubudehe = $person->field_ubudehe[LANGUAGE_NONE][0]['value'];
              if ($lactation_sign == 'breastfeeding' && in_array($ubudehe, [1, 2])) {
                $expected[] = 'mother_fbf';
              }
            }
  ```
  The app shows Mother FBF to every breastfeeding mother at an FBF or ACHI group:
  ```elm
  -- client/src/elm/Activity/Utils.elm:444-456
                      -- Show at FBF groups, for mothers that are breastfeeding.
                      MotherFbf ->
                          case participant.adultActivities of
                              MotherActivities ->
                                  if List.member offlineSession.session.clinicType [ Achi, Fbf ] then
                                      getMotherMeasurementData2 motherId offlineSession
                                          |> LocalData.map
                                              (.current
                                                  >> .lactation
                                                  >> Maybe.map (Tuple.second >> .value >> EverySet.member Breastfeeding)
                                                  >> Maybe.withDefault False
                                              )
  ```
  Commit `77ee83371` (2024-09-19, "change the fbf entitlement by Ubudehe") replaced the Ubudehe 1 / 2 test in the app with `Maybe.map (\_ -> True)`. The server rule was written in 2024-08 and still has it.
- **Reachability.** Completion generation → `hedley_reports_generate_completion_data_for_nutrition_group_encounter` → the stored completion data → Completion app, Nutrition Group, the mother activities.
- **Impact.** For sessions since the app change, a breastfeeding mother with Ubudehe 3, 4 or none at an FBF / ACHI group is not expected to receive Mother FBF. `hedley_reports_generate_completion_result` counts completions among expected activities only, so both figures on the row are too low. A site whose persons carry no Ubudehe gets an empty row (scout's reading; whether such a site runs FBF / ACHI groups was not checked).
- **Not checked.** No count of affected sessions; the date the app change reached each site; whether the rule before 2024-09-19 must be kept for older sessions.
- **Fix shape (guess).** Apply the Ubudehe condition only to sessions before the app change, with a date cutoff as the module does for other dropped rules (`$exposure_cutoff`, `$covid_nextsteps_cutoff`). Stored completion data needs regenerating, as for B-584 / B-591.
