### B-271 — Vaccination progress: when two encounters record the same dose with different dates, which date wins depends on an arbitrary anchor encounter — READY · CONFIRMED (fold + stable-sort + AssocList last-wins verified) · LOW · tier 4 · found while building B-214
- **Mechanism.** `generateVaccinationProgressForVaccine` (`Measurement/Utils.elm:1270-1288`) folds every vaccination value into `(dose, date)` pairs, then `List.sortBy (Tuple.first >> vaccineDoseToComparable)` — a **stable** sort — then `Dict.fromList`, which for vendored AssocList is `List.foldl insert`, so the **last** pair for a dose wins. The pre-sort order is `assembled.measurements :: previousMeasurements` (`:10214-10216`), i.e. the anchor encounter first, everything else after in date-DESC order. So for a dose recorded at two encounters with different dates — a duplicate entry, or a correction — the winning date depends on which encounter is the anchor.
- **And the anchor is arbitrary.** `behindOnVaccinationsByProgressFromWellChild` (`:9268`) and `behindOnVaccinationsByProgressFromChildScoreboard` (`:9298`) both pick it with `get…EncountersForParticipant db >> List.map Tuple.first >> List.head` — no date sort, so storage (UUID) order. Same shape as the B-214 defect.
- ⚠ **This is the ONLY part of the reviewer's B-214 finding that survives, and the headline claim was REFUTED.** The review of PR #2170 reported these two sites as reading a stale encounter's vaccination progress and mis-reporting a child as behind. That does not happen: `Backend.Measurement.Utils.generatePreviousMeasurements` excludes **only** the anchor and keeps every other encounter, so anchor + others = all encounters for any anchor. The measurement set is anchor-independent, and `assembled.person` does not vary. `generateVaccinationProgressDictsForChildScoreboard` has the identical structure. ⭐ Keep this: an arbitrary `List.head` is not automatically a defect — check whether anything downstream actually depends on the choice.
- **Impact.** Only when the same dose is recorded at two encounters with differing dates. Display and the behind-on-vaccinations flag; no data written. All sites.
- **Fix shape (guess).** Decide the rule (earliest administration date is the clinically meaningful one), then make the fold explicit rather than order-dependent — e.g. keep the minimum date per dose instead of relying on `Dict.fromList` last-wins. Sorting the anchor pick would only make the arbitrariness deterministic, not correct. Sibling: [[B-270]] (same last-wins class, ECD milestones).
