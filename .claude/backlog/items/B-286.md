### B-286 — NCD hypertension staging compares against the encounter's OWN just-written stage: a Stage-3 patient with one low reading is stepped down twice in one visit, and a mistyped BP cannot be corrected to a lower stage — READY · CONFIRMED (generation, re-run trigger and PATCH→revision path verified) · MED · tier 3 · R26 unit 5 · ⭐ DEPLOYED (since `929a3f43b`, 2022-09-14; identical on `origin/main`)
- **Mechanism.** `generateNCDDiagnoses` (`Pages/NCD/Utils.elm:104-109`) → `applyHypertensionDiagnosesLogic` (`:112-157`) takes the "current condition" from `resolveCurrentHypertensionCondition` (`:320-328`), which puts `{ diagnoses = assembled.encounter.diagnoses, … } :: assembled.previousEncountersData` through `resolveHypertensionCondition` — so the encounter being re-assessed is the head of the list and its own previously written stage is what the new stage is compared against. `generateNCDAssessmentMsgs` (`Backend/Update.elm:9324-9346`) — whose comment says *"At this stage new diagnoses were not updated yet, therefore, we can use the diagnoses set for the encounter"* — re-runs on EVERY Vitals, CoMorbidities, RandomBloodSugar, UrineDipstick and Creatinine revision (`:3562-3654`, `processRevisionAndAssessNCD`), and `SetNCDDiagnoses` (`Backend/NCDEncounter/Update.elm:29-30`) replaces the set via `sw.patchFull` (`:309-320`), whose local write comes straight back as an `NCDEncounterRevision` (`:6465-6473`), so `db.ncdEncounters` already carries the new set before the nurse's next save.
- **(a) Double step-down.** History `{Stage3}`, today's vitals 95/70. Vitals save → today matches no stage (`hypertension = []`), `lowerHypertensionStageCondition` (`:277-279`, `sys < 100`) true, current = Stage3 from history → writes `{Stage2}` (`:124-142`). The next Random Blood Sugar save (expected at every encounter, `Activity/Utils.elm:876-877`; even "not performed" is a revision) re-runs the same branch with current = the encounter's OWN Stage2 → writes `{Stage1}`. A third trigger (urine dipstick; creatinine at the recurrent phase) stays at Stage1. `Pages/NCD/Test.elm:355-388` pins "steps down by one" (Stage3 + low → Stage2), but every fixture has `encounter.diagnoses = EverySet.empty` (the file's own comment at `:141-147`), so the second pass is never exercised.
- **(b) Ratchet on correction.** First encounter, nurse types 185/85 (meant 145/95) → `{Stage3}`. Corrects to 145/95 → `hypertension = [Stage1]`, current = own Stage3, `1 > 3` false → `current :: others` (`:145-157`) → stays Stage3. Only a correction to a normal reading (sys ≥ 100 and below Stage 1) clears it. Same shape, smaller: `matchNCDDiagnosis DiagnosisDiabetesRecurrent` (`:219-221`) short-circuits on `diagnosed DiagnosisDiabetesInitial assembled` — the stale set — so unticking Diabetes in co-morbidities hides a sugar-count diabetes for one pass.
- **Reachability.** Any nurse NCD encounter. (a) needs a prior Stage 2/3 and a systolic < 100 today followed by any lab save — the normal Examination → Laboratory order. (b) needs a BP re-edit while still hypertensive.
- **Impact.** The stage written to the encounter is what `resolveHypertensionCondition` reads at every later encounter (chronic — ratchets up, or one step down on sys < 100), what `medicateForHypertension`/`referForHypertension` gate on (`:586-628`, `:939-949`: Stage3 → mandatory hospital referral; "choose two medications" vs one, `:672-676`), and what the progress report prints. (a) silently demotes a Stage-3 patient to Stage 1 for good; (b) leaves a Stage-3 referral requirement the nurse cannot remove. Both sites.

Pin with a `Test.elm` case that seeds `encounter.diagnoses`.
