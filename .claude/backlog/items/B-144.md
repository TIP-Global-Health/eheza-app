### B-144 — `gulp publish` cannot fail on an Elm compile error → a broken production artifact ships with all steps green — ✅ IMPLEMENTED 2026-08-09 (issue #2056, PR #2057, MERGED) · **HIGH · release-prep**
- `client/gulpfile.js:311-330` (verified): the `elm` task uses `plumber()` + an `.on('error')` handler that writes the error into `serve/index.html` and continues — right for dev watch, wrong for `publish` (:492-497 reuses it via build→pwa:dev). On compile failure `minify` packages serve/ into dist/ (error page, no app) and gulp exits 0; `deployPantheon` rsyncs whatever dist contains. Fix shape: a publish-path variant that re-emits the error (or checks the elm exit) so publish exits non-zero. Related PLAUSIBLE: uglify `.on('error')` (:271-275) may likewise let a partial dist through.
