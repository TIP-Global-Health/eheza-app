### B-631 — Person edit / add family member: a stored address level under a place missing from the location list is looked up among the provinces, and a match blocks the save — READY · mechanism CONFIRMED by reading (orchestrator read the lookup, the default chain and the validator); ⚠ LATENT — the stored-data precondition is NOT sized · LOW · tier 4 · R62 unit 2 · Burundi sites (vhw, uvl) · nothing run
- **Mechanism.** Each level's resolved id is the parent key of the next lookup. An unresolved level gives `Nothing`, and `Nothing` is the key of the province bucket:
  ```elm
  -- client/src/elm/GeoLocation/Utils.elm:45-48
  getGeoLocation reverseGeoInfo parent name =
      Dict.get parent reverseGeoInfo
          |> Maybe.andThen (Dict.get (String.toLower name))
  ```
  ```elm
  -- client/src/elm/Backend/Person/Form.elm:95-98, 108-111, 121-124
        defaultProvinceId =
            defaultProvince
                |> Maybe.andThen (getGeoLocation reverseGeoInfo Nothing)
                |> Maybe.map Tuple.first
  ...
        defaultDistrictId =
            defaultDistrict
                |> Maybe.andThen (getGeoLocation reverseGeoInfo defaultProvinceId)
                |> Maybe.map Tuple.first
  ...
        defaultSectorId =
            defaultSector
                |> Maybe.andThen (getGeoLocation reverseGeoInfo defaultDistrictId)
                |> Maybe.map Tuple.first
  ```
  So below an unresolved level, a stored name equal to a province name resolves to that province's id, and `applyDefaultAddress` writes it into the lower field (`Form.elm:271-272`, `( False, unwrap accum setLevel storedId )`). A field that holds a value is validated as given:
  ```elm
  -- client/src/elm/Backend/Person/Form.elm:586-594
                -- A field never set keeps the related person's stored value, such
                -- as a place missing from the address list. A cleared field holds
                -- "" and is validated as given.
                if isNothing (Form.Field.asString validationField) then
                    defaultValue related validation validationField

                else
                    validation validationField
  ```
  A province id is not in the district or sector table, so the form fails on a level the nurse never touched. Per the scout (not re-traced): the select shows blank and the level above is locked, so there is no direct way out.
- **Which names.** Burundi provinces are Bururi, Rumonge and Burunga (`GeoLocation/Utils.elm:63-65`). Example: stored Bururi / Bururi / Bururi — the province resolves, commune "Bururi" is not under it in the list, zone "Bururi" is then looked up among the provinces and gets id 1. The scout's script found no such collision possible inside the Rwanda or Somalia tables; a stored off-list name could still collide there, which is far less likely.
- **Reachability.** A nurse edits, or adds a family member to, a person on vhw / uvl whose stored address has that shape. The form cannot produce it (it offers list values only); it needs imported or otherwise off-list person data.
- **Sizing.** None. Needed: persons on vhw / uvl where a level does not resolve under its parent and the next level's value is Rumonge, Bururi or Burunga. R33 measured 1.4 % unresolvable addresses on ihangane; Burundi was never measured.
- **Relation to [[B-605]].** Before PR #2556 any validation failure fell back to the stored value, so the wrong id was harmless. As merged, only a never-set field falls back.
- **Fix shape (guess).** Look a lower level up only when its parent id resolved, rather than letting `Nothing` mean "top level".
