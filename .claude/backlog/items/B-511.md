### B-511 — Service worker: while the database version differs from `dbVerno`, every request opens a new connection and never closes the old one; `statistics.js` keeps its own copy of the old opener — READY · LOW · tier 4 · from PR #2422 review round 2 (findings 1 and 2)
- **Mechanism.** After PR #2422, `nodes.js` reopens whenever the open connection's version differs from `dbVerno`. Once an opening finishes, `dbOpening` is cleared, so in that state each later request runs `Dexie.exists` and opens again:

  ```js
  -- client/src/js/nodes.js:108-120 (branch B-168-sw-single-db-opening)
        if (dbSync === null || dbSync.verno != dbVerno) {
            if (dbOpening === null) {
                dbOpening = openSyncDb().finally(function () {
                    dbOpening = null;
                });
            }
  ```

  Old instances are never closed, so connections and hook sets pile up until Chrome stops the worker. Reopening cannot help in that state: the database is still at the other version. The same per-request reopen exists on develop.
- **Twin.** `statistics.js` opens the database the old way, `dbSync = new Dexie('sync')` before `open()`, with its own `exists` check. It only reads, so nothing is lost.
- **Impact.** Saves are safe since #2422, because each save uses `table.db`. What remains is wasted opens and leaked connections in the window between a `dbVerno` bump and the page upgrading the database.
- **Fix shape.** One shared opener in `sw.js` for both scripts that reopens only when the connection is closed (Dexie closes it on `versionchange`), not on version inequality. Needs a test that upgrades the database mid-run.
