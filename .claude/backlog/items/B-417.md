### B-417 — Two config-as-code gaps: an unexported taxonomy component, and the two custom permissions that `drush fra` cannot restore — READY · CONFIRMED (scout grep-proved both) · LOW · tier 4 · R34 unit 6 · ops/developer only
- **(a) A taxonomy component declared but never exported.**
  ```
  -- server/hedley/modules/custom/hedley_patient/hedley_patient.info:46
  features[taxonomy][] = nutrition_health_signs
  ```
  ```php
  -- server/hedley/modules/custom/hedley_patient/hedley_patient.features.taxonomy.inc:11-13
  function hedley_patient_taxonomy_default_vocabularies() {
    return array();
  }
  ```
  `nutrition_health_signs` appears nowhere else in the repository. The component can never match its default, so `drush fd`/`fra` carry permanent noise for it, and a real vocabulary of that name — if one exists on a site — is not under config control.
- **(b) Neither custom permission is in any Features export.** `hedley_view_export_permission()` defines `hedley export views` and `logs_glitchtip_permission()` defines `administer glitchtip`; the 1,096 exported permissions across all 24 `*.features.user_permission.inc` files are all node/core permissions. `hedley export views` is granted only by `hedley_update_7023()` (`hedley.install:570`), an update hook `hedley_install()` does **not** replay — its replay list is `7002-7005, 7012-7016, 7032, 7046` (`hedley.install:44-54`).
- **Impact.** Nothing is broken today: on existing sites the administrator role holds both, because Drupal grants new-module permissions to `user_admin_role` and 7023 ran. What it means is that `drush fra` cannot restore either permission, and no non-administrator role can ever be given the export permission through config — a fresh install is the case that would notice.
- **Fix shape (guess).** Export both permissions into a Features permission file; drop the `.info` taxonomy line and the empty export unless the vocabulary is meant to exist (settle with `terminus remote:drush <site>.live -- sql-query "SELECT machine_name FROM taxonomy_vocabulary"`).
