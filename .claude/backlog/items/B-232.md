### B-232 — Case Management immunization pane: a child is listed only on the day the follow-up was scheduled, never afterwards — the pane is effectively empty — READY · CONFIRMED (anchor verified; scout probe: 1 item in, 0 entries out) · HIGH · tier 2 · R24 unit 3
- **Mechanism.** `Pages/GlobalCaseManagement/View.elm:1560-1591` `generateImmunizationFollowUpEntryData` is a copy of the nutrition version (:442-469; the stale `-- No Home Visit encounter found.` comment at :1589 is the tell). It takes the last non-NewbornExam Well Child encounter with `startDate < limitDate` and keeps the entry only if `Date.compare encounter.startDate item.dateMeasured == LT`. For nutrition the acting encounter (home visit) differs from the scheduling one, so "acting encounter older than the follow-up" is meaningful. For immunization BOTH are Well Child encounters: the encounter that saved the `nextVisit` measurement (`asapImmunisationDate`, `Utils.elm:220-243`) has `startDate == item.dateMeasured` (saved with `currentDate`, `Backend/WellChildEncounter/Update.elm:~391`), so `LT` is false and the entry is suppressed. It survives only on the scheduling day itself (that encounter is excluded by `< limitDate` because `viewImmunizationPane` :1534-1538 passes `currentDate`, not `Date.add Days 1 currentDate` like the five sibling panes :417/:539/:677/:804/:941) — i.e. while the CHW is still with the child — and while fetches are in flight (entries flash, then vanish).
- **Reachability.** CHW → Case Management → immunization pane (:146-151); data fully fetched (`Fetch.elm:60-65, 78-81`) — entries are computed then filtered away. Both sites, no flag.
- **Impact.** Children who left a well-child visit with immunisations owed are never listed for the CHW to chase. ⚠ Long-standing; if the user says the pane is not relied on, re-tier — but as coded the feature does not work.
- **Fix shape (guess).** Suppress only when a Well Child encounter STARTED AFTER the follow-up (`GT`), and pass tomorrow as the limit date like the siblings. Check whether `Pages/Dashboard/Utils.elm:1113-1140`, which shares the nutrition/AI/prenatal entry generators, needs an immunization counterpart (it does not read immunization today). Fixing the `LT` alone would expose the second defect: an entry stays live after today's visit and tapping it opens a second Well Child encounter the same day.
- 📌 Scout note, not raised: `viewImmunizationFollowUpEntry` (:1600-1605) labels ≤30 days overdue as `DueThisMonth` (green) instead of using `followUpDueOptionByDate` like every other pane — possibly deliberate.
