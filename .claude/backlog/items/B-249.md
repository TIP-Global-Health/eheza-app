### B-249 — Dashboard family planning: the donut buckets each record by the date it was uploaded, not the date it was measured — READY · CONFIRMED (query, emit site and consumer verified) · MED · tier 3 · R25 unit 8
- **Mechanism.** `hedley_stats_get_family_planning_stats_by_period` (`hedley_stats.module:2662-2707`) windows the query on `field_date_measured` (via `hedley_stats_get_base_query`, `:3630-3643`) but ships the node's creation timestamp: `:2687` `$row->created = hedley_stats_convert_timestamp_to_nominal($row->created);`, where `created` comes from `$query->fields('node', ['nid','type','created'])` — the moment the sync POST landed on the server. `HedleyRestfulSync::handleChanges()` never sets `$node->created` from the payload. The client then buckets on exactly that value: `Backend/Dashboard/Decoder.elm:179` `required "created" decodeYYYYMMDD`, consumed at `Pages/Dashboard/Utils.elm:1513` under the ThisMonth / LastMonth / ThreeMonthsAgo window.
- **The right value is already in the row and already shipped.** `:2691-2697` unsets six keys but **not** `field_date_measured`, which the base query added — the decoder simply ignores it.
- **Every sibling keys on the measured date.** Case management groups by `$row->field_date_measured` (`:3436`, `:3487`); total encounters filters attendance on it. Family planning is the only builder that switches to node creation.
- **Reachability.** AQ worker → `hedley_stats_get_family_planning_stats_by_period($hc, PAST_THREE_MONTHS)` (`:669`) → cached → served on every stats sync → the family-planning donut (`Pages/Dashboard/View.elm:368, 2019-2030`).
- **Impact.** Offline-first makes this bite: any FBF record whose upload crosses a month boundary relative to the session lands in the wrong month, and a record measured inside the selected window but uploaded outside it is misplaced entirely. Nurse FBF dashboards, all sites. Unmeasured — the local DDEV database is a 532-node demo.
- **Fix shape (guess).** Emit the measured date as `created`, or add the key the decoder should read from `field_date_measured`. ⚠ The client field is literally named `created`, so a rename touches `Backend/Dashboard/{Decoder,Encoder,Model}.elm` as well — and `Encoder.elm` matters because the payload is re-persisted (the B-163 path).
