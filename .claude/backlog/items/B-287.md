### B-287 — NCD labs Case Management entry is closed by the final lab result BEFORE that result's diagnosis exists, so the Next Steps it triggers drop out of Case Management — READY · CONFIRMED (both generators + pane filter verified; prenatal sibling handles it) · MED-LOW · tier 3 · R26 unit 5
- **Mechanism.** On a lab-result revision two generators run side by side on the same post-revision model (`Backend/Update.elm:3562-3620`: `extraMsgsForLabsResults ++ extraMsgsForAssessment`). `generateNCDLabsResultsAddedMsgs` (`:9412-9476`) sets `resolutionDate = currentDate` when `size updatedCompletedTests == size updatedPerformedTests && Pages.NCD.RecurrentActivity.Utils.activityCompleted assembled RecurrentNextSteps` — with `assembled` built from `after`, whose `encounter.diagnoses` is still the pre-result set (the sibling `generateNCDAssessmentMsgs :9328-9331` says exactly that). `activityCompleted RecurrentNextSteps` (`RecurrentActivity/Utils.elm:35-45`) is `resolveNextStepsTasks |> List.all …`, and `expectNextStepsTask` (`:56-66`) reads `diagnosed DiagnosisDiabetesRecurrent` / `DiagnosisRenalComplications` from that stale set → no tasks → `List.all` on `[]` → closed today. `viewNCDLabsPane` (`Pages/GlobalCaseManagement/View.elm:1452-1460`) keeps only `Date.compare currentDate resolutionDate == LT`, so the entry vanishes at once; `NCDRecurrentEncounterPage` is reached only from that pane (`:1531`) and the report's back button.
- **The prenatal sibling does it right.** `generatePrenatalRecurrentPhaseCompletedMsgs` (`:9226-9249`) rebuilds `encounterWithDiagnoses` before deciding; the NCD copy does not.
- **Reachability.** Recurrent phase, the last pending result is the one that creates a diagnosis: RBS sent to lab → sugar count → `DiagnosisDiabetesRecurrent`; creatinine alone → `DiagnosisRenalComplications`. Entering the result navigates back to the recurrent encounter page, where Next Steps appears once the diagnoses revision applies; if the nurse leaves (Leave Encounter, reload, re-login) before completing it, the entry is gone. With two pending tests the first result updates the diagnoses before the second closes the entry.
- **Impact.** The medication distribution / hospital referral the lab result was meant to trigger is never recorded for that encounter (the initial phase is usually already ended); it resurfaces only at the next visit via `diagnosedPreviously…`. Both sites. Silent when it happens.
- **Fix shape (guess).** Recompute the diagnoses (as the prenatal sibling does) before evaluating `activityCompleted RecurrentNextSteps`, or drop the Next-Steps clause and rely on the close in `RecurrentActivity/Update.elm:41-77` (`generateNextStepsMsgs`).
