### B-043 — Acute-illness fever + prenatal MUAC read a GROUP_CONCAT list with a scalar cast → wrong flag on duplicate measurements; raw MUAC concat can hard-fail the whole dashboard decode — ✅ IMPLEMENTED 2026-08-16 (issue #2092, PR #2093, branch `b043-concat-scalar-reads` off origin/develop @caa405b52) · CONFIRMED-mechanism · promoted to Tier 3, LATENT on all 3 sites
- `hedley_stats.module` ~:986-993 (`GROUP_CONCAT(fever_period)`, `GROUP_CONCAT(body_temperature)`) then :1037-1038 `(float) $row->body_temperature >= 37.5` and `$row->fever_period > 0`: with ≥2 measurements of that type in one AI encounter, `(float)"36.8,38.6"` = 36.8 → fever-by-vitals uses only the first (COVID-suspect/complicated-infection undercount). Prenatal MUAC (~:1201-1203) passes the raw concat to `$item['muac']` → a two-value string reaches the client float decoder and can fail the ENTIRE dashboard-stats decode (agent flags this as the more dangerous variant). Requires duplicate same-type measurements in one encounter (unusual).
- **What shipped:** the two AI aggregates became `MAX(...)` — the HIGHEST temperature and LONGEST fever period decide, which is the clinically right reading and not what "first value" would give. Prenatal MUAC now goes through **`hedley_stats_extract_first_value()`, which ALREADY EXISTED and is used at 9 other sites** (well-child + nutrition MUAC, z-scores) — the prenatal read was the only one that didn't. ⭐ The B-159 lesson paid off: grepped for the helper before writing one.
- ✅ **Column types checked before trusting `MAX()`** — `field_body_temperature_value` is `float`, `field_fever_period_value` is `int(11)`, `field_muac_value` is `float`. Had they been varchar, `MAX` would be LEXICOGRAPHIC and `"9" > "38"`. Always check the column type before switching an aggregate to MAX.
- ✅ **LIVE SIZING 2026-08-16 — LATENT EVERYWHERE, nothing mis-reported today:** prenatal encounters with >1 DISTINCT muac = **0 on all three sites** (ihangane has 54,442 encounters WITH a muac, so the zero discriminates; `GROUP_CONCAT(DISTINCT …)` collapses equal values, which is why); AI encounters with >1 body_temperature = **2**, and both hold the SAME value repeated (`36,36` and `38,38,38`) so the cast happens to be right; >1 fever_period = **0**. So this is a guard, exactly like B-100.
