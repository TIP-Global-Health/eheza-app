### B-561 — National-ID search (Burundi, Somalia): an ID registered with a leading space is never found, because the search trims its input while the form stores the ID as typed — READY · LOW · tier 4 · CONFIRMED (code read both sides; count not measured) · DEPLOYED · the residue PR #2450 (B-382) declined and meant to log · R51 unit 4
- **Mechanism.** On Rwanda the registration form validates the ID to 16 digits; Burundi and Somalia accept any string, untrimmed:
  ```elm
  -- client/src/elm/Backend/Person/Form.elm:419-429
                  nationalIdNumberValidator =
                      case site of
                          SiteBurundi ->
                              nullable string

                          -- @todo - needs validation?
                          SiteSomalia ->
                              nullable string
  ```
  `Gizra/elm-form` `Validate.string` returns the value as typed, and the encoder sends it verbatim (`Backend/Person/Encoder.elm:26`). The search trims at both ends:
  ```elm
  -- client/src/elm/Components/PatientsSearchForm/Update.elm:45-56
          SetSearch search ->
              let
                  trimmed =
                      String.trim search
  ```
  ```elm
  -- client/src/elm/Backend/Update.elm:1619-1627
          FetchPeopleByNationalId nationalId ->
              let
                  trimmed =
                      String.trim nationalId
  ```
  and the index is a prefix match on the raw stored string:
  ```js
  // client/src/js/nodes.js:1001-1006
  return table.where('national_id_number').startsWithIgnoreCase(nationalIdContains).distinct()
  ```
  so `" 12/345"` stored never matches a search for `12/3`. The CSV importer trims (`hedley_person.module:858`), so only device-entered IDs are affected.
- **Reachability.** Burundi or Somalia nurse registers a person with a pasted or mistyped leading space, later searches by national ID. Rwanda is unaffected (digits-only validator).
- **Impact / size.** uvl and tip-somalia only; a miss leads to a duplicate registration. Not measured — B-382's scout counted 13 uvl IDs with a space anywhere, not leading spaces. Before #2450 these inputs froze the search field, so this is pre-existing, not a regression.
- **Already recorded, distinct.** B-382 (PR #2450) declined this from its scope and says "logged as B-521" — B-521 is the growth-chart gridline item; this entry is the missing record. B-257 is the duplicate-lookup trigger length; B-165 the search widget's mode switch.
- **Fix shape (first guess).** Trim (and possibly collapse inner whitespace) the national ID at write time in the person form for the free-text sites; the normalised index key B-382 named needs a Dexie schema bump and is the heavier alternative.
