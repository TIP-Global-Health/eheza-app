### B-332 — Backend error reporting: the GlitchTip event buffer is a `drupal_static`, and the stats/report/village builders call bare `drupal_static_reset()`, which empties it before the shutdown sender runs — errors in exactly the unattended AQ paths are never sent — READY · CONFIRMED (buffer, core reset semantics and 31 reset sites read) · LOW · tier 4 · R29 unit 5 · masked by B-331 today, survives its fix
- **Mechanism.** Events accumulate in `&drupal_static('logs_glitchtip_events', [])` (`logs_glitchtip.module:155`, read again at `:234`) and are flushed only by the shutdown function registered at `:61`. Core's no-argument `drupal_static_reset()` resets every named static to its default (`includes/bootstrap.inc` `drupal_static`: `foreach ($default as $name => $value) { $data[$name] = $value; }`), so the buffer becomes `[]`. Bare-reset callers: `hedley_stats.module` ×29 (every `hedley_stats_get_*` builder and `hedley_stats_calculate_stats_for_health_center`), `hedley_reports.module:1807`, `hedley_chw.module:140` (village creation batch loop), `hedley_activity.module:284`, `hedley_activity.drush.inc:49`.
- **Reachability.** AQ workers (stats recalculation, report generation) run as one drush process: an ERROR logged inside a builder is discarded at that builder's reset, long before shutdown. Web: an administrator creating a village drops any error logged earlier in that request.
- **Fix shape (guess).** Keep the buffer where `drupal_static_reset()` cannot reach it (a function-local `static`, or `$GLOBALS`), or send immediately instead of at shutdown.
