### B-306 — Acute Illness follow-up: a saved follow-up keeps the diagnosis it was saved with, so a later diagnosis correction leaves case management showing the outdated one — READY · PLAUSIBLE (mechanism confirmed; not live-sized) · LOW · tier 4 · side-finding from the B-280 review
- **What is wrong.** `toFollowUpValue` (`Pages/AcuteIllness/Activity/Utils.elm`, near `FollowUpForm`) embeds the encounter's diagnosis into `AcuteIllnessFollowUpValue` at save time, and nothing refreshes the stored follow-up when the encounter's diagnosis later changes. A follow-up saved between a wrong diagnosis and its correction carries the outdated diagnosis into case management.
- **Siblings do it right.** The nutrition / well-child paths refresh follow-ups when an assessment changes (`updateAssesmentOnFollowUpMsg` in `Backend/Update.elm`); the acute-illness path has no equivalent.
- **Exposure.** Pre-existing on first encounters (their diagnosis has always been re-written when measurements change). PR #2185 (B-280) extends the same mutability to subsequent visits, so the window now exists there too. Requires the worker to save Next Steps' follow-up and then correct the RDT/danger signs in the same encounter — reviewer judged PLAUSIBLE / low severity; no live sizing done.
- **Fix shape (guess).** Mirror `updateAssesmentOnFollowUpMsg` for acute illness: when the diagnosis write fires and the encounter already has a follow-up, re-save the follow-up value with the new diagnosis.
- **Relations.** Found by the [[B-280]] review (PR #2185, inline thread on `Backend/Update.elm`).
