- **Found R37 unit 2** (head-circumference / z-score cluster as merged, @e747d3eaf).
- **Mechanism.** `clear-implausible-zscores.php` deletes z-score rows straight from `field_data_*` / `field_revision_*` without saving the node, so no node hooks run. It queues the NCDA recalculation itself and tells the operator to run `recalculate-stats.php`. Nothing refreshes the reports data, which keeps its own copy of these z-scores.

  - The copy: `hedley_reports_calculate_aggregated_data_for_person` (`hedley_reports.module:561-606`) reads `field_zscore_age` / `field_zscore_length` from the loaded height and weight nodes into `s` / `w` / `u`, and stores the result in `field_reports_data` (`:1342`).
  - Statistical Queries read only that stored field (`hedley_reports_generate_results_data_for_restful`, `:1875-1934`). It is rebuilt only when a node hook queues `HEDLEY_REPORTS_CALCULATE_AGGREGATED_DATA`.
  - The report bands stored values: `server/elm/src/Pages/Reports/Utils.elm` `categorizeZScore`: `if score <= -3 then ... else if score <= -2 then`. So a leftover −25 still counts as severe stunting or underweight.
- **Impact.** All sites, once the script runs at deploy. The PR #2294 description promises "Underweight, stunting and wasting statistics no longer count these values". That holds for dashboards but not for Statistical Queries. Scout's ihangane.live count: **4,652 children** with a height- or weight-for-age z-score the script will clear (3,169 height and 2,800 weight measurements, 3,189 weight-for-length; the per-type figures match the PR body). Head-circumference z-scores (~29.9k) are read by no report, NCDA or stats consumer.
- **Secondary.** Both queues are built from `$cleared`, the rows this run deleted. If a run dies after the deletes but before queuing, a re-run finds nothing and queues nothing.
- **Folded in (same deploy step, marginal).** `mark-zero-head-circumferences-not-taken.php` changes encounter warnings from microcephaly to `no-head-circumference-warning` under drush, where `hedley_stats_trigger_stats_recalculation` returns early on `drupal_is_cli()`. So the dashboard `numberOfCephaly` keeps counting those encounters until stats are recalculated, and, unlike its sibling, the script prints no "now run recalculate-stats.php". Live: 5 encounters on ihangane.
