### B-424 — Prenatal recurrent labs: entering the last outstanding result saves the labs-results record twice, and the second save is built from the pre-save copy, so that test drops out of "completed" and the next encounter asks for it again — READY · CONFIRMED (orchestrator traced handler → both generators → PATCH path → every reader, and sized live) · MED-LOW · tier 3 · R36 unit 1 · DEPLOYED (same shape on origin/main)

  Both go `SaveLabsResults` → `saveMeasurementCmd … (Just id)` → `sw.patchFull` (`Backend/Utils.elm:276-279`). In `client/src/js/nodes.js:245` `patchNode` does `table.update(uuid, json)` and then builds the upload change row from `table.get(uuid)`, so the later update wins locally and on the server: `resolutionDate` set, `completedTests` missing the test just entered, `reviewState` reverted. Same shape a second time in `processVitalsRevisionAndUpdatePrenatalLabsResults` (`:2227-2290`, `TestVitalsRecheck`). The NCD sibling `generateNCDLabsResultsAddedMsgs` (`:9395-9407`) has a "do not update if already set" guard and emits one message.
- **Reach.** Nurse (not lab tech — the helper returns `[]` for lab techs) on the recurrent activity page enters the last outstanding result while no other recurrent activity is pending — i.e. every all-normal panel (no Next Steps, no vitals recheck, no follow-ups). Ten revision arms route here (`:3075-3280`).
- **Readers of the stale record.** `generatePendingLabsFromPreviousEncounters` (`Pages/Prenatal/Activity/Utils.elm:5542-5560`, `performed − completed`) feeds `expectLaboratoryTask` (`:5424`) and the labs-history section (`Activity/View.elm:3872`): the NEXT nurse encounter lists the test as pending from the previous visit and asks for a result or an explicit "completed". `secondPhaseRequired` (`Pages/Prenatal/Encounter/Utils.elm:1010-1017`) keeps offering "Pause" instead of "End" if the initial page is revisited; `NextStepsWait` (`Activity/Utils.elm:545-560`) is re-expected there. `reviewState` reverting has no nurse-visible effect (Case Management hides the entry by `resolutionDate`).
- **Live (orchestrator, 2026-09-22, ihangane):** 16 resolved records where `hiv` is in performed, absent from completed, and a `prenatal_hiv_test` node with a result exists for the encounter (latest resolution 2026-09-18); HIV only — other test types add to it. 1,212 resolved records have completed < performed overall (mixed causes), 19,311 have none. Not site-specific.
- **Fix shape (first guess):** let the single results-added message own the whole value (it already sets `resolutionDate` for the nurse all-completed case) and have `generatePrenatalRecurrentPhaseCompletedMsgs` skip its PATCH when a labs message precedes it — or thread the updated value into it. Keep the standalone path (`processPrenatalRevisionPossiblyCompletingRecurrentPhase`, `:2300`) working, since it reaches the helper with no preceding labs message.
