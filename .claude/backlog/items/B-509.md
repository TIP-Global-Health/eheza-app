### B-509 — Completion report full run (#2417's post-deploy step): every encounter of seven programs gets a new revision, so every device re-downloads all of them and one Statistical Queries recalculation is queued per person; the step does not say so — READY · MED-LOW · tier 3 · CONFIRMED (code, 2026-10-26) · UNRELEASED (develop, ships with #2417)
- **Mechanism.** Each of the seven history-reading builders ends with an unconditional save of every encounter it processed, with no comparison against the stored value:

  ```php
  -- server/hedley/modules/custom/hedley_reports/hedley_reports.module:3875-3876 (Acute Illness; same tail at :4876, :6392, :6871, :7467, :7623, :7891)
      $encounter->field_reports_data[LANGUAGE_NONE][0]['value'] = json_encode($completion_data);
      node_save($encounter);
  ```

  The `--exclude_set` guards (`:3766`, `:3811` and siblings) are the only skip, and #2417's step runs the scripts without the flag on ihangane, vhw and uvl. Every save goes through `hedley_device_node_presave()` (`hedley_device.module:22-27`), which sets `$node->revision = TRUE` unless `hedley_device_disable_revisions` is set, so each encounter gets a new `vid`. The device sync endpoint selects `node.vid > base` over the sharded bundles (`HedleyRestfulSync.class.php:141-152`, `HEDLEY_RESTFUL_SHARDED` in `hedley_restful.module`), and all seven encounter bundles are sharded — so every device re-downloads every Acute Illness, Child Scoreboard, HIV, NCD, Prenatal, TB and Well Child encounter of its health centres, 500 per request. Every save also fires `hedley_reports_node_update()` → `hedley_reports_trigger_recalculation_by_edited_content()` → `hedley_reports_trigger_recalculation_by_new_content()` (`:165-170`, `:367-405`, `:415-438`), which enqueues `HEDLEY_REPORTS_CALCULATE_AGGREGATED_DATA` once per person (deduplicated only while an item for that person is queued or processing). `node_revision` and the `field_revision_*` tables grow by one row per encounter.
- **Precedent.** The same side effect has happened before on a smaller scale: release #1468 (2026-01) ran the prenatal script in full and #1918 (2026-08) the NCD one, both with the AQ mirror already in place (`b252a45ec`, in v1.18.2). B-341 recorded the re-download for ~3,200 restored persons as something "to plan for". #2417 runs seven scripts at once with no note.
- **Impact (on release).** Sync load on every device of every health centre of three sites until all encounters are pulled again; an AdvancedQueue backlog of one aggregated-data recalculation per person with any such encounter, drained by the single Jenkins worker (H/10, serialized); revision tables grow by the encounter count. Report data is correct afterwards; B-185's content fix needs the full run. Magnitude, measured on the ihangane copy of 2026-10-26 02:00 UTC (published, not deleted, joined to a participant):

  | bundle | encounters | persons |
  |---|---|---|
  | prenatal_encounter | 69,036 | 36,319 |
  | well_child_encounter | 49,842 | 30,098 |
  | acute_illness_encounter | 30,410 | 19,293 |
  | child_scoreboard_encounter | 21,569 | 11,198 |
  | ncd_encounter | 8,022 | 4,686 |
  | tuberculosis_encounter | 285 | 116 |
  | hiv_encounter | 62 | 57 |
  | **all seven** | **179,226** | **94,902 distinct** |

  So the step writes ~179k new revisions on ihangane and queues up to ~95k `hedley_reports_calculate_reports_data` items (the queue held 39,947 done items in total on that copy), all drained by the single serialized Jenkins worker; `hedley_device_disable_revisions` is `b:0` on ihangane, so every one of those revisions is downloaded by every device holding that health centre.
- **Evidence.** Builder tails, presave flag, sync `vid` filter, sharded list, update hook and AQ dedup all read on `origin/develop` 18ac201aa by the orchestrator; the scout traced the same chain. Not run against a live copy yet.
- **Fix shape (first guess).** Skip `node_save` when the encoded JSON equals the stored `field_reports_data` value, so only encounters whose completion data changes get a revision (B-185 says ~6 % of them). Alternatively run the step with `hedley_device_disable_revisions` set and restored afterwards, and in either case say in #2417's step what devices and the queue will do. Not a repair script.
