### B-399 — `field_incident_type` allows `files-upload`, but the client sends `file-upload` and the backend stores it unvalidated — 9 live rows hold a value outside the field's option set — READY · CONFIRMED (orchestrator traced both sides and counted live rows) · LOW · tier 4 · R34 unit 5 · ⭐ DEPLOYED, all four sites
- **Mechanism.** The exported option set has one spelling:
  ```php
  -- server/hedley/modules/custom/hedley_device/hedley_device.features.field_base.inc:93-96
      'settings' => array(
        'allowed_values' => array(
          'files-upload' => 'Files upload',
          'content-upload' => 'Content upload',
  ```
  The client sends the other:
  ```elm
  -- client/src/elm/SyncManager/Encoder.elm:203-205
          FileUploadIncident identifier ->
              [ ( "incident_type", string "file-upload" )
  ```
  and the backend writes it verbatim (`hedley_restful.module:454-457`, `$wrapper->field_incident_type->set($incident_type);`). Nothing rejects it: `EntityMetadataWrapper::set()` validates only the data type plus an optional validation callback, and list/options fields register none. `'files-upload'` appears exactly once in the whole repo — in that array. `'file-upload'` is what the client, `app.js` (`/api/file-upload`) and the backend's own docblock (`hedley_restful.module:425`) all use.
- **Reachability (traced).** Live sync path, no admin action: `SyncManager/Utils.elm:136` / `:182` raise `SyncReportIncident (FileUploadIncident reason)` when a photo or screenshot upload exceeds `fileUploadFailureThreshold` with a non-network error → `SyncManager/Update.elm:934-938` POSTs `/api/report-sync-incident`.
- **Evidence (orchestrator live query, 2026-09-21).** `terminus remote:drush ihangane.live -- sql-query "SELECT field_incident_type_value, COUNT(*) FROM field_data_field_incident_type GROUP BY 1"` → `content-upload 794`, **`file-upload 9`**. Live, not latent.
- **Impact.** Ops-facing, no patient data. The stored key has no label in the option set, so the `sync_incident` edit form renders the select with nothing chosen and an admin cannot save without changing the type; the `list_default` formatter and the auto-label token fall back to the raw key; and any future code mapping `allowed_values` to labels, or any exposed Views list filter on this field, silently omits all nine. Deduplication inside `hedley_restful_report_sync_incident` uses the same literal both ways, so incidents are not duplicated.
- **Fix shape (guess).** Make the two agree — most likely add `'file-upload'` to `allowed_values`. ⚠ Decide first whether `'files-upload'` was ever written; renaming the Elm literal instead would orphan the nine existing rows.
