### B-380 — E2E: the Acute Illness nurse test "report shows lemon juice or honey only when it was given" flakes — after saving the physical exam it times out waiting for the encounter page, on PRs that do not touch that flow — READY · CONFIRMED as intermittent (two failing CI logs read; mechanism NOT traced) · LOW · tier 4 (test harness, no app impact seen) · added 2026-09-17 as a side-finding while shipping B-375 (PR #2264) and B-259/B-222 (PR #2269)
- **Symptom.** `e2e_playwright_1` fails in `completePhysicalExam` → `saveActivity`:
  ```ts
  -- client/e2e/helpers/acute-illness.ts:59-69
  async function saveActivity(page: Page, actionsClass: string) {
    await click(
      page.locator(`.actions.${actionsClass} button.ui.fluid.primary.button`, { hasText: 'Save' }),
      page,
    );
    // Wait for return to encounter page.
    await page
      .locator('div.page-encounter.acute-illness')
      .waitFor({ timeout: 10000 });
  ```
  `TimeoutError: locator.waitFor: Timeout 10000ms exceeded — waiting for locator('div.page-encounter.acute-illness') to be visible`, at `acute-illness-encounter-nurse.spec.ts:346`.
- **Evidence.** CircleCI job 30761 (PR #2264, `28a13340e`, PHP-only change) and job 30859 (PR #2269, `cb2505cba`, person-save initiators only). The same test passed on both PRs' other runs (jobs 30802, 30785), so 2 failures in 4 runs.
- **Not yet known.** Whether Save did not register, the exam had a task left open, or the page took longer than 10 s. The failure screenshot (`test-failed-1.png` artifact) would tell; not read.
- **Fix shape (guess).** Read the screenshot from a failing run first; then either wait on the save button's effect rather than a fixed 10 s, or fix the missed field.
- 🔎 **R34 unit 1 — candidate mechanism (a lead, not verified; the suite cannot be run from a scout seat).** The failure is `completePhysicalExam` → `saveActivity` timing out on `div.page-encounter.acute-illness`. The diagnosis popup is *inside* that div (`Pages/AcuteIllness/Encounter/View.elm:63-72`), so the popup is not the cause. What is unguarded is the click: the acute-findings branch clicks both "None of the above" labels in a loop with **no `waitForTimeout` between them** (`client/e2e/helpers/acute-illness.ts:637-646`) and goes straight into
  ```ts
  -- client/e2e/helpers/acute-illness.ts:59-68
  async function saveActivity(page: Page, actionsClass: string) {
    await click(page.locator(`.actions.${actionsClass} button.ui.fluid.primary.button`, { hasText: 'Save' }), page);
    await page.locator('div.page-encounter.acute-illness').waitFor({ timeout: 10000 });
  ```
  which never checks `.active`. The suite's own shared helper documents why that matters — `client/e2e/helpers/common.ts:650-653`: *"A button without `active` has no click handler, so the click below would be silently dropped"*. If the second checkbox's re-render has not landed, the Save click is dropped and the 10 s wait times out — intermittently, in exactly this helper, on PRs that touch nothing.
- ⚠ This flake lives in `e2e_playwright_1`, whose two legs are joined by `&&` ([[B-396]]) — so each occurrence also silently skips the job's other 25 tests.
