  For an initial encounter `assembled.diagnosis` is the resolver's output (`Encounter/Utils.elm:96-105`), never the stored `encounter.diagnosis`, and the resolver's age-based predicates read `currentDate` — respiratory-rate thresholds (`respiratoryRateElevated currentDate person`, `Activity/Utils.elm:2795-2809`), the MUAC / nutrition exam expectations (`expectPhysicalExamTask`, `:1839-1846`). `getAcuteIllnessEncountersForParticipant` returns the dict in insertion order (not sorted), so "first" is the REST order's head — in practice the initial encounter.
- **Reachability.** Participant page → Record outcome, days or weeks after the first visit → outcome page. The label differs from the stored diagnosis only when the child crossed an age threshold (2 / 6 / 12 / 60 months) between the first visit and today and that threshold decides the diagnosis (e.g. a respiratory rate that was elevated for the age at the visit and is normal for the age today → "Simple cold and cough" instead of "Uncomplicated respiratory infection").
- **Impact.** One label, display only; the stored diagnosis, the report and Case Management are untouched. Rare (needs a boundary crossing inside the illness's span).
- **Already recorded, distinct.** B-360 (progress report physical-exam pane judged against age today — the same class on another pane), B-220 (report reads the stored diagnosis — fixed), B-567 (the subsequent-visit page diagnosis). Grepped `Outcome`, "age today", `viewPersonDetailsWithAlert`.
