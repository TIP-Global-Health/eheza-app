### B-291 — NCDA Antenatal Care step (all four hosts): tapping an already-recorded ANC month silently stores a phantom ANC visit date — READY · CONFIRMED (every hop re-verified by orchestrator) · MED-LOW · tier 4 · R27 unit 1
- **Mechanism.** `Measurement/View.elm:3588-3612` (`viewRadioButton` in `ancVisitsInpustAndTasks`): `disabled = List.member monthNumber encountersMonthsFromANCData` is only a `classList` entry on an `input[type=radio]` that is `display: none` (`client/src/assets/scss/_new.scss:953-955`; the `.checked.disabled` rule only sets `opacity: 0.5`, and its `pointer-events: none` is a comment, `:968-971`). The visible clickable element is the label, whose `onClick` unconditionally dispatches `toggleANCVisitDateMsg dateForMonth` with the synthetic date `pregnancyStartDate + (monthNumber-1) months + 14 days`. For a month backed by a real prenatal encounter, `isChecked` is true regardless of form state, so the tap changes nothing on screen while `ToggleANCVisitDate` inserts the date into `form.ancVisitsDates` — all four copy-adapted handlers behave identically (`Measurement/Update.elm:288-322`, `Pages/Nutrition/Activity/Update.elm:389`, `Pages/WellChild/Activity/Update.elm:1536`, `Pages/ChildScoreboard/Activity/Update.elm:96`). `toNCDAValue` (`Measurement/Utils.elm:8841`) persists it into `anc_visits_dates`. A second tap removes it; neither tap gives feedback.
- **Reachability.** First NCDA fill only (`expectNCDAStep`: `NCDAStepAntenatalCare -> ncdaNeverFilled`, `Measurement/Utils.elm:9370-9377`), from any of the four NCDA hosts (group session `Measurement/View.elm:3868`, Nutrition `Pages/Nutrition/Activity/View.elm:487`, WellChild `:2163`, ChildScoreboard `Pages/ChildScoreboard/Activity/View.elm:138`); the month grid renders after answering Yes to "ANC encounters not recorded?". Tapping a month that already shows a recorded visit is a plausible confirm-this-month gesture.
- **Impact.** A phantom ANC visit is written into the questionnaire: (a) in-form, the counseling gate `(ancDataVisits + formVisists) < 4` (`View.elm:3624-3637`) counts the month twice — the low-ANC-attendance counseling is wrongly suppressed at 3 real visits; (b) the client scorecard unions **exact dates** (`Pages/WellChild/ProgressReport/View.elm:1869-1918`), and the synthetic mid-month date is distinct from the real encounter's date, so `allEncountersDates` is inflated toward the ≥4 green-V gate; (c) the server aggregated scoreboard appends questionnaire dates raw (`hedley_ncda.module:725-746` — B-190's counting site). Distinct from B-190 (server missing dedup, downstream) and from the B-283 raw-form family: this is the client minting the bad date, and it fires mid-first-fill with a live raw form. Flag-gated surface: `ncda` = ihangane only (0/absent on vhw/uvl/tip-somalia, live-checked 2026-09-01); child-scoreboard data also lives on ihangane (11,579 participants; zero on vhw).
- **Fix shape (guess).** Suppress the label's `onClick` (or dispatch a no-op) when `disabled` is true; optionally also drop form dates falling in already-recorded months in `toNCDAValue`.
- **Sizing (written, not run).** Phantom signature: a stored `field_anc_visits_dates` date in the same pregnancy-month as a real prenatal encounter of the same child's pregnancy (every widget date is synthetic mid-month by design, and a genuine second-same-month visit is not expressible in the widget either, so same-month overlap ≈ the defect). Needs the child → `field_newborn` participant → prenatal-encounter join. Cheap prevalence first: `SELECT n.type, COUNT(DISTINCT f.entity_id) FROM field_data_field_anc_visits_dates f JOIN node n ON n.nid = f.entity_id WHERE n.status = 1 GROUP BY n.type;`
