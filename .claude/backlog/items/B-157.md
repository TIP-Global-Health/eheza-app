### B-157 — CI gating cluster: the only server-side test job can pass with ZERO tests run, + 6 smaller gate defects — READY (each part independent) · CONFIRMED (a/b headline self-verified by orchestrator; grep matrix + shell mechanics proven by running) · **(a) HIGH · release-prep** · R19 Unit 5
- **(a) Simpletest job goes green if the runner never runs** — `.ddev/commands/web/simpletest:9-15` (self-verified verbatim 2026-08-11): `php ./www/scripts/run-tests.sh ... | tee /tmp/simpletest-result.txt` (pipe eats the runner's exit code; no `set -e`/`pipefail` in the wrapper), gate is ONLY `grep -E -i "([1-9]+ fail)|(Fatal error)|([1-9]+ exception)|([0-9]+0 fail)|([0-9]+0 exception)" && exit 1`, then **unconditional `exit 0`**. No exit-status check, no positive assertion that any test ran. Proven by stub runs: runner exit 255 + "Segmentation fault" → GREEN; `Could not open input file: ./www/scripts/run-tests.sh` → GREEN; "ERROR: The simpletest module must be enabled" → GREEN; empty output → GREEN. `drush en simpletest -y` (line 7) also unchecked. Failure scenario: a broken site build (post-start hooks) leaves the ONLY server-side test job green on every PR of the pending release — nothing distinguishes "0 failures" from "0 tests". Fix: `set -o pipefail` + capture runner exit + require a `\d+ passes` summary line with passes ≥ 1.
  📌 **Positive half, answers the open gating question (durable):** for COMPLETED runs the grep DOES gate on exceptions — `0 fails, 2 exceptions` → RED, `Fatal error` → RED, trailing-zero counts (10/20) handled by the digit-class trick (all proven by running the exact grep). The hole is exclusively the never-ran case.
- **(b) `ddev restart || ddev logs` masks install failure** — `ci-scripts/install_drupal.sh:11` under `set -e` (self-verified; same pattern `install_ddev.sh:21`, dormant there): failing restart + succeeding `ddev logs` → step green. Compounds (a): the whole Drupal install is DDEV post-start hooks, and ddev's documented behavior is warn-and-continue on hook failure (this hop PLAUSIBLE — ddev not runnable in the audit env), so simpletest can go green with no site. In e2e jobs the same mask surfaces as misattributed "flaky e2e" reds. Fix: `ddev restart || { ddev logs; exit 1; }`.
- **(c) No `forbidOnly` in `client/playwright.config.ts`** (self-verified absent) — a committed `test.only` silently shrinks an e2e shard to one test, job stays green; e2e is the only functional QA for the release. Fix: `forbidOnly: !!process.env.CI` (1 line). CONFIRMED · MED.
- **(d) E2E failure artifacts never uploaded on failure** — `.circleci/config.yml:146-148/:200-202/:254-256` `store_artifacts` defaults to `when: on_success`, so screenshots (`only-on-failure`) + traces are lost exactly when a test fails; every red e2e run is debugged blind. Fix: `when: always`. CONFIRMED (CircleCI step semantics) · MED (diagnosis, not gating).
- **(e) lint_elm_review runs UNPINNED registry-latest elm-review** — job steps are checkout→install→test with no npm install (self-verified `.circleci/config.yml:54-60`), `node_modules` gitignored ⇒ `npx elm-review` (test_elm_review.sh:15/:34) auto-installs latest at run time, ignoring both package.json pins. Required gate whose toolchain changes overnight + live registry dependency. Fix: `npm ci` in the job or `npx elm-review@<pin>`. CONFIRMED · MED-LOW.
