- ✅ **(a) IMPLEMENTED (issue #2066, PR #2067, MERGED).** Was: **simpletest job goes green if the runner never runs** — `.ddev/commands/web/simpletest:9-15` (self-verified verbatim 2026-08-11): `php ./www/scripts/run-tests.sh ... | tee /tmp/simpletest-result.txt` (pipe eats the runner's exit code; no `set -e`/`pipefail` in the wrapper), gate is ONLY `grep -E -i "([1-9]+ fail)|(Fatal error)|([1-9]+ exception)|([0-9]+0 fail)|([0-9]+0 exception)" && exit 1`, then **unconditional `exit 0`**. No exit-status check, no positive assertion that any test ran. Proven by stub runs: runner exit 255 + "Segmentation fault" → GREEN; `Could not open input file: ./www/scripts/run-tests.sh` → GREEN; "ERROR: The simpletest module must be enabled" → GREEN; empty output → GREEN. `drush en simpletest -y` (line 7) also unchecked. Failure scenario: a broken site build (post-start hooks) leaves the ONLY server-side test job green on every PR of the pending release — nothing distinguishes "0 failures" from "0 tests". Fix: `set -o pipefail` + capture runner exit + require a `\d+ passes` summary line with passes ≥ 1.
  📌 **Positive half, answers the open gating question (durable):** for COMPLETED runs the grep DOES gate on exceptions — `0 fails, 2 exceptions` → RED, `Fatal error` → RED, trailing-zero counts (10/20) handled by the digit-class trick (all proven by running the exact grep). The hole is exclusively the never-ran case.
