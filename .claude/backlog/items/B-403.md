### B-403 — The `HandleRevisions` re-assessment dispatch has no test and cannot get one the usual way, so dropping a revision from B-365's list would silently stop the nurse assessment re-running — READY · CONFIRMED (scout searched every suite; orchestrator confirmed the constraint is already recorded) · LOW · tier 4 · R34 unit 2 · coverage hole
- **The hole.** [[B-365]] (tier 1, implemented, deployed) added `MedicalHistoryRevision`, `ObstetricHistoryRevision`, `ObstetricHistoryStep2Revision`, `ObstetricalExamRevision`, `PrenatalNutritionRevision` and `PrenatalUltrasoundRevision` to the special-case list in `processRevisionAndAssessPrenatal` (`client/src/elm/Backend/Update.elm:2979-3320`). Its own entry records only "scout scratch test for one input"; **no `Test.elm` mentions `processRevisionAndAssessPrenatal` or any of those constructors.** Every other tier-1 item of rounds 26–31 (B-286, B-320, B-323, B-324, B-336, B-339, B-343, B-344, B-345, B-364) has permanent Elm cases.
- **The named untested behaviour.** Dropping any single revision name from that list stops the nurse assessment re-running after the corresponding save, leaving a stale preeclampsia-risk diagnosis that gates Aspirin. Nothing would fail.
- **Why the obvious test is impossible.** `elm-test` cannot import `Backend.Update` — CI's `test_elm` OOM-kills the compile with no error output ([[elm-test-cannot-import-backend-update]]). The prescribed workaround is a seam in the owning `Pages/*/Utils` module; nobody has built one, so the **whole 214-branch `handleRevision` dispatch table is untestable and untested**, not just B-365's six.
- **Other named holes found alongside** (same unit, recorded here rather than as separate items): `/api/sync` upload (`handleChanges`) is exercised by exactly one scenario, `HedleyPatientConsolidation::checkPersonPatchKeepsPhoto()` — batch semantics, partial failure, `db_version` mismatch and the whole-batch-delete-on-200 contract that the per-record-commit design brief turns on have no test at all; `hedley_general_apply_exclude_deleted()`'s single-alias trap has none; the two daily Jenkins duplicate-measurement sweeps have none.
- **Fix shape (guess).** Build the seam once, in the module that owns the prenatal assessment, and test the list through it — the value is the seam, not any single case.
