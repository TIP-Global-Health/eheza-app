### B-400 — The Well Child "Vitals skip round-trip" e2e test passes when the vitals row is missing entirely, which is the regression it exists to catch — READY · CONFIRMED (scout traced both files; orchestrator re-read the helper and the assertion) · LOW · tier 4 · R34 unit 1
- **Mechanism.** The query helper initialises its return value to exactly what cycle 1 asserts, and returns it when the row can never be read:
  ```ts
  -- client/e2e/helpers/well-child.ts:1116-1127, 1141
    let last: { rr: number | null; temp: number | null } = { rr: null, temp: null };
    for (let attempt = 0; attempt < 10; attempt++) {
      ...
        if (parsed.error) {                       // e.g. 'No well_child_vitals row'
          console.log(`queryWellChildVitalsValues attempt ${attempt + 1}: ${parsed.error}`);
          if (attempt < 9) { execSync('sleep 5'); continue; }
          return last;                            // {rr: null, temp: null}
        }
  ```
  ```ts
  -- client/e2e/well-child-encounter-chw.spec.ts:264-268
      {
        const vitals = queryWellChildVitalsValues(fullName, { rr: null, temp: null });
        expect(vitals.rr, 'cycle 1: RR should be null (skipped)').toBeNull();
        expect(vitals.temp, 'cycle 1: BT should be null (skipped)').toBeNull();
      }
  ```
- **Impact.** A regression in which "both measurements skipped" saves **no** `well_child_vitals` row at all — the exact case the test was built for, since skip-both *is* cycle 1 — is invisible: cycle 1 passes on the error default, cycle 2 unticks BT, types 36 and creates the row, so cycles 2–4 and the final assertions pass too. The whole test stays green. It also burns 50 s of retry sleeps per occurrence before passing. No assertion anywhere in the test distinguishes "row exists with nulls" from "no row".
- **Fix shape (guess).** Have the helper report "no row" distinguishably — throw, as `queryNCDAWeight` already does at `helpers/child-scoreboard.ts:630-632` — rather than returning a value that is also a legitimate expectation.
