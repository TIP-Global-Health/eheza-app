### B-539 — Statistical Queries, date-range reports: a pregnancy is admitted or dropped by the day its participant node REACHED the server, so a pregnancy whose first ANC visit falls inside the range but whose upload came after the TO date vanishes with all its encounters — READY · LOW-MED · tier 4 · CONFIRMED (code; sized on the 2026-11-02 ihangane copy) · DEPLOYED · R49 unit 1
- **Mechanism.** The per-person reports JSON stamps each pregnancy with the participant node's arrival date:
  ```php
  -- server/hedley/modules/custom/hedley_reports/hedley_reports.module:1066-1070
      // Adding participant data for pregnancies.
      if ($participant_type == HEDLEY_STATS_PRENATAL_ENCOUNTER_TYPE) {
        $participant_data = [
          'created' => date("Y-m-d", $individual_participant->created),
        ];
  ```
  and the admin app's date-range filter reads it as the pregnancy's existence date:
  ```elm
  -- server/elm/src/Pages/Reports/Utils.elm:822-825
                                      (\participantData ->
                                          -- Pregnancy was created not after the TO date.
                                          if Date.compare participantData.created limitDate == GT then
                                              Nothing
  ```
  Offline-first devices upload days or weeks after the visit. A report FROM 1 Aug TO 31 Aug run in September drops a pregnancy whose first visit was 20 Aug but whose participant arrived 5 Sep, together with every August encounter under it. The clinical start exists on the node: `field_expected.value`, which the Dashboard builder already uses for the same purpose (`hedley_stats.module:1143` `'created' => date_format(date_create($row->field_expected), 'Y-m-d')`).
- **Reachability.** `hedley_reports_node_insert/update` → AQ `hedley_reports_calculate_reports_data` → `field_reports_data` → `HedleyRestfulReportsData` → Statistical Queries (admin / Statistical Queries Manager), both sites.
- **Size.** Of 7,412 antenatal `individual_participant` nodes created since 2025-01-01 on ihangane, 350 (4.7 %) arrived in a later month than their `field_expected` start and 94 arrived more than 30 days after it (orchestrator re-ran the count). Member of the arrival-time family with B-540 and B-541; B-249 is the Dashboard sibling (family planning by `created`).
- **Fix shape (first guess).** Emit `field_expected[value]` as the pregnancy's `created`, falling back to the node date when empty. One line in the JSON builder; stored report data regenerates on the next recalculation.
