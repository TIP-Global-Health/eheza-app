### B-553 — Group session child progress report: the page never requests the session's measurement calculation, so after any sync download (or a reload at that URL) today's group assessment is filed under "Review prior diagnoses" instead of Active — READY · LOW · tier 4 (display; B-469's symptom by another cause) · CONFIRMED (code; not rendered) · DEPLOYED · R50 unit 1
- **Mechanism.** The route returns no calculation messages, unlike every other session page:
  ```elm
  -- client/src/elm/Pages/ProgressReport/Fetch.elm:9-18
  fetch childId db =
      ( (FetchHealthCenters
          :: Backend.Model.FetchExpectedSessions childId
          :: Backend.NutritionEncounter.Fetch.fetch childId db
        )
          ++ Pages.AcuteIllness.Participant.Fetch.fetch childId db
      , []
      )
  ```
  ```elm
  -- client/src/elm/Pages/Participant/Fetch.elm:8-9
  fetch sessionId =
      ( [], [ FetchEditableSessionMeasurements sessionId ] )
  ```
  The view's "today's assessment is active" flag reads the session's measurement `LocalData`:
  ```elm
  -- client/src/elm/Pages/ProgressReport/View.elm:43-44
          mandatoryNutritionAssessmentMeasurementsTaken =
              mandatoryActivitiesCompleted currentDate zscores features session.offlineSession childId isChw db
  ```
  ```elm
  -- client/src/elm/Activity/Utils.elm:674-678
  childHasCompletedActivity childId activityType session =
      getChildMeasurementData2 childId session
          |> LocalData.map (hasCompletedChildActivity activityType)
          |> LocalData.withDefault False
  ```
  `makeEditableSession` rebuilds with `measurementData = Success NotNeeded` (`Backend/Update.elm:10107-10108`); a downloaded batch with any session-type revision runs `processRevisions` → `makeEditableSession` for every loaded session (`:2513-2541`). On the child page the next 50 ms tick repairs it because the page wants `FetchEditableSessionMeasurements`; on the progress report nothing wants it, so the flag turns `False` and stays. With it `False`, `resolveDateOfLastNutritionAssessment` (`Pages/WellChild/ProgressReport/View.elm:803-827`, `InitiatorNutritionGroup` → `.dateMeasured >> (/=) currentDate`) excludes today's group measurements and returns the previous session's date, so today's entries partition into the completed list.
- **Reachability.** Nurse → child page → Progress report (`Pages/Participant/View.elm:182`); correct on arrival, flips on the first sync download carrying a session-type revision while the report is open; also every reload at `/session/<id>/progress-report/<child>`.
- **Impact.** Which section of the report (and of the WhatsApp-shared list) today's assessment shows in. Both sites.
- **Already recorded, distinct.** B-469 (Child Scoreboard passes a constant `False`), B-024 (health centers fetch), B-362 (WhatsApp mode).
- **Fix shape (first guess).** Return `[ FetchEditableSessionMeasurements sessionId ]` as the calculation list for `ProgressReportPage` (the caller in `Pages.Session.Fetch` has `sessionId`).
- **Production check 2026-11-09 (read-only).** ihangane: 133 group sessions scheduled in the last 90 days, so the page's path is in daily use. How often a report is open during a download is not measurable from the database.
