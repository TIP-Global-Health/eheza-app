### B-458 — Admin content: outside super user mode, three more ways to delete or unpublish a node are still offered and always fail with an uncaught exception — READY · VERIFIED (code read) · LOW · tier 4 · DEPLOYED, all sites
- **Found 2026-10-07** in the review of #2315 (B-414), round 1, findings 1–2; the content list's bulk Delete / Unpublish and row Delete link are handled there.
- **Mechanism.** `hedley_admin_node_delete()` and `hedley_admin_node_update()` throw outside super user mode, but these entry points stay:
  - the bulk action "Change value" (`views_bulk_operations_modify_action`, `display_values` `_all_`) can set Published to No;
  - the `node/N/delete` tab and the Delete button on every node edit form.
- **Why the access layer does not help.** `node_access()` returns TRUE for *bypass node access* before any `hook_node_access`, and `administrator` holds it.
- **Fix shape (guess).** Hide the edit-form Delete button and gate the `node/%node/delete` route on super user mode; give "Change value" an explicit property list without `status`.
