### B-135 — Service-worker decode errors reach Rollbar labeled "db" instead of the purpose-built "sw" source — READY · CONFIRMED · LOW · 1-line
- `ServiceWorker/Update.elm:38`: `TriggerRollbar App.Model.IndexedDB (Decoder err)` — commit `c48c4c288` (2023-09) added the `App.Model.ServiceWorker` Rollbar source variant, the `"sw"` path (`App/Update.elm` ~:1574) and the JS `case 'sw'`, then dispatched the wrong variant. SW errors take the offline dbErrors route instead of the immediate md5-deduped sw route. Fix: swap the variant.
- ⚠ **2026-10-12 (checked while choosing a tier-4 quick win): the fix shape is WRONG as written.** The `'sw'` port path dedupes by `md5`, and `App/Update.elm:1575-1581` sends `md5 = ""` for `ServiceWorker`. Swapping the variant alone means the first SW error on a device is the last ever reported; today's `'db'` route reports every one. A real fix also needs an md5 of the message (and the `'sw'` route logs immediately, the B-350 before-init hazard). Not a one-liner.
- ➕ **2026-10-12, from PR #2333's review (finding 4):** SW *registration* failures are never reported to Rollbar at all — only stored in the Elm model and shown on the service worker status. Reporting them would go through the same `'sw'` route, so do it together with the md5 fix above.
