### B-530 — Family Nutrition: the IndexedDB load takes the LOWEST-uuid mother record while every other picker takes the newest, so an encounter holding two live mother MUAC / AHEZA rows can show one value on a fresh load and another after a sync — READY · LOW · tier 4 · CONFIRMED (code + Dexie 3.2.7 ordering; unsized — the feature is live only on tip-somalia, of which there is no local copy) · DEPLOYED (tip-somalia) · R48 unit 4
- **Mechanism.** The per-type vid sort that every other encounter key gets is skipped for the family-nutrition key, yet the decoder still takes the head:
  ```js
  -- client/src/js/nodes.js:578-584
                          data[target][node.type].push(node);
                          if (key !== 'person' && key !== 'family_nutrition_encounter') {
                            // Sorting DESC, so that node with highest vid
                            // is selected first, as it was edited last, and
                            // got most recent data.
                            data[target][node.type].sort((a,b) => (b.vid - a.vid));
  ```
  ```elm
  -- client/src/elm/Backend/Measurement/Decoder.elm:351-357
  decodeFamilyNutritionMeasurements =
      succeed FamilyNutritionMeasurements
          |> optional "aheza_mother" (decodeHead decodeAhezaMother) Nothing
          |> optional "aheza_child" (decodeChildDict decodeAhezaChild) Dict.empty
          |> optional "family_nutrition_muac_mother" (decodeHead decodeFamilyNutritionMuacMother) Nothing
  ```
  Dexie's `anyOf` walks the index cursor and IndexedDB orders equal index keys by primary key, so rows of one encounter arrive by `uuid` ascending → `decodeHead` = `List.head` = lowest uuid, unrelated to recency. The revision path (`AhezaMotherRevision` / `FamilyNutritionMuacMotherRevision`, `Backend/Update.elm:5472-5486`, `:5962-5975`) overwrites the slot in vid order → highest vid; the nightly dedup keeps the highest vid; `decodeChildDict` (`Dict.fromList` on the vendored AssocList, last wins) takes the highest-uuid child row. Four pickers, three rules.
- **Reachability.** `Pages/FamilyNutrition/Encounter/View.elm:457-574` reads `ahezaMother` / `muacMother` for the forms and `Utils.elm:190-193` for completion; the first view loads from IndexedDB, later views from revisions. Needs the `family_nutrition` site feature — on at tip-somalia only (R27 flag snapshot). Two live rows arise from the same upload-retry bursts that produced 2–32 copies of other bundles on ihangane; no `family_nutrition_encounter` measurement exists on the ihangane or vhw copies, and tip-somalia has no local copy, so the live count is unknown.
- **Impact.** Mother MUAC / AHEZA value for an encounter flips between page loads until the dedup runs; the value feeds the Family Nutrition report's MUAC colour.
- **Fix shape (first guess).** Drop `family_nutrition_encounter` from the exclusion so its arrays are vid-sorted like every other encounter key (harmless for the per-child dicts).
