### B-240 — Prenatal recurrent labs: an operator-precedence slip makes a **positive** lab HIV result suppress the HIV follow-up, so "is she enrolled in the HC HIV programme?" is never asked — READY · CONFIRMED (precedence + consumers verified) · MED · tier 3 · R25 unit 2
- **Mechanism.** `Pages/Prenatal/RecurrentActivity/Utils.elm:299-311`, `expectLaboratoryResultFollowUpsTask` / `TaskHIVTest`: `wasFollowUpScheduled TestHIV && (not <| expectLaboratoryResultFollowUpsTask assembled TaskPartnerHIVTest || (hivTest result == TestPositive))`. `<|` is `infixr 0` and `||` is `infixr 2`, so this parses as `not (partnerFollowUpExpected || hivPositive)` = `not partnerFollowUpExpected && not hivPositive`. The comment directly above states the intent — *"So we either do not expect TaskPartnerHIVTest follow up, or, only when test HIV result is positive"* — i.e. `(not partnerFollowUpExpected) || hivPositive`. The `hivPositive` term therefore **suppresses** the task that it was written to force.
- **Reachability.** Lab tech enters HIV result `Positive` in the recurrent Lab Results. `toHIVResultValue` with `isLabTech = True` (`Measurement/Utils.elm:8086-8095`) stores `hivSigns = {PrenatalHIVSignPendingInput}`; `Backend/Update.elm:9128` adds `TestHIV` to `testsWithFollowUp`. The nurse then sees the task nowhere: Lab Results hides it (follow-up was scheduled) and Labs Results Follow Ups drops it because `not (False || True) = False`. Unlike B-239 this does **not** block the encounter — the task simply disappears, and `laboratoryResultFollowUpsTaskCompleted`'s `(not <| taskExpected …) || …` short-circuits to complete.
- **Impact.** The only question that follow-up form asks for a positive result is `HIVProgramHC` (`Measurement/Utils.elm:4245-4263`, verified), and on the nurse's recurrent path it exists nowhere else — the initial-phase form asks it only for point-of-care results. So `hivProgramAtHC` (`Pages/Prenatal/Utils.elm:2955-2960`) stays False for every lab-diagnosed HIV-positive pregnancy, which means (a) `referToARVProgram` (`RecurrentActivity/Utils.elm:724`) is False → the ARV-programme referral is never offered in the recurrent Next Steps, and (b) `resolveHIVPositiveSet` (`Pages/Prenatal/Utils.elm:1801-1812`, `hivDiagnosed && not hivProgramHC`) always prescribes TDF3TC + Dolutegravir, including for a woman already enrolled on an HC programme. All sites. Written in `80fa884d4` (2024-10-11), unchanged since.
- **Fix shape (guess).** Make the expression match its comment: `(not <| expectLaboratoryResultFollowUpsTask assembled TaskPartnerHIVTest) || hivPositive`. ⚠ Confirm the intent with the clinical spec before flipping — it changes which of the two HIV tasks appears in the partner-positive case, and B-239 sits on the other side of that same choice.
