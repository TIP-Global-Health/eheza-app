### B-272 — Well Child vitals: the "previous" respiratory rate and temperature shown beside the inputs are the child's OLDEST readings, not the last visit's — READY · CONFIRMED (anchors + list order verified) · MED-LOW · tier 3 · R26 unit 1
- **Mechanism.** `resolvePreviousValue` (`Pages/WellChild/Activity/Utils.elm:2199-2209`) reads `assembled.previousMeasurementsWithDates`, filters to the measurement, then `List.reverse |> List.head`. That list is built by `Backend.Measurement.Utils.generatePreviousMeasurements` (`Measurement/Utils.elm:10149`, the Well Child assembled-data builder), which ends `|> List.sortWith sortTuplesByDateDesc` — its own comment says *"Most recent date to least recent date"*; `sortByDateDesc` (`Utils/NominalDate.elm:229-231`) compares `entity2` against `entity1`. Reversing a most-recent-first list and taking the head yields the least recent element.
- **The copy-adapted-sibling shape.** Prenatal's `resolvePreviousValue` (`Pages/Prenatal/Activity/Utils.elm:4130-4157`) and Acute Illness's (`Pages/AcuteIllness/Activity/Utils.elm:3187-3196`) use the same `reverse |> head` idiom — but their lists are sorted ASC (`Pages/Prenatal/Encounter/Utils.elm:298` `sortEncounterTuples`; AI's `compareAcuteIllnessEncounters`, ASC), so there it means "latest". Well Child is the one file whose list is DESC, and its other readers of the same list already treat `List.head` as latest (`ageInMonthsAtLastAssessment :1221-1230`, `latestAdministrationDateForMedicine :1427-1440`). The helper is the odd one out.
- **Second-order effect.** The value function returns `Maybe` and the caller does `Maybe.andThen identity` (`:833-838`), so when the OLDEST vitals row has the field null (a CHW ticked "unable to take"), no previous value shows at all even though later visits recorded one.
- **Reachability.** Any Well Child encounter type except Newborn Exam (`expectActivity WellChildDangerSigns` is `/= NewbornExam`) → Danger Signs → Vitals → `View.elm:706-712 viewVitalsForm` → `generateVitalsFormConfig` (`Utils.elm:823-844`) → `respiratoryRatePreviousValue`/`bodyTemperaturePreviousValue` → rendered by `Measurement/View.elm:1494` and `:1555` via `viewPreviousMeasurement`. Traced end to end.
- **Impact.** Every Well Child vitals form for a child with ≥2 prior encounters carrying vitals shows the first-ever reading as "previous" beside respiratory rate and temperature. Display only — the red/yellow alerts read the current input, and nothing saves the previous value — but it is the reference the nurse compares against. All sites, nurse and CHW.
- **Fix shape (guess).** Drop the `List.reverse` (the list is already most-recent-first), or make it order-independent the way `Backend/NutritionEncounter/Utils.elm:538-544 resolveLatestValue` does (sort by date desc, head). One unit test with two dated vitals rows discriminates. Single file, one line — the #2160/#2162 shape.
