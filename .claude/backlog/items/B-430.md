### B-430 — Group sessions (nurse Clinics page): while the health centre is uploading, today's sessions are never fetched, so the group button creates another session on every tap and the day's data splits across sessions — READY · CONFIRMED (orchestrator read the fetch gate, the view gate, the forget loop, the sticky Uploading status, the button default and the revision path; sized live) · MED · tier 2 (⬆ from 3, 2026-09-24) · R36 unit 4 · DEPLOYED (all sites with nurse groups)
- ⬆ **Re-tiered 3 → 2 by the user, 2026-09-24** ("Move all t2 candidates to t2"): 582 same-device duplicate nurse clinic-days on ihangane; split check-ins and measurements.
- **Mechanism.** The page's fetch suppresses `FetchSessionsByClinic` in three sync states, the view hides the page in fewer:
  ```elm
  -- client/src/elm/Pages/Clinics/Fetch.elm:70-78
                                case syncInfo.status of
                                    NotAvailable -> []
                                    Uploading -> []
                                    Downloading -> []
                                    _ -> ... |> List.map Backend.Model.FetchSessionsByClinic
  -- client/src/elm/Pages/Utils.elm:1495-1518 (viewBySyncStatus): only NotAvailable, and Downloading with remainingToDownload > 1500, replace the content
  ```
  With `sessionsByClinic` absent the button defaults to creating a session:
  ```elm
  -- client/src/elm/Pages/Clinics/View.elm:158-190
                    sessions =
                        Dict.get clinicId db.sessionsByClinic
                            |> Maybe.andThen RemoteData.toMaybe
  ...
                            |> Maybe.withDefault
                                [ { startDate = currentDate, endDate = Nothing, clinicId = clinicId, ... }
                                    |> PostSession
  ```
  `PostSession`'s guard only blocks an in-flight double tap (`Backend/Update.elm:4664`). The new session's revision cannot create the missing dict entry (`SessionRevision`, `:7796`, `Dict.update … (Maybe.map …)`), so every later tap posts another. `Uploading` is set on the first batch and cleared only when `remaining == 0` (`SyncManager/Update.elm:1317-1324`, `1386-1400`), and no session page fetches `FetchSessionsByClinic`, so the 5-minute forget loop (`App/Update.elm:1460-1476`, `Backend/Fetch.elm:708`) drops it during the session.
- **Reach.** Nurse runs a group session, works >5 min while saves keep the authority `Uploading` (online with a backlog — the normal busy-session state), taps back to Clinics, taps the group again → session #2, empty Attendance page (`HandlePostedSession`, `:4675-4689`). Offline the status is `Error`, which fetches normally.
- **Impact.** Check-ins, attendance, FBF and group measurements after the split live under a session the nurse never intended; people are checked in twice; dashboard session counts double. Live ihangane (2026-09-22): 1,164 nurse clinic-days (fbf/pmtct/achi/sorwathe) with more than one live session, **582 of them with two or more created by the same device** (256 since 2025-01-01); CHW clinics add 3,240 days (B-330's page). The mechanism is one contributor; two devices at one clinic is another.
- **De-dup.** B-330 is the CHW page (empty fetch); this is the nurse page with a status-gated fetch. B-298 is the measurement double-tap.
- **Fix shape (first guess):** make the fetch gate match the view gate (suppress only where the page is hidden), and/or make the button inert while that clinic's `sessionsByClinic` is not `Success` so a missing fetch is never read as "no session today".
