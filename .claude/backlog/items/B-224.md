### B-224 — NCD progress report: the pregnancy-test row is hidden on every follow-up encounter, so an earlier pregnancy result becomes unreachable from the report — PLAUSIBLE (mechanism orchestrator-read; "intended" not excluded) · LOW · tier 4 · R23 unit 3
- **Mechanism.** `Pages/NCD/ProgressReport/View.elm:218` `pregnancy = expectLaboratoryTask currentDate assembled TaskPregnancyTest`; that is `isPersonAFertileWoman && initialTestRequired TaskPregnancyTest` (`Pages/NCD/Activity/Utils.elm:897-899`), and `initialTestRequired` is False once any previous encounter holds a valid pregnancy result. So from the encounter after the test, `displayConfig.pregnancy = False` and `Pages/Report/View.elm:~1018` hides the row — though `generateLabsResultsPaneData` has collected the result. The history page for pregnancy is reachable only through that row. All other NCD rows are unconditionally `True`; the prenatal sibling sets `pregnancy = False` by design.
- **Judgement.** A stakeholder could argue "show the row only when the test is relevant" — present as a question, not a defect. Fix shape if wanted: gate on `isPersonAFertileWoman` (or "any pregnancy result exists").

- **R31 unit 4 note (2026-09-14).** On develop this is resolved by `cfbfee71b` (B-289): `expectLaboratoryTask TaskPregnancyTest` is now `isPersonAFertileWoman currentDate assembled.person` (`Pages/NCD/Activity/Utils.elm:898-901`) — this entry's own fix shape.
