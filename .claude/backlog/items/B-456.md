### B-456 — Admin reports CSV download: the file has no byte-order mark and always separates with a comma, so Excel can garble accented letters and a semicolon-locale Excel (French, Burundi) puts each row in one column — READY · VERIFIED (code read) · LOW · tier 4 · DEPLOYED, all sites
- **Found 2026-10-07** in the review of #2312 (B-446), round 1, outside that PR's scope.
- **Mechanism.** The port handler writes the CSV as a UTF-8 data URI with no byte-order mark:
```js
-- server/hedley/modules/custom/hedley_general/js/elm.js:39
            element.setAttribute('href', 'data:text/csv;charset=utf-8,' + encodeURIComponent(content));
```
  Excel reads a BOM-less file in the system code page, and splits on the locale's list separator (`;` in French). The admin app ships Kinyarwanda, Kirundi and Somali labels.
- **Impact.** Anyone opening a Statistical Queries / demographics CSV in Excel; LibreOffice asks and is unaffected. Not measured.
- **Fix shape (guess).** Prefix `﻿`; the separator is a product question — ask which spreadsheet and locale Burundi uses before changing it.
