### B-203 — CI never checks that the committed `elm-main.js` matches `server/elm/src` — ✅ IMPLEMENTED 2026-08-19 (issue #2117, PR #2118, MERGED)
**Mechanism.** `server/elm` is compiled by hand and its output committed as `server/hedley/modules/custom/hedley_general/js/elm-main.js`. No CircleCI job, `RoboFile.php` task or gulp task rebuilds it; the pipeline's only `server/elm` reference is `ci-scripts/test_elm_review.sh` (lints source, ignores the bundle). A branch touching `server/elm/src` that merges without a rebuild ships source the deployed app does not run, and CI passes.
**Evidence (2026-08-19).** Observed live on develop: PR #2097 (issue #2096, immunisation) merged at `ce0f93b38`; the bundle's last rebuild was `7c2ad7ade`, one PR earlier. `git show origin/develop:...elm-main.js | grep -c dosesTheSiteExpects` = 0 while the source counted 2 — the scoreboard half of a released fix was absent from the artifact. User rebuilt and pushed `ab3a6e88f`; both develop and `r22-server-components-dedup` now verify byte-identical to a fresh `elm make`.
**Fix shape.** CI job: `cd server/elm && elm make src/Main.elm --output <scratch>` then `cmp` against the committed file; fail on difference. No `--optimize` in the documented build (`server/elm/elm-watch.sh`), so output is deterministic. Full compile of 82 modules ≈ 1.2s — cheaper than any existing job.
