### B-216 — Person: correcting an ADULT's birth date rewrites the enrolment/graduation dates of every child they bring to a group — ✅ IMPLEMENTED 2026-09-24 (issue #2288, PR #2289, branch `B-216-adult-birth-date-enrolment`, base `4072a6bb1`) — CONFIRMED (orchestrator-read hook + helper + stats consumers) · MED-HIGH (server dashboards only) · tier 2 (⬆ from 3, 2026-09-24) · both sites · R23 unit 6
- ⬆ **Re-tiered 3 → 2 by the user, 2026-09-24** ("Move all t2 candidates to t2"): its own severity label is MED-HIGH; it rewrites children's enrolment and graduation dates with no recompute path.
- **Mechanism.** `hedley_person.module:1202-1238` `hedley_person_process_birth_date_update()` — documented as "when child age is edited, updates graduation date" — runs on ANY person whose `field_birth_date` changed. It resolves participations via `hedley_person_pmtct_participants_for_person()` (`:1328-1343`), which associates by **both** `field_person` and `field_adult`, then for each sets `field_expected.value = date('Y-m-d', $birth_date)` and `value2 = birth_date + 26 months` (fbf/pmtct/chw clinics; Sorwathe/ACHI keep value2 but still get the wrong start). No check that `$node` is the `field_person` side. When the edited node is the adult, every participation where they are `field_adult` gets the MOTHER's DOB as the child's enrolment start and mother's DOB + 26 months as graduation.
- **Reachability.** Client edit of an adult exposes the birth-date selector (`Pages/Person/View.elm:~579-600`), encoder sends `birth_date` (`Backend/Person/Encoder.elm:29`) → PATCH → `hedley_person_node_update` → this hook. Also admin node edit.
- **Impact.** Client ignores `PmtctParticipant.start/end` (encoder-only) — no device breakage. Server `hedley_stats` consumes them: `:1502` (`field_expected_value2 > cutoff` filter), `:961/:1143/:1314` (`created` = `field_expected`), graduation stats. A child whose mother's DOB is corrected drops out of group-programme dashboards as "graduated" decades ago with a join date before their birth. Persists — no recompute path; `graduate-participants.php` skips participants whose `value2` is already set. Both sites.
- **Fix shape (first guess):** only process participations where `field_person == $node->nid` (filter the helper's entries by field), so an adult's DOB change is a no-op here. A live count of participations whose `field_expected.value` predates the child's `field_birth_date` would size the existing damage (local ihangane copy: `ddev drush sqlq`).
