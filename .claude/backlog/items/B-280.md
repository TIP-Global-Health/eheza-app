### B-280 — Acute Illness subsequent visit: a diagnosis once written to the encounter is never corrected, even when the RDT or danger signs that produced it are changed — ✅ IMPLEMENTED (issue #2184, PR #2185, 2026-09-01) · was READY · CONFIRMED (both branches + consumers verified) · MED-LOW · tier 3 · R26 unit 4
- **Mechanism.** `generateSuspectedDiagnosisMsgsSubsequentEncounter` (`Backend/Update.elm:9993-10000`): `if data.encounter.diagnosis == NoAcuteIllnessDiagnosis && diagnosisByCurrentEncounterMeasurements /= NoAcuteIllnessDiagnosis then [ updateAcuteIllnessDiagnosisMsg ... ] else []` — first write wins. The first-encounter sibling (`:9881-9899`) compares before/after and also writes `NoAcuteIllnessDiagnosis` back when the resolver returns `Nothing`. On a subsequent visit the only diagnosis the resolver can produce comes from the malaria RDT plus danger signs (`Pages/AcuteIllness/Activity/Utils.elm:2414-2445`), and both inputs stay editable after the write: the Lab task's subsequent gate (`:1997-2016`) filters for a positive in PREVIOUS encounters only (`initialWithSubsequent`), so the current encounter's own positive does not hide it, and Danger Signs can be reopened. New encounters start with `diagnosis = NoAcuteIllnessDiagnosis` (`Backend/AcuteIllnessEncounter/Model.elm:31`).
- **Reachability.** Subsequent visit (CHW or nurse), fever recorded, mandatory activities complete → RDT saved Positive → `MalariaTestingRevision` → `processRevisionAndDiagnoseAcuteIllness` → encounter diagnosis := `DiagnosisMalariaUncomplicated`. The worker corrects the RDT to Negative and saves (Save is gated only on `tasksCompleted == totalTasks`). The revision runs the same path; `setDiagnosisMsg` is `[]`; the stored diagnosis stays Malaria. Variant: a danger sign added after the write → resolver says Complicated, stored stays Uncomplicated.
- **Impact.** The activity page uses `assembled.diagnosis`, which falls back to the previous encounters' diagnosis when the resolver yields `Nothing` (`Pages/AcuteIllness/Encounter/Utils.elm:84-89`), so the post-save popup and Next Steps show the original illness diagnosis — while everything that reads `encounter.diagnosis` shows Malaria: the illness label and the subsequent-visit gate on the Participant page (`Participant/View.elm:338-342`), the diagnosis carried into the NEXT encounter (`Encounter/Utils.elm:185-202`, head of the DESC list, skipping `No`), the progress report assessment pane (`ProgressReport/View.elm:212-259`) and `Pages/Report/View.viewAcuteIllnessDiagnosisEntry`. Both sites. Needs a corrected RDT / added danger sign on a subsequent visit, but the wrong diagnosis then persists for the illness.
- **Fix shape (guess).** Make the subsequent branch mirror the first: write when `data.encounter.diagnosis /= diagnosisByCurrentEncounterMeasurements`, including `NoAcuteIllnessDiagnosis` when the resolver returns `Nothing`. No test pins the write-back rule (TH-16's fixtures cover the resolver only).
