### B-336 — Prenatal recurrent Next Steps: a medication that becomes required AFTER the nurse saved that task is never offered — the "nothing to give" marker keeps the task complete, so the encounter closes without the prescription — ✅ IMPLEMENTED · CONFIRMED (completion rule, form default and the diagnosis timing all read) · MED · tier 1 · issue #2213, PR #2214 · found in the review of PR #2210 (B-323), 2026-09-07
- **Mechanism.** `nextStepsTaskCompleted` (`Pages/Prenatal/RecurrentActivity/Utils.elm`) decides the medication-distribution task is done by asking whether ANY allowed sign was recorded, and the allowed set includes the "nothing to give" marker:
  ```elm
                    if medicationDistributionRequired then
                        let
                            allowedSigns =
                                NoMedicationDistributionSignsRecurrentPhase :: medicationsRecurrentPhase
                        in
                        medicationDistributionMeasurementTaken allowedSigns assembled.measurements
  ```
  and the predicate is a plain membership test (`Pages/Prenatal/Utils.elm`):
  ```elm
  medicationDistributionMeasurementTaken allowedSigns measurements =
      getMeasurementValueFunc measurements.medicationDistribution
          |> Maybe.map
              (\value ->
                  List.any (\sign -> EverySet.member sign value.distributionSigns)
                      allowedSigns
              )
          |> Maybe.withDefault False
  ```
  So a save made while nothing was required writes `NoMedicationDistributionSignsRecurrentPhase` (`toMedicationDistributionValueWithDefaultRecurrentPhase`), and that marker satisfies the completion test for ever after.
- **Reachability.** `expectNextStepsTask NextStepsMedicationDistribution` is True from any of several arms — `diagnosedSyphilisByPhase`, `diagnosedMalariaByPhase`, `diagnosedHypertension`, moderate anemia — independently of whether `resolveRequiredMedicationsSet ... PrenatalEncounterPhaseRecurrent` has anything in it. Nothing orders `LabsResultsFollowUps` before `RecurrentNextSteps`; both are simply offered. So: nurse opens Next Steps first with syphilis already diagnosed and saves (marker written) → a later save adds a diagnosis whose medication is required → the task is still green → `activityCompleted RecurrentNextSteps` True → the recurrent phase completes and the medication row is never shown.
- **Impact.** A prescription the app decided was required is silently not offered, and the encounter closes normally. Not display-only: it is the care pathway for the diagnosis.
- **How it was found.** The B-323 review (PR #2210). B-323 added a guard so the discordant-partnership diagnosis waits for the nurse's follow-up answers instead of firing on the lab technician's save; that made this ordering reachable for TDF3TC/PrEP. ⚠ **Not a regression from B-323** — before it the diagnosis never fired at all — and the same trap already existed for any recurrent diagnosis arriving after a Next Steps save (`Iron`/`FolicAcid` for recurrent moderate anemia is the other named case).
- **Fix shape (guess).** The completion rule is the defect, not the ordering: when `resolveRequiredMedicationsSet` is non-empty, the "nothing to give" marker should not satisfy it — the task should reopen so the nurse is shown the new row. ⚠ Check what a deliberate non-administration records: refusal is captured per medication through `resolveMedicationsNonAdministrationReasons`, not by the empty marker, so excluding the marker should not strand a nurse who declined to give something. ⚠ `nextStepsTaskCompleted` is shared by the malaria / syphilis / hypertension / anemia paths — this needs its own e2e, not a unit test alone.
