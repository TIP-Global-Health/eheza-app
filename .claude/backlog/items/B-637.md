### B-637 — Build / station tooling minors: `ddev client-install` cannot fail; the deploy skills leave the main tree off `develop`; the bookkeeping hook commits everything staged — READY · CONFIRMED as code (orchestrator read all three) · LOW · tier 4 · R65 unit 1 · tooling only, no patient data
- **(a) `ddev client-install` always exits 0.** No `set -e`, and the last command is for a package the client no longer has, so its exit code is what the script returns:
  ```bash
  # .ddev/commands/web/client-install:8-12
  npm install -g bower

  cd ../../client
  npm install --no-audit --no-fund
  bower install
  npm rebuild node-sass
  ```
  `node-sass` is in neither `client/package.json` nor `package-lock.json` (grep, 0 hits). The scout ran `npm rebuild node-sass` in a project without it: exit 0. The command runs from `post-start` (`.ddev/config.local.yaml.example:28-29`), so the `ddev restart` in both deploy skills fires it before `ddev gulp publish`. A failed `npm install` there is silent and publish builds with the old `node_modules`. Fix shape (first guess): `set -e`, drop the rebuild line. Related: B-408 (the same hook rewrites the lock files).
- **(b) Both deploy skills check another branch out in the main tree and never return it.**
  ```
  # .claude/skills/deploy-release/SKILL.md:70
  1. 🟢 You run: `git checkout main && git pull`.
  # .claude/skills/deploy-multidev/SKILL.md:73

  ```
  Neither skill mentions `develop` (grep). While the tree is off `develop`, `commit-bookkeeping.sh:36-39` only warns, and `night-discovery.sh:115-119` launches nothing. The repo rule says the main tree stays on `develop`. Fix shape (first guess): a last step that returns the tree to `develop`, as the e2e procedure has.
