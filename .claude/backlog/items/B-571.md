### B-571 — Completion report (Well Child): the server still counts a child's age in whole months by flooring, while the app since #2490 counts a month-end day that a milestone falls on as reached — so a visit on that day can be charged a "missed" activity the app never offered, or lose one it did — READY · LOW · tier 4 · CONFIRMED (orchestrator ran the PHP date pairs and read both sides on ca8da2a33) · B-178..B-185 completion-family member, opened by #2490 (B-372) · ON RELEASE (#2417; not deployed) · R53 unit 1
- **Mechanism.** #2490 moved every Well Child age gate to `ageInMonthsReached`, which counts the clamped month anniversary as the month reached (born 31 Mar, seen 30 Sep → 6; born 29 Feb 2024, seen 28 Feb 2027 → 36). The Completion builder's twin still floors:
  ```php
  -- server/hedley/modules/custom/hedley_reports/hedley_reports.module:10757-10764 (hedley_reports_resolve_age_for_individual_encounter)
      $interval = $start_date_obj->diff($birth_date_obj);
      ...
        case 'month':
          return ($interval->y * 12) + $interval->m;
  ```
  ```php
  -- hedley_reports.module:5431-5438, 5453-5454 (hedley_reports_well_child_generate_expected_ecd_signs)
    $age_in_months = ($interval->y * 12) + $interval->m;
    ...
      $age_in_months_at_last_assessment = ($interval->y * 12) + $interval->m;
  ```
  `php -r` on the two pairs above gives 5 and 35. The same age feeds MUAC `>= 6` / head circumference `< 36` (`:5297-5303`), the medication age windows (`:6067-6104`), and the ECD groups (`hedley_reports_well_child_generate_grouped_ecd_signs`, `:5506-5535`), whose branch structure is identical to the client's `ecdSigns6To12Months` (`Pages/WellChild/Activity/Utils.elm:1185-1210`) — only the age input differs on a clamp day.
- **Direction.** `hedley_reports_generate_completion_result` (`:10822-10838`) lists every expected activity and marks as completed those with a measurement, so the report shows an expected-but-absent activity as missed. Client expects more than the server (MUAC / Vitamin A / mebendezole lower bounds, a new ECD group reached a month "early"): the extra completed activity is simply not listed — harmless. Server expects what the app did not show: head circumference at 36 months, Vitamin A / mebendezole at 72, albendazole at 144 (whole-year clamps → 29 Feb births seen on 28 Feb), and the ECD 6–12-month group (client at reached 9 offers majors only, server at floored 8 expects minors too; client at reached 12 offers nothing, server at 11 expects majors; a last ECD assessment on a clamp day keeps the 5-/13-week groups on the server and drops them on the client) → a phantom missed activity on that row.
- **Reachability.** Nightly / post-deploy `completion-generate-well-child-data.php` → `hedley_reports_generate_completion_data_for_well_child` (`:4698`, age set at `:4816`); any Well Child visit on the exact clamped anniversary of a 29/30/31 birth day. Both sites. Before #2490 both sides floored and agreed.
- **Impact.** Completion report rows only; the app, the stored measurements and the next-visit date are untouched. Rare: the symptom day itself was 5 of 45,308 pediatric dates on ihangane (B-372), and this needs that day plus an age gate that flips on it. Not sized.
- **Scope note.** The Nutrition and Acute Illness builders' `age_in_months` also floor, but their client gates still floor, so changing the shared helper for them would create the mirror-image gap; only the Well Child consumers moved.
- **Already recorded, distinct.** B-372 (the app side, merged as #2490 — its entry never mentions the PHP twin), B-476 (CHW "unable to take" height/weight charged as missing, same report), B-500 (NCDA scoreboard month rule, different code), B-554 (pediatric visit date never re-derived). Grepped `age_in_months`, `clamp`, `month-end`, `ageInMonthsReached`, "Completion report".
