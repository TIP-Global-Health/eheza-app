### B-323 — Prenatal: a partner HIV result entered by a LAB TECHNICIAN produces no discordant-partnership diagnosis at all, because the match hand-rolls its own execution-note list and omits `TestNoteRunConfirmedByLabTech` — READY · CONFIRMED (run) · MED · tier 1 · split out of B-237's review 2026-09-06
- **Mechanism.** `Pages/Prenatal/Activity/Utils.elm`, `discordantPartnershipByPartnerHIVTest` accepts only three notes:
  ```elm
                                if
                                    (value.executionNote == TestNoteKnownAsPositive)
                                        || (List.member value.executionNote [ TestNoteRunToday, TestNoteRunPreviously ]
                                                && (value.testResult == Just TestPositive)
                                           )
                                then
  ```
  Every other disease diagnosis in the same `case` goes through `testedPositiveAt`, which uses the shared predicate `testPerformedByExecutionNote` (`Measurement/Utils.elm`): `List.member executionNote [ TestNoteRunToday, TestNoteRunPreviously, TestNoteRunConfirmedByLabTech ]`. The discordant-partnership match is the only one with a hand-rolled list, and it is the shared list minus `TestNoteRunConfirmedByLabTech`.
- **Reachability.** `toPartnerHIVResultValue` rewrites the note whenever the lab tech confirms the run: `executionNoteConsideringLabTech = if form.runConfirmedByLabTech == Just True then TestNoteRunConfirmedByLabTech else executionNote`. That confirmation question (`contentAndTasksLaboratoryResultConfirmation`) is rendered only `if isLabTech`, so the note flips exactly when a lab technician enters the result — the ordinary path for a partner test sent to the lab. A nurse entering the same result from the recurrent encounter leaves the note at `TestNoteRunToday`, and the diagnosis fires.
- **Impact.** Neither variant matches, so the encounter carries no Discordant Partnership diagnosis: no TDF3TC/PrEP in either phase, and nothing on the progress report. Silent. ⚠ Strictly worse than B-237, which put the diagnosis in the wrong phase; this drops it entirely.
- **Verified by running** (2026-09-06, in B-237's worktree): a partner test with `executionNote = TestNoteRunConfirmedByLabTech`, `testResult = Just TestPositive`, `hivSigns` not naming `PartnerTakingARV`, plus an immediate negative patient HIV test, yields `(False, False)` for `(Initial, Recurrent)`.
- **Live sizing (ihangane.live, 2026-09-06).** 110 partner HIV tests carry `run-confirmed-by-lab-tech`, of which **0 are positive** — so it has not fired yet, exactly like B-237. The other three sites have no deferred partner tests at all.
- **Fix shape (guess).** Replace the hand-rolled list with the shared predicate — `testPerformedByExecutionNote value.executionNote && value.testResult == Just TestPositive`, keeping the `TestNoteKnownAsPositive` arm beside it. ⚠ Check the `patientHIVNegative` half of the same function, which hand-rolls the same two-note list for the patient's own test and has the same gap.
- ⚠ **Interacts with B-237** (issue #2205, PR #2206): B-237's `resultKnownAtInitialPhase` accepts `TestNoteKnownAsPositive` and `TestNoteRunPreviously`; a lab-tech-confirmed result is correctly *not* initial-phase, so the phase logic needs no further change once this match accepts the note.
- ➕ **Second site, same omission:** `resolvePartnerHIVTestResult` (`Pages/Prenatal/Utils.elm`) hand-rolls the identical three-note list to decide whether the partner's result is known. It drives the HIV tab's *"Is the patients partner HIV positive"* question, which is drawn only while that resolves to `TestIndeterminate` — so after a lab tech confirms a positive partner result, the nurse is still asked to supply the partner's status by hand. Fix both sites together.
- ⭐ **Correction to a claim made while working B-237:** `byHIVTest` is NOT a legacy-only source. `viewHIVTestUniversalForm` still asks *"Is the patients partner HIV positive"* on the patient's own HIV test whenever `resolvePartnerHIVTestResult` is `TestIndeterminate` — i.e. exactly while the partner test is deferred to the lab. The low live count (89 records, latest 2025-11-04) means the answer is rarely Yes, not that the question is gone.
