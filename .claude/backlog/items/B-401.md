### B-401 — Eight e2e backend checks skip the async-write retry every sibling call site uses, so a lagging write fails the test — READY · CONFIRMED (scout enumerated the call sites) · LOW · tier 4 · R34 unit 1 · flake class, false red only
- **Mechanism.** `queryMeasurementNodes(person, types, expectedTypes?)` only retries while `expectedTypes` is supplied, and returns the first successful read otherwise (`client/e2e/helpers/common.ts:168-175`). The suite documents why the wait exists:
  ```ts
  -- client/e2e/helpers/well-child.ts:1068-1070
   * The retry is needed because writes flow through service-worker shardChanges
   * → Advanced Queue → node_save asynchronously after `syncAndWait` reports
   * "Status: Success".
  ```
  Call sites passing **no** expected list: `nutrition-encounter.spec.ts:80` and `:211`; `nutrition-encounter-chw.spec.ts:103` and `:176`; `prenatal-encounter-chw.spec.ts:73` and `:174`; `home-visit.spec.ts:58` and `:90`. Every other family — acute-illness, child-scoreboard, HIV, TB, NCD, well-child — passes the list, and `queryGroupSessionNodes` / `queryFamilyNutritionNodes` hard-code required keys internally.
- **Impact.** False **red**, never false green: a lagging write makes `expect(nodes.height).toBe(70)` fail on `undefined`. Contributes to the flake background that [[B-396]] turns into 25 skipped tests.
- **Fix shape (guess).** Pass the expected type list at all eight sites, as the other six families do.
