### B-379 — E2E harness: `switchUser` in `lab-tech-encounter.spec.ts` flakes — `page.goto('/')` in `pairDevice` is interrupted by the still-running app navigating after its storage is cleared, failing whichever lab-tech test runs it before any clinical step — READY · CONFIRMED (four occurrences read from CI logs and B-338's local run) · LOW · tier 4 (test harness, no app impact) · added 2026-09-16 out of B-344's CI (PR #2253), per B-338's note "worth its own minor if it recurs"
- **Mechanism.** The helper clears the origin's storage through CDP while the Elm app is still open on an activity page, then logs in again; the first navigation of the login is a plain `goto`:
  ```ts
  -- client/e2e/lab-tech-encounter.spec.ts:50-58
  async function switchUser(page: Page, pinCode: string) {
    const client = await page.context().newCDPSession(page);
    await client.send('Storage.clearDataForOrigin', {
      origin: `http://localhost:${getClientPort()}`,
      storageTypes: 'all',
    });
    await client.detach();

    resetDevice();
    await setupDevice(page, pinCode, 'Nyange Health Center');
  }
  -- client/e2e/helpers/auth.ts:45-55 (pairDevice, reached from setupDevice → login)
  export async function pairDevice(page: Page, pairingCode = '99999999') {
    ...
    await page.goto('/');
    await page.evaluate(() => {
      localStorage.clear();
      sessionStorage.clear();
    });
    await page.reload();
  ```
  The app, having lost its stored state, changes its own URL hash (to `#pincode`, or back to the activity route it was on) while `goto('/')` is in flight, and Playwright rejects the `goto` with `Navigation to "http://localhost:3000/" is interrupted by another navigation to ...`.
- **Evidence (CircleCI `e2e_playwright_1`).** Job 30078 on `develop` 2026-09-09 (first lab-tech test); job 30441 on B-343's PR 2026-09-14 (B-336's test — B-343 entry line 33); job 30571 on B-344's PR 2026-09-15 (the blood-smear test, a different test from the one the PR changed; the same test passed on the PR's previous commit); plus B-338's local run 2026-09-09. Each time a re-run passed. Always inside `switchUser`, never in a clinical step.
- **Impact.** A red `e2e_playwright_1` on an unrelated PR, one CI cycle (~15 min) to retrigger, and a real risk of a genuine failure being dismissed as "the flake".
- **Fix shape (guess).** Leave the app before clearing its storage (`page.goto('about:blank')` at the top of `switchUser`), so nothing is running to navigate; or have `pairDevice` retry a `goto` rejected with "interrupted by another navigation". The first is one line and removes the race rather than absorbing it.
- **Recurred 2026-09-17** on PR #2269 (`cb2505cba`, CircleCI job 30859): `lab-tech-encounter.spec.ts:617` failed in `switchUser` with the same interrupted `page.goto('/')`.
