### B-579 — Prenatal (nurse): the Medication activity (calcium, MMS, Fefol / iron / folate, Mebendazole) is listed only at the FIRST nurse visit, so a supplement not yet due or not given then is never offered again — calcium for a first visit before 14 weeks, Mebendazole before 24 — READY · MED-HIGH · tier 2 (prophylaxis gating, not a diagnosis rule — ⚠ user may re-tier) · CONFIRMED (orchestrator read both activity lists and the expectation on e7f1e46e1; scout's scratch elm-test: `expectActivity … Medication = True` with all six tasks while `getAllActivities` does not contain it) · DEPLOYED, both sites, since `050eab283` (2025-06-24) · not sized · R54 unit 2
- **Mechanism.** The expectation was rewritten to "offer each supplement until it has been administered", but the activity list of a subsequent nurse encounter has no `Medication`:

  ```elm
  -- client/src/elm/Pages/Prenatal/Activity/Utils.elm:130-133, 833-859
  ```

  `medicationNeverAdministeredPreviously` scans `nursePreviousEncountersData` — non-empty only on the encounters where the activity is never listed. The encounter page builds both tabs from `getAllActivities |> List.filter expectActivity` (`Encounter/View.elm:370-373`); the mandatory gate and the phase-completed writer use the same list.
- **Spec.** Issue #1508: "Each of this activities appears from the first visit, until it has been distributed" (aspirin: #1512). The server completion builder (`hedley_reports.module:8012-8088`) expects these on every nurse encounter after the change date — so the Completion report charges later visits with activities the app never shows.
- **Impact.** Nurse antenatal care, both sites: no calcium ever for a woman first seen before 14 weeks; Mebendazole only through the older Treatment Review question → Next Steps route; MMS / Fefol / iron / folate not given at visit 1 (out of stock, declined) never offered again. Sizing (not run): `prenatal_calcium` / `prenatal_mms` nodes on non-first nurse encounters ≈ 0.
