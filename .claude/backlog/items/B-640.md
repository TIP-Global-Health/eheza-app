### B-640 — Comment length check: a long comment added to a script without a file extension, or to a `.ts` file, passes CI — READY · CONFIRMED (orchestrator read the tables and ran the checker on 40-word comments) · LOW · tier 4 · R69 unit 1 · tooling only, no patient data, latent
- **What is wrong.** `CLAUDE.md` says CI rejects a comment over 30 words that a PR adds, except in tests. The checker decides how to read a file from its suffix alone, and reads nothing from a file whose suffix is not in its tables:
  ```python
  -- ci-scripts/check_comments.py:108-116
  def syntax(path):
      """The line-comment tokens and block-comment pair a file uses."""
      name = Path(path).name
      if name in BY_NAME:
          return BY_NAME[name], None
      suffix = Path(path).suffix
      if suffix in LINE_COMMENT or suffix in BLOCK_COMMENT:
          return LINE_COMMENT.get(suffix, ()), BLOCK_COMMENT.get(suffix)
      return None, None
  ```
  The tables hold `.css .elm .inc .install .js .module .neon .php .profile .py .scss .sh .theme .twig .yaml .yml`; `BY_NAME` holds only `.gitignore`. There is no `.ts`, and a shell script with no extension has no suffix at all.
- **Files not read (tracked, at adaab7963).** Every script in `.ddev/commands/host` and `.ddev/commands/web` (12), `server/install`, `server/upgrade`, `server/scripts/build`, `server/scripts/reset`, `server/scripts/setup-dev`, `.ddev/web-build/Dockerfile`, and `client/playwright.config.ts` (the only `.ts` outside the exempt `client/e2e/` and `.claude/`). The scout also lists `.example`, `.info`, `.make`, `.SQL` and `.html` files (not recounted).
- **Evidence (orchestrator ran it, in memory, nothing written).** `blocks_of` on a 40-word `#` comment returns no block for `server/scripts/build` and `.ddev/commands/web/simpletest`, and one 40-word block for `x/y.sh`. A 40-word `//` comment returns no block for `client/playwright.config.ts`, and one for `x/y.js`.
- **Reachability.** The `lint_comments` job runs the checker on every pushed branch (`.circleci/config.yml:44-50`). A PR that adds a long comment to any file above goes green.
- **Impact.** Developers only; the rule is not enforced where it says it is. The scout found no PR that has used the gap: the over-budget comments in those files predate the lint (scout's dating, not rechecked).
- **Not filed with it (scout demonstrated, contrived).** A comment trailing code on the same line is never measured. False rejects when touched: `#` lines inside a shell heredoc, `--` lines inside an Elm `"""` string, YAML front matter in a `.md` outside `.claude/`.
- **Fix shape (guess).** Add `.ts` to both tables; for a file with no suffix read the shebang line, or list the names in `BY_NAME` (`Dockerfile` too). Add a test per new entry to `ci-scripts/tests/test_check_comments.py`.
