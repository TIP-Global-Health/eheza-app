### B-523 — Sync download: `HealthCenterRevision` ignores `deleted`, so a health centre soft-deleted on the server is re-inserted into the device's in-memory list until the next reload — READY · LOW · tier 4 · CONFIRMED (code; 1 deleted `health_center` on ihangane, 0 on vhw) · DEPLOYED · R47 unit 3
- **Mechanism.**
  ```elm
  -- client/src/elm/Backend/Update.elm:6051-6058
          HealthCenterRevision uuid data ->
              let
                  healthCenters =
                      RemoteData.map (Dict.insert uuid data) model.healthCenters
  ```
  `health_center` carries `field_deleted` and the decoder reads it strictly (`Backend/HealthCenter/Decoder.elm:14` `required "deleted" bool`), but the revision branch inserts regardless, unlike `encounterActionConsideringDeletedField` (`:5258-5262`). The IndexedDB load path filters deleted rows, so the stale entry lives only until the app reloads.
- **Impact.** The HC appears in the PIN-page location picker (`Pages/PinCode/View.elm:530` reads `db.healthCenters`), the Device page and the sync view for the rest of the session; a nurse could select it and sync its authority. Rare: one deleted health centre on ihangane, none on vhw. `ClinicRevision` (`:5771`) and `ResilienceSurveyRevision` (`:7754`) share the shape but those bundles have no `field_deleted`, so the server always sends `false`. `StockUpdateRevision` (`:7856-7879`) also inserts regardless into `model.stockUpdates`, which nothing reads (starts `NotAsked`, so the `RemoteData.map` is a no-op) — dead, not a defect.
- **Fix shape (first guess).** Route the branch through the deleted-aware insert/remove helper. Sibling of B-522; fix together.
