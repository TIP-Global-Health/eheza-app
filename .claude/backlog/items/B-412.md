### B-412 — Three exported field instances permit a shape the client decoder or the sync query cannot survive — the same poison-record class as B-108/B-388, latent on all four sites today — READY · CONFIRMED (orchestrator read all three configs and their consumers, and counted live rows) · LOW · tier 4 · R34 unit 5 · latent
- **(a) `participant_form.body` — optional server-side, `required` in the decoder, on the ALL-DEVICES lane.**
  ```php
  -- server/hedley/modules/custom/hedley_forms/hedley_forms.features.field_instance.inc:440-442
      'field_name' => 'body',
      'label' => 'Body',
      'required' => FALSE,
  ```
  ```elm
  -- client/src/elm/Backend/ParticipantConsent/Decoder.elm:38-40
      map2 go
          (field "body" string)
          (field "kinyarwanda_body" (nullable string))
  ```
  `kinyarwanda_body` and `kinyarwanda_title` are `nullable`; `body` is not. `HedleyRestfulParticipantsForm` left-joins the field, so a body-less node emits `null`. `participant_form` is in `HEDLEY_RESTFUL_ALL_DEVICES` (`hedley_restful.module:23`), so **one body-less form fails the general download batch for every device on the site** — not one health centre.
  **Live counts (orchestrator, 2026-09-21):** ihangane 2 forms, 0 with a null body; vhw, tip-somalia and uvl have **no `participant_form` nodes at all**. The only programmatic creator is the `forms` migration, which deliberately omits the child when the XML body is blank; the remaining door is an administrator using the node form with Body empty. ⚠ The *consumer* (`participant_consent`) is dead ([[obsolete-participant-consent-and-trace-contacts]]), but the **form** still rides sync and is still decoded, so that deadness does not protect this.
- **(b) `individual_participant.field_expected` is `required => 0`** (`hedley_schedule.features.field_instance.inc:1818, 1846-1848`) while the client has `|> requiredAt [ "expected", "value" ] decodeYYYYMMDD` (`Backend/IndividualEncounterParticipant/Decoder.elm:15`) and the REST plugin emits `'value' => $value1 ? … : NULL`. The sibling `pmtct_participant.field_expected` is `required => 1`.
- **(c) `acute_illness_encounter.field_individual_participant` is `required => 0`** (`hedley_schedule.features.field_instance.inc:135, 161`), against `required => 1` on `home_visit`, `ncd`, `nutrition` and `prenatal` in the very same file and on `tuberculosis`, `child_scoreboard` and `well_child` elsewhere — only `hiv_encounter` shares the 0. `HedleyRestfulIndividualEncounter::alterQueryForViewWithDbSelect` joins the participant uuid with an **inner** join, so such an encounter would be silently absent from every sync batch forever (B-045's class, which does not list this join), and `hedley_device_assign_shards` would throw on it (`$wrapper->field_individual_participant->field_person->getIdentifier()` on an unset reference).
- **Impact.** None today — this is "the config permits a shape the code cannot survive", not "this is happening". (a) is the one with teeth if it ever fires, because it stops sync for a whole site.
- **Fix shape (guess).** For (a), make the decoder tolerate a null body as it already does the Kinyarwanda one — the decoder side is safer, since a stored null cannot be fixed by config. For (b) and (c), align the instances with their siblings (`required => 1`); optionally make the participant-uuid join a left join so an orphan degrades rather than disappears.
