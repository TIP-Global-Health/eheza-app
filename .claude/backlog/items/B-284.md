### B-284 — TB and HIV "not diagnosed": the participant is closed but the encounter is never ended, so every screening that finds no disease leaves a permanently open encounter the Completion report counts as incomplete — READY · CONFIRMED (client path + both server generators verified) · LOW · tier 4 · R26 unit 8 · ⚠ joins the gated Completion-report batch (B-179…B-187, B-246: "is the Completion report used?")
- **Mechanism.** `Pages/Tuberculosis/Activity/Update.elm:116-122` and `Pages/HIV/Activity/Update.elm:215-225` emit `CloseTuberculosisSession TuberculosisOutcomeNotDiagnosed` / `CloseHIVSession HIVOutcomeNotDiagnosed` + `SetActivePage PinCodePage`. `Backend/IndividualEncounterParticipant/Update.elm:49-75` sets the participant's `endDate`/`outcome`; nothing writes the encounter's `endDate` — its only writer is `CloseTuberculosisEncounter` (`Backend/TuberculosisEncounter/Update.elm:26-37`), reached only from End Encounter. The client could not end it on this path anyway: `Medication` is always expected (`expectMedicationTask TaskPrescribedMedication = True`, `Tuberculosis/Activity/Utils.elm:103-104`; HIV `:100-101`), so a not-diagnosed encounter can never reach "no pending activities".
- **Consumer.** `hedley_reports.module:7506-7519` (TB) / `:7355-7365` (HIV) always expect `*_medication`, and the encounter queries (`:7460`, `:7309`) have no end-date condition, so every not-diagnosed encounter is reported incomplete for good. Client side is harmless: the closed participant is filtered out (`Participant/View.elm:100-104`) and a new one is minted next time, orphaning the open encounter.
- **Impact.** Both sites, nurse. Report accuracy only (plus one orphaned open encounter per negative screening).
- **Fix shape (guess).** Also send `CloseTuberculosisEncounter`/`CloseHIVEncounter` on that path, and/or teach the completion generators that a `not diagnosed` diagnostics measurement completes the encounter. Needs the batch's gate answered first: what should the report say about a negative screening?
