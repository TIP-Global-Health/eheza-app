### B-297 — Group sessions: nothing has closed a session since mid-2023 — the close flow was removed but the closed-session guard remains, so any past session reopened from browser history is fully editable — READY · CONFIRMED (no dialog producer; census run) · LOW · tier 4 · R27 unit 4 · ⚠ half product-question: is an explicit close wanted back, or auto-close by date?
- **Mechanism.** The only producers of `Backend.Session.Model.CloseSession` are the end-session dialogs in `Pages/Participants/Update.elm:12-18` and `Pages/Activities/Update.elm:17-23` — and those dialogs can no longer open: `ShowEndSessionDialog True` / `SetDialogState (Just DialogEndSession)` are dispatched NOWHERE (repo-wide grep, only the cancel sides exist); the "End Group Encounter" button is now `SetRedirectPage <| UserPage ClinicalPage` in both views (`Pages/Participants/View.elm:144`, `Pages/Activities/View.elm:141`; swapped deliberately by `15b1710d6`, 2023-06-01). The whole close path — the `endDate` patch (`Backend/Session/Update.elm:23-35`), `isClosed`'s `pastEnd` branch, `viewClosedSession` (`Pages/Session/View.elm:211`) — is dead, and the server has no substitute (nothing sets `field_scheduled_date` `value2`).
