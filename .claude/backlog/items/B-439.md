### B-439 — Acute illness contact tracing: the "register contact" form shows a stale backend error from an earlier person save — READY · VERIFIED (orchestrator read reader, writers, resets) · LOW · tier 4
- **Found R37 unit 4** (as-merged read of [[B-259]] / [[B-222]], PR #2269).
- **Mechanism.** `viewCreateContactForm` (`Pages/AcuteIllness/Activity/View.elm:2050`) reads the app-wide `db.postPerson` and shows `Failure` as "Backend error". `ResetPostPersonRequest` is sent only on entry to `CreatePersonPage` / `EditPersonPage` (`App/Update.elm:1212-1227`), not when the contact form opens. Since #2269 a failed edit PATCH stores its real result:
```elm
-- client/src/elm/Backend/Update.elm:4663
                            ( { model | postPerson = RemoteData.map (always personId) data }
```
  So a failed person edit, like a failed create before it, leaves `Failure` behind, and it shows on the next register-contact form until the nurse submits.
- **Impact.** Cosmetic and rare: person PATCHes go to the local service-worker store, so they seldom fail.
- **Fix shape (guess).** Send `ResetPostPersonRequest` when `ContactsTracingFormRegisterContact` is entered.
