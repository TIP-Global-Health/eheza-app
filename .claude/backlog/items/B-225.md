### B-225 — Sync report-state: the "only save when changed" guard never passes, so every sync cycle rewrites the device user twice — READY · CONFIRMED (run locally) · LOW-MED · tier 4 · R24 unit 1
- **Mechanism.** `hedley_restful/plugins/restful/node/report/HedleyRestfulReportState.class.php:71-88` compares stored vs posted state with `!==` before `$wrapper->save()`. Two of the four legs compare different types and are always true: `field_total_to_upload->value()` is the DB string `"0"` vs the JSON int `0`; `field_health_centers->value()` is a list of loaded node OBJECTS vs `$synced_authorities`, a sorted list of nids from `hedley_restful_resolve_nids_for_uuids()` (:68). So the guard is dead and `user_save()` runs on every call.
- **Reachability.** The PWA posts `/api/report-state` at sync start AND sync end of every cycle (`SyncManager/Update.elm:892-919`, from `IndexDbQueryGetTotalEntriesToUploadResult`). Every paired device, all sites; code identical on Pantheon `origin/master`.
- **Impact.** Two full `user_save()` writes per device per sync cycle (users row + all user field tables + entity-cache clear) instead of only on change. `hedley_user_user_presave()` (`hedley_user.module:70`) also runs each time — it only does work while `field_incident_details` is non-empty (it clears the field at :291 on success), so the presave tail is bounded. Stored values are correct; this is load and write-amplification, not data corruption. Not measured on live.
- **Evidence.** `ddev drush php-eval` on the local DB: `field_total_to_upload->value()` → `string(1) "0"`; `field_health_centers->value()` → `[object]`; `->value(['identifier'=>TRUE])` → `["4"]`. Client encoder sends `int` + `list string` (`SyncManager/Encoder.elm:197-203`).
- **Fix shape (guess).** Cast `total_to_upload` to int on both sides and read `field_health_centers->value(['identifier' => TRUE])` (ints, sorted) — the idiom `hedley_reports_resolve_scope_for_reports_by_current_user()` already uses.
- 📌 Unit-1 coverage notes worth keeping: `/api/me` and `/api/users` have NO live caller (only `Restful/Login.elm`, which nothing imports); `/api/reports-data` gates on the `administrator` ROLE while its page gates on role-or-uid-1 (uid 1 gets the role at install, so not a defect); every sync bundle also exposes a plain authenticated `GET /api/<bundle>` list endpoint the PWA never calls (sharding bypass by token — security class, declined).
