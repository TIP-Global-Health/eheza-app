### B-653 — Prenatal lab results (nurse): a hospital referral answer saved at lab results for one diagnosis also completes the Referral task for a diagnosis found by a later result, so the nurse is not asked about it — READY · LOW · tier 3 (⚠ care pathway, same tier and same open tier-1 question as B-582) · CONFIRMED by reading (scout read; orchestrator read the completion rule, the expectation rule, the phase helpers and the activity list on 4d110cbd4 — nothing run) · DEPLOYED, both sites · present before PR #2594, which does not cover it · not sized · R74 unit 2
- **Mechanism.** The lab-results Referral task is complete when the hospital is answered and the answer was not given at the exam. It does not look at which diagnoses the answer was given for:
  ```elm
  -- client/src/elm/Pages/Prenatal/RecurrentActivity/Utils.elm:683-697
  nextStepsTaskCompleted currentDate assembled task =
      case task of
          NextStepsSendToHC ->
              let
                  hospitalAnsweredAtExam =
                      getMeasurementValueFunc assembled.measurements.sendToHC
                          |> hospitalReferralAnsweredAtExam
              in
              resolveRequiredReferralFacilities assembled
                  |> List.all
                      (\facility ->
                          referralToFacilityCompleted assembled facility
                              && not (facility == FacilityHospital && hospitalAnsweredAtExam)
                      )
  ```
  Once a lab-results save stamps the record `recurrent`, the task stays complete whatever diagnoses later results add.
- **Reachability.** The task is expected as soon as one lab-found hospital diagnosis exists; it does not wait for the remaining results. Only Health Education has that wait:
  ```elm
  -- client/src/elm/Pages/Prenatal/RecurrentActivity/Utils.elm:644-648, 660-664
          NextStepsSendToHC ->
              resolveRequiredReferralFacilities assembled
                  |> List.isEmpty
                  |> not
          ...
          NextStepsHealthEducation ->
              -- Emergency referral is not required.
              (not <| emergencyReferralRequired assembled)
                  && diagnosisSourcesCompleted currentDate isLabTech assembled
  ```
  `RecurrentNextSteps` is an ordinary entry in the activity list (`RecurrentEncounter/Utils.elm:12`), with no gate on the other activities.
- **Scenario.** Labs sent at the exam. A positive Hepatitis B result is entered from Case Management › ANC Labs; the nurse opens Next Steps › Referral and saves "No, client refused". Days later the blood group result (Rh-negative) or a blood sugar result (diabetes) is entered on the same encounter. Next Steps reads completed; the stored refusal stands for the new diagnosis, and the form opens pre-filled with it.
- **Impact.** Same outcome as B-582, inside the lab-results part. Expected population smaller than B-582's 3 of 426 on ihangane; a stored "referred" is harmless, a stored refusal is not. Not sized.
- **Already recorded, distinct.** B-582 (the exam's answer standing for a lab-found diagnosis — fixed by #2594), B-652 (hospital question pre-filled No when the exam answered another place), B-592 (No→Yes keeps the reason), B-345 (the Health Education twin, fixed with the wait above). Grepped `referralToFacilityCompleted`, `NextStepsSendToHC`, `hospitalReferralPhase`, `diagnosisSourcesCompleted`, "later result".
- **Fix shape (first guess).** The wait Health Education already has (`diagnosisSourcesCompleted`), or completion keyed on the diagnoses the answer was saved against. Size first: lab-results referral records saved before a later hospital diagnosis appeared on the same encounter (B-582's query, with the stamp or revision order turned around).
