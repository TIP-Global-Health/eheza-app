### B-050 — Background catch-up sync (>45s) force-reloads the page mid-workflow, discarding a nurse's in-progress form entries — ✅ IMPLEMENTED 2026-07-16 (issue #1955, PR #1956, branch `b050-gate-sync-page-refresh`, base develop @15275c54f, commit a61e371b1, Copilot requested). **3-iteration design (high review drove it):** (A) defer-retry re-scheduling SchedulePageRefresh — REJECTED by high review: SyncManager has ONE last-write-wins debouncer (Debouncer.Basic `manual`/`lastInput`, Model.elm:430 debounce 15000) shared by RefreshPage + TryDownloadingPhotos, so a photo schedule in the 15s window CLOBBERS the deferred reload → never fires; also an all-session 15s wakeup loop = battery drain. (B) gate-at-dispatch — 2nd high review found the 15s window gap (gated when scheduled but fires 15s later without re-check → nurse navigating INTO a form during the window still reloaded). (C) FINAL = gate at the FIRE site (RefreshPage handler): reload only if `pageAllowsBackgroundRefresh activePage` (any UserPage → skip), else `noChange` (skip, NOT re-schedule → no loop, no debouncer touch). New pure predicate `SyncManager.Utils.pageAllowsBackgroundRefresh : Page -> Bool` (exposed+tested, 3 cases). Skipping is SAFE: high review REFUTED 'reload is the only mechanism' — reactive fetch (CheckDataWanted) surfaces synced data. Photos decoupled (own timer, commit 0d758f49b). elm make 548, elm-test 2833, elm-format+elm-review clean.

- `SyncManager/Update.elm:461-465`: when a cycle's authority-download phase exceeds 45s, dispatches `SchedulePageRefresh` → debounced 15s (`Model.elm:430`) → `RefreshPage` → `refreshPage()` port → `app.js` `location.reload()`. NO `activePage` gating (only the two photo-capture pages pause sync via `determineSyncStatus`; the reload fires on any page). In-progress form state lives in the in-memory LoggedInModel page dicts and does not survive reload. Trigger: device offline over a weekend (or authority just re-added → full re-download), nurse logs in immediately and starts a form while catch-up runs >45s → silent reload wipes unsaved fields.
- Fix: gate `SchedulePageRefresh` on `activePage ∈ {PinCodePage, DevicePage}` (or `loggedIn /= Success`); defer until a safe screen. Severity MED-LOW (data-entry loss, no corruption; correlates with post-offline resumption).
