### B-510 — Sync incidents: a user's incident details naming only entities that already exist are never cleared, by the live save path or by the post-deploy script — READY · LOW · tier 4 · CONFIRMED (code + vhw post-deploy copy, 2026-10-26) · DEPLOYED (v1.18.3, all sites)
- **Mechanism.** `hedley_user_user_presave()` skips an entry whose UUID resolves and counts it neither as created nor as failed, so when every entry exists `$created_any` stays FALSE and the details are left as they were:

  ```php
  -- server/hedley/modules/custom/hedley_user/hedley_user.module:109-131 (origin/main f851e440d)
      foreach ($pending as $data) {
        if (hedley_restful_resolve_nid_for_uuid($data->uuid) !== FALSE) {
          // The entity exists on the backend already.
          continue;
        }
        ...
    if (!$created_any) {
      return;
    }
  ```

  `recreate-sync-incident-entities.php:67-71` likewise `continue`s a user whose `$missing_uuids` is empty, so the script neither saves the user nor reports the leftover (PR #2373 promised a watchdog reason for anything left behind).
- **Live instance (vhw, post-deploy copy 2026-10-26).** uid 80 still holds a 467-byte `field_incident_details` naming `danger_signs` `e6fd4517-…`, which is nid 81074 on both copies (the incident was a failed PATCH carrying `vid` 123636; the node's current values equal the payload, so nothing was lost). uid 189's details, which named a missing entity, were cleared by the script run at 09:35:38 UTC. ihangane (post copy): three users keep details the script could not clear — uid 700 (2024 bare-object format, both named entities absent), uids 3648 and 3704 (sessions that already exist) — the same class.
- **Impact.** Admin-facing: the user's edit page keeps showing a resolved incident and the script's summary cannot count it; no patient data effect.
- **Fix shape (first guess).** Treat "already exists" as resolved in both places: drop it from the details in the hook (set `$created_any`-equivalent progress) and count it in the script's summary. Not a repair script.
