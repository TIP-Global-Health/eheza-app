### B-563 — Group session: a child whose page or activity row was shown more than five minutes ago is dropped from the open session — gone from the mother's list, the participants list and every activity list until a reload — on the next group-measurement save or download — READY · MED · tier 3 by reading · CONFIRMED (code, every link read on 3778065f9) · ⚠ NOT reproduced in a browser; the child-page route is DEPLOYED and years old, so a reproduction is the first step · broadened by PR #2465 (B-548, release #2417) to every child shown on an activity page · R51 unit 3
- **Mechanism.** The session page fetch returns the shown child's individual data set as ordinary top-level fetch msgs:

  `CheckDataWanted` (every 50 ms after any msg; `Tick` every 10 s keeps it alive) stamps each returned msg and forgets any msg not wanted for five minutes:
  ```elm
  -- client/src/elm/App/Update.elm:1459-1472
  ```


  Once the child is no longer the shown one, nothing re-wants those keys: `fetchEditableSession` re-requests only keys still present as `NotAsked` (`Backend/Session/Fetch.elm:16-35`, `getIds`), and the only seeder of those keys, `HandleFetchedExpectedParticipants` (`Backend/Update.elm:475-516`), never re-fires while `expectedParticipants` is `Success`. Every editable session is rebuilt on a group-measurement revision from either origin — a download (`processRevisions`, `Backend/Update.elm:2512-2535`, `WeightRevision` and siblings return the recalc flag `:8168-8174`) and a local save of one height / weight / MUAC / nutrition-signs record (`processRevisionAndAssessNutritionGroup`, `:2089-2135`, dispatched at `:2898-2961`) — and the rebuild drops a child whose key is gone:
  ```elm

                          Dict.keys participants.byChildId

                                      Dict.get id db.people
  ```

  `offlineSession.children` feeds `getChildren` / `getChild` (`Backend/Session/Utils.elm:17-30`), the participants summary and every activity list; `calculateOfflineSessionMeasurements` (`:10220-10230`) keeps only `Success` measurement sets, so the child's saved group measurements leave the session view as well.
- **Reachability.** Nurse or CHW in an open group session: (a) participant-first — open child A's page, go back, work on other children for more than five minutes, save any group measurement → A vanishes from the mother's children and the participants list; (b) after #2465, activity-first — any child shown on an activity page (the row the page loads for) counts the same way. A reload re-seeds everything from IndexedDB; nothing is lost on disk.
- **Impact / size.** Every site running group sessions. The child cannot be measured again in that session until a reload; attendance and summaries miss them meanwhile. ⚠ The exposure is old (per-child fetch on the child page since before 2021-06, the forget loop since 2019-05 `f985c3c4d`), which argues for an unseen masking factor — reproduce before building: open a session, view child A's page, go back, wait five minutes (the forget window is wall-clock), save a weight for child B, check whether A is still listed under the mother and on the participants page. Count not measurable server-side (device-local state).
- **Already recorded, distinct.** B-548 / B-329 are the fetch gap this PR closed; B-299 / B-300 / B-330 / B-430 use the forget loop only as a refetch mechanism; no item records a dropped session child (grepped `dataWanted`, `App.Fetch.forget`, `offlineSession.children`, "vanish", "disappear").
- **Fix shape (first guess).** Keep a session's children out of the forget while the session itself is wanted (have `fetchEditableSession` re-want `FetchPerson` / `FetchChildMeasurements` for every expected child, or make `forget` skip keys referenced by a `Success` editable session); or make `makeEditableSession` treat a missing key as `NotAsked` so the next cycle refetches instead of dropping. Decide after the reproduction.
