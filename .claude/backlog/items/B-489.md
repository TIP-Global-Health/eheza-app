### B-489 — WhatsApp send script: a record with no phone number, screenshot or template is skipped on every run and never retired — READY · CONFIRMED (orchestrator read the three `continue` branches and the base query) · LOW · tier 4
- **Found 2026-10-15** in review round 1 of B-347's fix (PR #2361). Predates that PR.
- **Mechanism.** The three give-up branches print and `continue` without setting `field_date_concluded` or adding to `field_delivery_attempts`, so the record matches the base query (`dc` NULL, attempts `< 5`) again on every run:
  ```php
  // server/hedley/modules/custom/hedley_whatsapp/scripts/send-messages.php
      $phone_number = $wrapper->field_phone_number->value();
      if (empty($phone_number)) {
        drush_print("Failed to pull destination number for node ID $node->nid. Giving up on it.");
        continue;
      }
  ```
  Same for an empty screenshot fid and an empty template SID.
- **Impact.** Unmeasured. Each such record prints every 5 minutes forever and takes a slot in the batch count; nothing is delivered either way. Its screenshot is never swept by `delete-processed.php` (needs concluded or attempts ≥ 5).
- **Fix shape (guess).** Set attempts to the cap in each give-up branch, so `delete-processed.php` sweeps it.
