- **Found R37 unit 3** (form-fix cluster as merged, @e747d3eaf). Same shape as [[B-421]]: a field the handler should clear is filled back in by `or` from the saved record.
- **Mechanism.** None of the three known-as-positive updates (Partner HIV `knownAsPositiveUpdatePartnerHIVTest`, `Measurement/Utils.elm:6740-6758`; own HIV; Hepatitis B) clears `immediateResult`, and it has no dirty flag. Hydration refills it:
```elm
-- client/src/elm/Measurement/Utils.elm:2509-2512 (same at ~2592 HIV universal, ~3150 Hepatitis B)
            { knownAsPositive = or form.knownAsPositive (Just knownAsPositiveValue)
            ...

```
  So `toPartnerHIVTestValue` saves `testPrerequisites = testPrerequisitesByImmediateResult (Just False)` = `{NoTestPrerequisites}` beside `executionNote = TestNoteKnownAsPositive`. The reader looks only at the prerequisites:
```elm
-- client/src/elm/Measurement/Utils.elm:8877-8883
expectUniversalTestResultTask value =
    ...
    Maybe.map (EverySet.member PrerequisiteImmediateResult >> not) value.testPrerequisites
        |> Maybe.withDefault False
```
- **Consequence 1 (phase, PrEP).** `Pages/Prenatal/Activity/Utils.elm:2764-2784` `resultKnownAtInitialPhase = ... expectUniversalTestResultTask >> not`, even though its own comment says a partner known as positive "needed no lab at all". The corrected record reads as "result still expected", so the Initial arm fails and `DiagnosisDiscordantPartnershipRecurrentPhase` is stored at the initial encounter. The initial phase's medication list offers PrEP only for the Initial variant (`Pages/Prenatal/Utils.elm:1979` `resolveDiscordantPartnershipSet DiagnosisDiscordantPartnershipInitialPhase`). An HIV-negative pregnant woman whose partner is known positive and not on ARVs gets no TDF+3TC task at that visit. If no other lab is pending, no recurrent phase opens to carry it.
  - ⚠ **Regression.** `origin/main` (v1.18.2) has `DiagnosisDiscordantPartnershipInitialPhase -> discordantPartnershipDiagnosed && immediateResult .hivTest`, which files the Initial variant correctly when her own test was immediate. The prerequisite-based helper came in with B-237's `e1ca33e80` (2026-09-06, merged, not deployed). B-237's recorded final shape had instead used `immediateResult || executionNote ∈ [TestNoteKnownAsPositive, TestNoteRunPreviously]`, which would have handled this record.
- **Consequence 2 (result task that can never be completed; not dependent on the regression).** `expectLaboratoryResultTask` (`Pages/Prenatal/RecurrentActivity/Utils.elm:199-219`) expects a result for HIV / Partner HIV / Hepatitis B. `testResultsCompleted` (`:144-150`) needs a performed note plus a result, or a why-not note, and `TestNoteKnownAsPositive` is neither. So at the recurrent phase LabResults never completes, End Encounter never appears, and `generatePrenatalRecurrentPhaseCompletedMsgs` (`Backend/Update.elm:~9234`) never fires. A lab tech is shown a result form for a test nobody ran.
