### B-604 — Registration: the duplicate national-ID warning is lost when any person record arrives by sync between typing the ID and Save (or Save is tapped while the lookup is still loading) — the duplicate is registered with no dialog — READY · CONFIRMED by reading (orchestrator read the Submit branch, the single trigger, and the cache clear; not run, not sized) · LOW-MED · tier 3 ⚠ tier is a judgement, scout said LOW · DEPLOYED, Rwanda mainly · R56 unit 3
- **Mechanism.** The lookup is issued once, on the keystroke; Save only reads the cache; every person revision empties that cache; nothing on the create page re-requests it.
  ```elm
  -- client/src/elm/Pages/Person/Update.elm:142-148
                        Form.Input _ _ (Form.Field.String value) ->
                            if String.length value > 13 then
                                ( [ Backend.Model.FetchPeopleByNationalId value
                                        |> App.Model.MsgIndexedDb
                                  ]
                                , []
                                )

  -- client/src/elm/Pages/Person/Update.elm:71-76 (Submit, CreatePerson)
                                                        Dict.get nationalId db.personSearchesByNationalId
                                                            |> Maybe.andThen RemoteData.toMaybe
                                                            |> Maybe.andThen (Dict.values >> List.head)
  -- ... `Nothing` falls through to PostPerson

  -- client/src/elm/Backend/Update.elm:7133-7144
        PersonRevision uuid data ->
            ...
            ( { model
                | personSearchesByName = Dict.empty
                , personSearchesByNationalId = Dict.empty
                , people = people
              }
  ```
  `FetchPeopleByNationalId` has two issuers (`Pages/Person/Update.elm:144`, `Components/PatientsSearchForm/Fetch.elm:24`); `fetchForCreateOrEdit` is not one. A `PersonRevision` is produced for every downloaded person.
- **Reachability.** Nurse types the ID, keeps filling the form, a sync download delivers any person from another device, nurse taps Save → `Dict.get` is `Nothing` → `PostPerson`, no dialog.
- **Impact.** A duplicate patient registered without the only warning the form has, on devices that download while registering (multi-device health centres). Rwanda mainly — B-257 records why the lookup rarely fires elsewhere. Not sized.
- **Corrects B-257**: the result is not cached "forever"; it is cleared on every person revision.
- **Fix shape (guess).** Do the lookup at Save and wait for it, or keep the form's current ID wanted from the page's fetch list so the cache refills.
