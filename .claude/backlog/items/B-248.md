### B-248 — Stats simpletest: three scenarios — including the B-032 and B-033 soft-delete regression tests — have exited early without running since 2020, and CI reports them green — READY · CONFIRMED (request shape, gate, and dead assertion all verified) · MED · tier 3 · R25 unit 8
- **Mechanism.** `HedleyStatsCalculation.test:222-243` builds `$request = ['base_revision' => 0, 'db_version' => …]` and calls `$handler->get($uuid, $request)`. The statistics payload is produced **only** when the request carries a `statistics` key — `HedleyRestfulSync.class.php:223`, `if (isset($request['statistics'])) { return self::getForHealthCenterStatistics($uuid); }` (verified) — and RESTful's `process()` passes the request through verbatim. So the call falls to the ordinary entity path, whose batch items are stdClass objects, `end($results['batch'])` is not an array, and the bare `return` at `:243` exits the whole test method.
- **Everything after that line is dead:** scenario 4 (stats blob + cache-hash invalidation), **scenario 5 = B-032** (soft-deleted measurements excluded, `:321-351`), **scenario 6 = B-033** (soft-deleted education participants, `:353-382`).
- **Two independent proofs it has never run.** (1) `:253` asserts `assertFalse(empty($stats['good_nutrition']))`, and I grepped the whole repo: `good_nutrition` appears **nowhere else** — not in any payload builder. If scenario 4 executed, that assertion would fail on every CI run. (2) The guard's comment says *"the above test will fail"*, but there is **no assertion above it** — `831c12c0a` (2020-04-01) added the guard together with `assertTrue(is_array($stats))`, and `36d7354ae`, tellingly titled *"Make Travis pass"* (2020-07-13), deleted that assertion, converting a loud failure into a silent skip. The same commit deleted `assertEqual($attendance, $count_completed_programs)`, which is why `:155-168` still computes `$count_missed_sessions` / `$count_completed_programs` and never asserts on either.
- **Impact.** Not user-visible: this is a hole in the safety net. ⚠ **It contradicts a claim already in the backlog** — B-032 and B-033 record *"CI green incl. test_simpletest_linux (new scenario ran end-to-end)"*. That claim does not hold; whatever those sessions verified was out of band. The module's only automated evidence for the stats payload shape, for cache-hash invalidation, and for both soft-delete regressions is inert — including for the code B-250/B-251 propose to change.
- **Fix shape (guess).** Pass `'statistics' => TRUE` in the scenario-4 request (or call `getForHealthCenterStatistics` directly), replace the bare `return` with a failing assertion, and drop the `good_nutrition` assertion for a key the payload actually has. ⚠ Nobody has seen these three scenarios execute, so budget for them failing once they do.
