- **Mechanism.** The session fetch requests the shared child data set (`Backend.NutritionEncounter.Fetch.fetch`: participants → nutrition encounters → measurements) for the activity's first pending participant only:
  ```elm
  -- client/src/elm/Pages/Session/Fetch.elm:46-56, 80-92
                              case activity of
                                  ChildActivity Height -> Just Height
                                  ChildActivity Muac -> Just Muac
                                  ChildActivity Weight -> Just Weight
                                  _ -> Nothing
  ...
                                                          |> .pending
                                                          |> Dict.toList
                                                          |> List.head
                                                          |> Maybe.map Tuple.first
                          fetchIndividualDataMsgs =
                              firstPendingParticipant
                                  |> Maybe.map (\childId -> Backend.NutritionEncounter.Fetch.fetch childId db)
  ```
  The page lets the nurse select any pending child (`Pages/Activity/View.elm:112-135`, `SetSelectedParticipant` in `Pages/Activity/Update.elm:101, 220`); the fetch receives only `sessionPage` and cannot see that choice, and the head stays the same child until that child is completed. Group measurements ARE loaded for every session child (`Backend/Session/Fetch.elm:34-35`), but `individualParticipantsByPerson` / `nutritionEncountersByParticipant` / `nutritionMeasurements` are not, so `generateIndividualNutritionMeasurementsForChild` yields `[]` and `resolveNutritionWeightMeasurementsForChild` (`Backend/NutritionEncounter/Utils.elm:567-589`) returns group weights only. The save runs the engine on that model: `Backend/Update.elm:2085-2135` → `generateNutritionAssessmentGroupMsgs currentDate … newModel`. The participant-first route (`fetchForChild`, `Pages/Session/Fetch.elm:35-40`) fetches the set for the chosen child, so the same child gets a different assessment by route. Even for the head child the set arrives over several fetch cycles, so a fast save sees a partial history.
