### B-245 — Statistical Queries: 15 prenatal diagnoses are missing from the report mapping, so encounters carrying only those are counted as "No Prenatal Diagnosis" — READY · CONFIRMED (mapping diffed independently; consumer chain verified) · MED-HIGH · tier 3 · R25 unit 7
- **Mechanism.** `hedley_reports_prenatal_diagnosis_mapping()` (`hedley_reports.module:2128`) maps only 82 of the 97 real allowed values of `field_prenatal_diagnoses`. The producer drops anything unmapped without a trace (`:980-992`, `if (!empty($prenatal_diagnosis_mapping[$diagnosis['value']]))`), then joins what is left into the wire (`$encounter_data = "$encounter_date|$encounter_type|$mapped_diagnoses|$mapped_indicators"`).
- **It is worse than an undercount.** When *all* of an encounter's diagnoses are unmapped, `$mapped_diagnoses` is `""`; `server/elm/src/Backend/Reports/Decoder.elm:253-260` turns that into `[]`; and `generatePrenatalDiagnosesReportData` (`server/elm/src/Pages/Reports/View.elm:2628-2635`) maps an empty list to `[ NoPrenatalDiagnosis ]`. A diagnosed encounter is therefore actively counted as **undiagnosed**.
- **The 15 values, verified by diffing the Features allowed-values list against the mapping keys myself** (8 structural array keys and `none` excluded): `malaria-continued`, `malaria-continued-recurrent`, `malaria-anemia-continued`, `malaria-anemia-continued-recurrent`, `hyperemesis-gravidum-by-symptoms`, `severe-vomiting-by-symptoms`, `heartburn-persistent`, `pelvic-pain-continued`, `urinary-tract-infection-continued`, `candidiasis-continued`, `gonorrhea-continued`, `trichomonas-or-bv-continued`, `high-risk-of-preeclampsia-initial`, `high-risk-of-preeclampsia-recurrent`, `moderate-risk-of-preeclampsia`.
- **All 15 are producible today.** `resolveSymptomsDiagnoses` (`client/src/elm/Pages/Prenatal/Activity/Utils.elm:3552-3570`) emits the `*Continued`, `*BySymptoms` and `HeartburnPersistent` values on every non-postpartum nurse encounter; `resolveLabResultsAndExaminationDiagnoses` (`:3470-3484`) emits the three preeclampsia-risk values from EGA week 12 for any pregnancy with a known LMP.
- **Two sub-cases with different fixes.** 12 have an obvious base code already in the map (`malaria`→`o`, `malaria-anemia`→`p`, `hyperemesis-gravidum`→`e1`, `severe-vomiting`→`f1`, `heartburn`→`k1`, `pelvic-pain-intense`→`m1`, `urinary-tract-infection`→`n1`, `candidiasis`→`p1`, `gonorrhea`→`q1`, `trichomonas-or-bv`→`r1`), and the map already collapses initial/recurrent pairs onto one code — so collapsing these too is the established convention. The 3 preeclampsia-risk values have no base code and no `PrenatalDiagnosis` constructor in `server/elm/src/Backend/Reports/Model.elm:126-190`, so surfacing them needs a code + constructor + `Translate` row: a product call.
- **Provenance.** The map was written 2025-04-20 (`ce5a984a0`); the `-continued` family predates it (2022-05-22, `e8b22dbbc`) so it was missed at authoring, and the preeclampsia-risk values arrived 2025-07-09 (`f3b8c6437`) after it and were never added.
- ⚠ **The map is baked into the stored `field_reports_data` blob**, so fixing it changes nothing on live until every person is recalculated.
- **Sizing query for the user:** `SELECT field_prenatal_diagnoses_value, COUNT(*) FROM field_data_field_prenatal_diagnoses WHERE field_prenatal_diagnoses_value IN (<the 15>) GROUP BY 1`, per site.
- **Fix shape (guess).** Add the 12 collapsible values pointing at their existing codes; decide the preeclampsia trio separately. ⭐ Worth a guard asserting every allowed value except `none` has a mapping entry — that class check would have caught both misses, and it is the same shape as B-230's encoder⊄decoder round-trip test.
