### B-312 — Aggregated NCDA scoreboard, "Iron during pregnancy" row: the nine counted months sit one month before the pregnancy — the month before the EDD and the EDD month never count, the month before conception does — READY · CONFIRMED (arithmetic re-derived from the justinmimbs `Date.diff` source) · MED-LOW · tier 3 · R28 unit 5 · ⭐ DEPLOYED (ihangane only)
- **Mechanism.** `server/elm/src/Pages/Scoreboard/View.elm:456-479`: `ageInMonths = diffMonths (Date.floor Month record.eddDate) targetDateForMonth`, `monthsBeforeDelivery = negate ageInMonths`, counted when `monthsBeforeDelivery > 0 && < 10`. `diffMonths` is `Date.diff Months` (`Gizra/NominalDate.elm:193-195`), which is `toMonths rd2 - toMonths rd1 |> truncate` with `toMonths = wholeMonths + day/100` (`justinmimbs/date` `Date.elm:1180-1210`). Forward (birth-month floor → last day of a later month) the fraction is positive and truncation rounds down correctly; backward (EDD-month floor, day 1 → last day of an EARLIER month, day 28–31) the fraction is negative and truncation rounds toward zero. EDD 2024-05-15: target 2024-04-30 → (…3.30) − (…4.01) = −0.71 → 0 → excluded; 2024-03-31 → −1.70 → −1 → counted; 2023-07-31 → −9.70 → −9 → counted. Counted months are Jul 2023 … Mar 2024 for a May 2024 EDD — every child shifted the same way, so the whole row is systematically one month early.
- **Reachability / impact.** Aggregated scoreboard, ANC + Newborn pane row 2; every cell holds the value that belongs to the following month. B-128 fixed the double shift at this site and introduced `negate ageInMonths`; the truncation asymmetry is what remains. The client scorecard computes this row differently (no `monthsBeforeDelivery` twin).
- **Fix shape (guess).** Compute the gap in calendar months (`diffCalendarMonths` on month-floored dates, or `y*12+m` arithmetic) and count 1..9 — whether the EDD month itself should count (0..9) is a spec decision.
