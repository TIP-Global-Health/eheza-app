### B-208 — Child wellness dashboard: a child registered twice is counted twice, and half their encounters are dropped — ✅ IMPLEMENTED 2026-08-24 (issue #2141, PR #2142) · CONFIRMED · tier 3 · found by `/code-review medium` on PR #2138
- **Root fact:** `hedley_stats_get_spv_data()` keys `$items` by the **individual-participant node** while setting `'id' => $row->field_person` (`hedley_stats.module:1598`), so a child registered into a second well-child participant arrives as **two `SPVDataItem`s sharing an `identifier`**, with their encounters split between them. Live: **56 persons on ihangane.live hold >1 `well-child` participant** (0.19% of 29,082). Same create-race family as [[B-195]].
- **The page then got it wrong in two OPPOSITE ways, which is what makes this worth a single fix:**
  - **Double-count** — the ECD donut maps over the items, so such a child contributes two slices, and the two can disagree: the participant carrying the verdict reads `ECDOnTrack` while the other reads `ECDNotAssessed`. The same child is drawn in the green AND the grey wedge, and the donut total exceeds the children-seen card beneath it (visible since B-206 deduped that card).
  - **Silent data loss** — ⭐ **`immunizationDataItems` was believed immune because it goes through `spvDataDict`. It is NOT.** `spvDataDict` is `List.map (\item -> ( item.identifier, item )) >> Dict.fromList`, and `AssocList.fromList` folds `insert`, which is `remove key dict` then a cons — so **the LAST item wins and the earlier participant's encounters are discarded**. `itemsToDict` on the nutrition page does the same, for well-child, individual-nutrition and group-nutrition data alike.
- ⭐ **The precedent was already in the file: `caseManagementMergeDuplicates`** solves precisely this for `CaseManagement` records (same child across programs, one identifier), with the same fold-into-a-Dict-then-`Dict.values` shape. `spvDataMergeDuplicates` follows it exactly. 📌 Grepping for an existing merge before writing one would have found it — as it would have found the dedupe idiom for B-206.
- ⚠ **A dedupe would have been WRONG, not merely incomplete.** Keeping one item discards the other participant's encounters, and the survivor is as likely to be the one that never carried an ECD verdict — the child then reads Not Assessed. A test pins that case: *"a verdict recorded against the earlier participant still decides the status"*.
- **Fix:** `spvDataMergeDuplicates` in `Pages/Dashboard/Utils.elm`; the overview applies it once at the boundary so the card, the ECD donut and `spvDataDict` all see one item per child; `itemsToDict` appends rather than replaces.
- **Verified:** `elm make` 548 modules · `elm-test` 3,001 pass · `elm-format --validate` clean · elm-review on the committed state in a fresh clone, 0 errors. **Discrimination test done by line number**: reverting the merge to last-wins fails exactly the two tests that encode the defect, while *"distinct children are left alone"* still passes.

- 📋 **Review outcome (`/code-review medium spv-merge-by-person`, 2026-08-24) — 5 findings; 2 real defects in my own diff, 1 refuted, 1 comment fix, 1 open product question.** All fixed in `63f238e3`.
  1. ⚠ **`itemsToDict` concatenated without sorting — a regression I introduced.** `countCurrentlyDiagnosedByValue` (`View.elm:3153-3174`) reads `List.head` as the most recent value, so it needs DESC order, and `mergeDicts` five lines above sorts for exactly that reason with a comment saying so. A child whose January encounter showed wasting and whose July encounter resolved it read as currently wasting. ⭐ **Worse than a regression: the sort was missing for EVERY child.** `hedley_stats_get_spv_data()` has no `ORDER BY` and `mergeDicts` sorts only in its *conflict* branch, so single-dict identifiers had always arrived in arbitrary order. Fixed for all.
  2. ⭐ **`childScoreboardDict` had the identical `Dict.fromList` last-wins bug, two lines away in the same `let`** — its encounters feed `generateVaccinationProgressDict`, so a dropped participant's doses vanish and the child reads "behind" on the immunization donut. **Fixing the SPV half alone would have been worse than fixing neither**, because the page would look consistent while the donut still lost doses. Fix: the helper is now **generic over extensible records** — `dataItemMergeDuplicates : List { a | identifier : PersonIdentifier, encounters : List b } -> …` — matching `getEncountersForSelectedMonth`'s existing style in the same file, and both feeds merge at the boundary.

Live confirmation: **0 encounters** carry more than one of the three ECD values, out of 49,301 with a warnings row. Reordering the branches would guard a state the writer cannot produce.

Product question, tracked on PR #2138, not a code defect.
