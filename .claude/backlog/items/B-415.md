### B-415 — The admin menu's "Create PMTCT Participation" link 404s: the exported path misspells the content type — READY · CONFIRMED (orchestrator read the export and the node-type name) · LOW · tier 4 · R34 unit 6
- **Mechanism.**
  ```php
  -- server/hedley/modules/custom/hedley_admin/hedley_admin.features.menu_links.inc:270-274
    // Exported menu link: menu-eheza-app-admin-menu_create-pmtct-participation:node/add/pmtct-paticipation.
    $menu_links['menu-eheza-app-admin-menu_create-pmtct-participation:node/add/pmtct-paticipation'] = array(
      'menu_name' => 'menu-eheza-app-admin-menu',
      'link_path' => 'node/add/pmtct-paticipation',
      'router_path' => 'node/add',
  ```
  The node type is `pmtct_participant`, so `node_menu()` registers `node/add/pmtct-participant`. `node/add/pmtct-paticipation` (missing `r`, and `-participation` for `-participant`) matches no router item — the export records this itself: `'router_path' => 'node/add'`, where every sibling records `node/add/<type>`. Mirrored in `hedley_admin.info:28`.
- **Reachability.** Rendered unconditionally for every administrator — `hedley_admin_block_view()` selects every row of the menu and emits `l($result->link_title, $result->link_path, …)` with no router or access check (`hedley_admin.module:182-194`). Clicking gives 404.
- **Impact.** Admin-facing, all sites, cosmetic-to-annoying; there is no other UI entry point for creating a PMTCT participation.
- **Fix shape (guess).** Correct the path, the array key and the `.info` line to `node/add/pmtct-participant`. ⚠ A stale `menu_links` row stays behind on existing sites, so this probably wants a small `hook_update_N` like the ones already in `hedley_admin.install`.
