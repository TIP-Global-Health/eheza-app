### B-378 — Person presave: the "has measurements, cannot delete" guard fires on EVERY save of an already-deleted person, so any later save (NCDA worker, a stale device PATCH, shard recalculation) silently un-deletes a person that has a live measurement — READY · CONFIRMED (guard read by the orchestrator; scout local rolled-back run) · LOW · tier 4 · R32 unit 5 · DEPLOYED, all sites; latent — 4 deleted persons with live measurements on ihangane, 0 automatic un-deletes so far
- **Mechanism.**
  ```php
  // server/hedley/modules/custom/hedley_person/hedley_person.module:~1157-1176
    // If being deleted, verify person got no measurements.
    $deleted = $wrapper->field_deleted->value();
    if (!isset($deleted) || $deleted === FALSE) {
      return;
    }

    $measurements_ids = hedley_general_get_person_measurements($node->nid);
  ...
    // Restore 'undeleted' status.
    $wrapper->field_deleted->set(FALSE);
  ```
  It checks the new value only, not whether the stored copy was already deleted; the update hook then cascades `FALSE` over live content only (B-218).
- **Evidence.** Scout local run: delete a person with no measurements (stays deleted), add an AI measurement, plain `node_save` → `deleted=false`. Live ihangane precondition: 4 deleted persons with live measurements (e.g. 1871602 deleted 2022-10-05 08:29, attendance and family planning uploaded 12:14 that day); vhw 0; the 4 historical un-deletes were manual.
- **Reachability.** Writers that save persons: `hedley_ncda` AQ worker `node_save($person)` (`hedley_ncda.module:~1048`, ihangane), device PATCH of a stale person (`deleted` ignored in the PATCH, stored TRUE stays, presave fires), `hedley_patient_recalculate_shards_for_person` on a group enrolment.
- **Impact.** A merged/deleted duplicate reappears on devices without family links or enrolments. Related: B-250 (deleted persons still listed by stats), B-199.
- **Fix shape (guess).** Refuse only when `$node->original` was not already deleted.
