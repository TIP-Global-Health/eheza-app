### B-124 — WellChild birth-length range gate can't be tested, because the task computation lives inside a view function — READY · CONFIRMED · S · test-hardening
- Surfaced by the medium review of B-121 (branch `b121-wire-range-gates`), deliberately NOT fixed there to avoid another scope move. **No GitHub issue — backlog only, per user 2026-07-22.**
- **The asymmetry:** B-121 gates two places the same way (an out-of-range measurement is not a done task). Prenatal's task count is `examinationTasksCompletedFromTotal` in `Pages/Prenatal/Activity/Utils.elm` — a pure function, so B-121 covers it with 10 tests including a site-varying one and a carried-over-height branch. WellChild's is computed INLINE inside `viewPregnancySummaryForm` (`Pages/WellChild/Activity/View.elm` ~:358), which returns `List (Html Msg)` and cannot be called for its task list alone.
- ⇒ Reverting the WellChild birth-length task to `[ maybeToBoolTask form.birthLength ]` restores the ungated save with the FULL suite green. The identical regression on the Prenatal side now fails 3 tests.
- **Fix:** extract the pregnancy-summary task computation out of the view into a callable function (Utils, mirroring the prenatal shape), then test it. `Pages/WellChild/Activity/Test.elm` already exists and already has a `birthLength = Just (HeightInCm 50)` fixture, so the scaffolding is there — the missing piece is the extraction.
- Wider point worth weighing when doing it: **task computation living in view functions is why this class can't be tested.** Prenatal is testable only because someone previously put it in Utils. Same shape likely applies to other `viewXForm` task lists.
