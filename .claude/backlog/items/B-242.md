### B-242 — Dashboard ANC: the "Current Pregnancies" filter has its date operands swapped, so it counts only pregnancies registered ON the reference day instead of every pregnancy open that month — READY · CONFIRMED (anchors + two siblings + git + deployment verified) · HIGH · tier 2 · R25 unit 4 — ✅ **IMPLEMENTED 2026-08-26 (issue #2153, PR #2154, branch `b242-current-pregnancies-date-swapped`, base develop @2b9b199ac, commit 50fb27e62)**
- **Mechanism.** `Pages/Dashboard/Utils.elm:890-893` in `getCurrentlyPregnantForSelectedMonth`: `createdDateFilter = not <| Date.compare dateLastDayOfSelectedMonth pregnancy.created == GT`, under the comment *"Pregnancy was tracked during current month, or before."* `Date.compare a b == GT` means `a > b`, so this reads `not (referenceDate > created)` = **`created >= referenceDate`** — the opposite of the comment. The two siblings in the same file put the subject first and are correct: `:994` `not <| Date.compare encounter.startDate dateLastDayOfSelectedMonth == GT` and `:1059` the same shape. The line mixes the two idioms.
- ⚠ **The reference date is TODAY for the default view.** `dateLastDayOfSelectedMonth = resolveSelectedDateForMonthSelector currentDate model.monthGap` (`View.elm:255-256`, `:1262-1263`), and `resolveSelectedDateForMonthSelector` (`Pages/Utils.elm:526-533`) returns `currentDate` when `monthGap == 0`, the last day of the month otherwise. So with the month selector untouched the card counts only pregnancies whose start date is **today** — typically a handful, against a real active cohort of hundreds. Stepping back a month counts pregnancies registered *after* that month, a wrong cohort that grows the further back you go.
- **`pregnancy.created` really is the registration date.** `hedley_stats.module:1141-1143` emits `'created' => date_format(date_create($row->field_expected), 'Y-m-d')` and the client encodes `expected.value = data.startDate` (`Backend/IndividualEncounterParticipant/Encoder.elm:16-21`), so it is always in the past.
- **Reachability and impact.** `countCurrentlyPregnantForSelectedMonth` → `View.elm:1269` ("Current Pregnancies" on the ANC page) and `View.elm:267` ("Mothers in ANC" on the CHW main page); `countCurrentlyPregnantWithDangerSignsForSelectedMonth` (`Utils.elm:931-933`) calls the same helper, so the "With Danger Signs" cards and `totalHighRiskPregnancies` (`View.elm:1355`) are wrong the same way. All sites, both nurse and CHW, no feature flag.
- **Live since 2023-12-28.** `git log -L` on those lines: the original test was `Date.compare pregnancy.created dateFirstDayOfNextMonth == LT` (correct); `a07da69ea` ("Implement immunization chart") rewrote it into the current form. `a07da69ea` is an ancestor of `origin/main` — **deployed**, and has been for every release since.
- **Fix shape (guess).** Swap the operands to match the sibling idiom (`not <| Date.compare pregnancy.created dateLastDayOfSelectedMonth == GT`), or drop the `not` and keep the operands. ⭐ Worth a discriminating test rather than a visual check: one pregnancy registered months ago must be counted for the current month — that single case fails today and passes after.

  dateLastDayOfSelectedMonth`, which is the idiom four other filters in the file already use.
