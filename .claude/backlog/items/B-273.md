### B-273 — Newborn Exam Pregnancy Summary: re-editing a record saved as "no complications" / "no defects", switching to Yes and saving with nothing ticked counts as complete and writes "none" back — READY · CONFIRMED (anchors verified by reading; not executed) · LOW · tier 4 · R26 unit 1
- **Mechanism.** `pregnancySummaryFormWithDefault` (`Pages/WellChild/Activity/Utils.elm:266-302, 316-319`): `deliveryComplications = if form.deliveryComplicationsPresent == Just False then [ NoDeliveryComplications ] else EverySet.toList value.deliveryComplications`, then `or form.deliveryComplications (Just deliveryComplications)`. The Yes/No toggle resets the list to `Nothing` (`View.elm:486-492`), and the form has no dirty flag for it (`Model.elm:178-194` — only apgar, birth weight and birth length carry one, B-030's scope), so the resolver immediately refills it from the saved value. When the saved value is the sentinel `{NoDeliveryComplications}` and the nurse has just switched to **Yes**, the form holds `deliveryComplications = Just [NoDeliveryComplications]`: the checklist (`View.elm:468-474`, options lists without the sentinel, `noneOption = Nothing`) renders nothing ticked, yet `maybeToBoolTask form.deliveryComplications` (`:476`) reports the task complete, Save is enabled, and `toPregnancySummaryValue` (`Utils.elm:333-335`) writes `{NoDeliveryComplications}` back. On reopen `listNotEmptyWithException` (`:358-364`) turns that into `deliveryComplicationsPresent = Just False`. `birthDefects` (`:275-280, :344-346`) is the same shape.
- **Why this is the dormant class waking up.** The R12 persistence-layer verdict said the sentinel/`or`-revert mechanism is inert *because every multi-select renders a clickable sentinel* — and flagged that it flips to a real bug the moment one does not. This is that instance: the sentinel is not among the rendered options, and G-06's rule draft already lists `WellChild/Activity/View.elm:462` as a gated (sentinel-less) site — correct for first entry, wrong for the re-edit path.
- **Reachability.** Newborn Exam → Pregnancy Summary saved once with "No" → reopen the activity from the Completed tab (`Encounter/View.elm:207`) while the encounter is open → toggle to Yes → Save without ticking a complication. `Update.elm:35-36` resolves the form through `pregnancySummaryFormWithDefault` before `toPregnancySummaryValueWithDefault` (`:227-234`), so the save path sees the refilled list. First-time entry is not affected (saved `Nothing` short-circuits `unwrap`); ticking any complication is fine (`setMultiSelectInputValue` replaces a lone sentinel, `Pages/Utils.elm:960-961`).
- **Impact.** The nurse's visible "Yes" is persisted as "No"; the task count reads N/N over an empty checklist. Narrow: edit path only, sentinel-saved record only; no in-encounter decision reads these flags. All sites.
- **Fix shape (guess).** When `deliveryComplicationsPresent == Just True` and the saved list is only the sentinel, resolve `form.deliveryComplications` to `Nothing` so the selection stays a pending task (same for birth defects); or add dirty flags in the B-030 style. Pin with a case beside the existing `pregnancySummaryFormWithDefault` tests in `Pages/WellChild/Activity/Test.elm`.
