- **Mechanism.** With a related person (always, on edit) every geo validator turns ANY failure into the stored value:
  ```elm
  -- client/src/elm/Backend/Person/Form.elm:563-570, 683-693
  withDefault related =
      case related of
          Just _ ->
              defaultValue related

          Nothing ->
              identity

  validateVillage geoInfo related =
      int
          |> mapError (\_ -> customError RequiredField)
          |> andThen (\id -> Dict.get (toEntityId id) geoInfo.villages ...)
          |> withDefault (Maybe.andThen .village related)

  -- Gizra/elm-form 1.0.0 src/Form/Validate.elm:94-95
  defaultValue a validation validationField =
      Ok (Result.withDefault a (validation validationField))
  ```
  The selects carry a blank option (`emptyOption ::`, `Pages/Person/View.elm`); picking it stores an empty string, and `applyDefaultLocation` refills only when the value is `Nothing` (`formFieldEmpty`), so the blank reaches validation, fails `int`, and falls back.
- **Reachability.** Nurse edits an adult (the address section is hidden for CHW): blank village, blank cell, pick another cell, Save without picking a village. Parent levels are locked until the child level is blanked, so changing a cell goes through this state.
- **Impact.** New cell + old village is saved; `generateMsgsForPersonEdit` then copies the address to related persons (parked B-065's cascade). The address matches no village, so village-resident lookups miss the person. Needs the nurse to leave a level unpicked.
- **Constraint on any fix.** The fallback has a purpose — stored names missing from the geo table (B-151 / B-389) must still save.
- **Fix shape (guess).** Fall back only when the field is untouched (`Nothing`), not when it is present and blank or invalid.
