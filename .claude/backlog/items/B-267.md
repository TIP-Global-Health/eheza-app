### B-267 — Three latent traps in the RESTful writable contract, all unreachable today — READY · CONFIRMED (anchors + cardinality + reachability all verified) · LOW · tier 4 · R25 unit 6
- Recorded together because none is live and each is a trap for a *future* change. The unit's exhaustive sweep (215 plugins × 214 uploadable entity constructors) found **zero** live instances of a client key the server does not declare.
- **(a) `field_review_state` is in NCD's `$multiFields` but is cardinality 1.** `HedleyRestfulNCDLabsResults.class.php:23-28` lists it among the multi-value fields; the prenatal sibling puts it in `$fields` (`HedleyRestfulPrenatalLabsResults.class.php:16-20`), and `hedley_prenatal.features.field_base.inc:1461` says `'cardinality' => 1` (all verified). `$multiFields` entries get `GROUP_CONCAT` + `explode`, so a set value would download as `"review_state": ["completed"]`, and both bundles share `decodeLabsResultsValue` (`Backend/Measurement/Decoder.elm:1035-1043`) whose `optional … (nullable decodeLabsResultsReviewState)` needs a string — `optional` falls back only when the key is absent or null, so a present array **fails the decode**. Unreachable today: `reviewState` is written in exactly two prenatal places, and every NCD path leaves it `Nothing`. It goes live the moment an NCD lab-review flow, migration or repair script writes the field. **Fix: move it to `$fields`.**
- **(b) `counseling_session.topics` is the one multi-valued entity reference the upload path never converts from UUIDs to nids.** `handleChanges()` converts only a hardcoded `$multiEntitiesFields = ['participating_patients']`; `encodeCounselingSessionValue` (`Backend/Measurement/Encoder.elm:942-945`) sends `topics` as an array of UUID strings, which misses both that branch and the scalar `Uuid::isValid` branch, so `target_id` is written as a UUID string and MySQL coerces it to `0`. ⚠ It would **not** error: `entityreference_field_validate()` records errors only inside `if (!empty($valid_ids))`, so a list where *nothing* resolves validates clean. Dead today — `SaveCounselingSession` has no producer and the counseling group activity is commented out — but a trap for whoever revives it, and because `HedleyRestfulCounselingSessions` inner-joins on `field_topics…target_id`, the affected nodes would then disappear from download batches (**B-192's shape**). **Fix: drive `$multiEntitiesFields` from the plugins' declared entity-reference fields rather than a hardcoded array.**
- **(c) `HedleyRestfulDevices` inherits a `uuid => field_uuid` mapping for a bundle with no such instance** — the `device` bundle has exactly one field instance, `field_pairing_code`. The only phantom property in 215 plugins, on an endpoint with no reachable caller. Dead code with a latent 500.
- 📌 **Durable fact this unit establishes, correcting the premise it was sent with: class (1) is NOT silent here.** `RestfulEntityBase::setPropertyValues()` (`contrib/restful/.../RestfulEntityBase.php:661-724`) collects leftover request keys and throws `RestfulBadRequestException('Property @names is invalid.')`, which propagates out of `handleChanges()`, rolls the transaction back, and returns 400 for the **whole batch**. So an undeclared key is a permanent upload jam, not a lost value — which is why finding zero of them matters, and why the `encodeIfSet` guards on the shared cross-program encoders (vitals, labs-results, blood tests) are load-bearing rather than cosmetic.
- 📌 Also established: `id` (→`nid`) and `vid` stay writable through `RestfulEntityBase` and are not in `$ignoredFields`; no client encoder emits either, so this is surface, not defect — same declined class as B-225's note on the plain endpoints.
