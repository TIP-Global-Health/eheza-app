### B-386 — Client and server now spell five clinical labels differently, so a device screen and a generated report name the same diagnosis two ways — READY · CONFIRMED (orchestrator grepped both copies) · LOW · tier 4 · R33 unit 3 · all sites, English readers · un-deployed (introduced by the duplicate-english fold, release #2128 open)
- **Mechanism.** The duplicate-English fold lower-cased five strings in `client/src/elm/Translate.elm` and left the server copy in Title Case:
  ```elm
  -- server/elm/src/Translate.elm:2462
                      { english = "Pregnancy-Induced Hypertension"
  -- server/elm/src/Translate.elm:2672
                      { english = "Severe Vomiting"
  -- server/elm/src/Translate.elm:2693
                      { english = "Imminent Delivery"
  ```
  plus `:2864` `"Perineal Pain or Discharge"` and `:1479` `"Severe Acute Malnutrition"`. The client now writes `"Pregnancy-induced hypertension"` (`:12105`), `"Severe vomiting"` (`:5632`, `:19681`), `"Imminent delivery"` (`:5611`, `:8991`), `"Perineal pain or discharge"` (`:12070`) and `"Severe acute malnutrition"` (`:15299`, `:25337`).
- **Reachability.** Client: the prenatal diagnosis pane and progress report (`PrenatalDiagnosis` / `PrenatalDiagnosisForProgressReport`) and the nutrition assessment. Server: the Drupal-hosted reports app, loaded by `hedley_general.module:674`, which names the same diagnoses.
- **Impact.** Cosmetic — no data, no logic, no decision reads the string. A manager comparing a device screen with a generated report sees two spellings of one diagnosis. Worth recording because the fold's own rationale is that two copies drift, and this is drift the new check cannot see (see [[B-387]] point 3).
- **Fix shape (guess).** Apply the five client spellings to the server copy and rebuild `elm-main.js`; `ci-scripts/test_server_elm_bundle.sh` catches a missed rebuild.
