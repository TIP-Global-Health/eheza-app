### B-270 — Child progress report ECD pane: when two Well Child encounters fall in the same pediatric-care milestone window, the one that decides the milestone's status is arbitrary — READY · CONFIRMED (anchor + AssocList.fromList semantics verified) · LOW · tier 4 · found while building B-214
- **Mechanism.** `generateECDMilestonesWithStatus` (`Pages/WellChild/ProgressReport/View.elm:1072-1095`) maps each encounter to `( milestone, status )` and calls `Dict.fromList`. Vendored `AssocList.fromList` is `List.foldl insert` (`pzp1997/assoc-list/1.0.0/src/AssocList.elm:464-471`), so for a duplicated key the **last** entry in the list wins. The list is `reportData.wellChildEncounters` (`:427`), which is storage order — encounter UUID order — so which of two same-window encounters decides the milestone's ECD status is arbitrary.
- **Why B-214 did not fix it.** B-214 sorted the *other* read in the same function (`:369`, the anchor encounter) but deliberately left `:427` alone: a DESC sort there would make the last element the OLDEST, so the oldest encounter in the window would decide the status — arbitrary replaced by wrong.
- **What is unresolved.** Which encounter *should* win: the most recent assessment in the window (ASC sort, or an explicit fold keeping the newest), or the most severe warning seen in the window. That is a clinical question, not a code one — the statuses are `StatusOffTrack` / `StatusECDBehind` / `StatusOnTrack`, and they are not obviously "latest wins".
- **Impact.** Only when a milestone window contains two or more Well Child encounters carrying ECD warnings, and they disagree. Display only; no data written. All sites.
- **Fix shape (guess).** Decide the rule first, then either sort ASC before `Dict.fromList` (latest wins) or fold with an explicit severity comparison. ⚠ Do not "fix" this by sorting DESC — see above.
