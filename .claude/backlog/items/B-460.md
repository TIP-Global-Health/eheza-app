### B-460 — Sync incidents: the backend cannot re-create a missing entity the device sent, because a `false` boolean is written as an empty string — ✅ IMPLEMENTED 2026-10-09, issue #2320, PR #2321 · CONFIRMED (prod dblog, vhw live) · every auto-creation fails · DEPLOYED, all sites
- **Found 2026-10-09**, reported by the user from field runs on vhw on 2026-10-08. Not found by a discovery round.
- **The feature.** A `Could not find UUID` upload error makes the device look the UUID up in `shards`, walk its parents, and POST them to `/api/report-incident-details`. That stores the JSON on the user, and `hedley_user_user_presave()` re-creates each missing node.
- **Mechanism (a): booleans.** `hedley_user_create_entity_by_sync_incident_data()` has no `list_boolean` case, so a decoded `FALSE` goes through `default` unchanged. PDO binds it as `''`, and strict MariaDB rejects that in an integer column:
```php
// server/hedley/modules/custom/hedley_user/hedley_user.module:278-280
      default:
        $entity[$name][LANGUAGE_NONE][0]['value'] = $value;
    }
```
  Every entity carries `"deleted": false`, so **no auto-creation can succeed**. The surrounding `catch` returns silently. Once the person fails, its `individual_participant` returns early because the required `field_person` does not resolve.
- **Evidence (vhw live).** Events 241295–241297, uid 234, 2026-10-08 13:35:21: `Could not find UUID: 55b69249-…`, then `Incorrect integer value: '' for column field_data_field_birth_date_estimated` (node 100926, person). Across all `/api/report-incident-details` rows: 2× on `field_birth_date_estimated`, 2× on `field_deleted`, and nothing else.
- **Mechanism (b): notice.** `$value = $data->{$name_at_data};` reads a property before `isset`, so any field missing from the JSON logs `Undefined property` (3× on vhw, for `$clinic`, which `person` has on vhw). The outcome is right; the notice is noise.
- **Fix (shipped in PR #2321).** Skip `field_deleted`, because a re-created entity is never deleted. Write `list_boolean` as `(int) $value`. Read the property with an `isset` guard.
- **Not in the fix: stuck incidents don't retry.** `HedleyRestfulReportIncidentDetails::processReport()` saves the user only when the details changed, and a failed attempt leaves them on the user. After deploy, resend the same JSON and nothing runs. Users stuck now need one re-save of their account (admin UI or drush) to retry.
- **Sample payload** (device, vhw): an `individual_participant` (well-child) plus its `person`, with `deleted: false`, `birth_date_estimated: false` and `save_gps_location: false`.
- **Verified locally** by running develop's function and the patched copy on the sample payload: develop creates nothing (same PDOException), the patch creates both nodes. No SimpleTest; that would add a full install to CI.
