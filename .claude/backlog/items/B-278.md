### B-278 — Well Child head circumference: correcting a reading that triggered the macro/microcephaly popup leaves the warning on the encounter — READY · CONFIRMED (three branches + backend replace logic verified) · LOW-MED · tier 4 · R26 unit 2
- **Mechanism.** `PreSaveHeadCircumference` (`Pages/WellChild/Activity/Update.elm:551-582`): the `zscore > 3` and `zscore < -3` branches emit `SetWellChildEncounterWarning Warning…cephaly`, and the no-z-score branch emits `SetWellChildEncounterWarning NoHeadCircumferenceWarning` ("measurement was not taken"), but the in-range branch returns `( NoHeadCircumferenceWarning, [] )` — no message. `Backend/WellChildEncounter/Update.elm:49-71` rewrites the head-circumference subset of `encounterWarnings` only when a message arrives, so a `WarningHeadCircumferenceMacrocephaly` recorded earlier on this encounter survives a corrected save.
- **Reachability.** Nurse or CHW types a wrong value (z > 3), the popup fires, "Continue" saves (`CloseHeadCircumferencePopup :537-548`) and the warning is written. The task is reopened (same session, or later via the Completed tab), the right value entered, Save → in-range branch → nothing clears it.
- **Impact.** Both sites. The progress report's warning pane (`Pages/WellChild/ProgressReport/View.elm:880-944`) lists the macro/microcephaly entry for that encounter; the dashboard cephaly count reads the same field through server stats (that hop not traced). Needs a wrong-then-corrected entry.
- **Fix shape (guess).** Emit `setEncounterWarningMsg NoHeadCircumferenceWarning` from the in-range branch too, so all three branches record the outcome and the subset is always rewritten on save.
- **Re-checked 2026-10-14 (process-backlog, presented as a tier-4 pick).** ⚠ The entry's fix shape is WRONG: `NoHeadCircumferenceWarning` means "not taken". `fix-well-child-encounters-warnings.php` deletes it from encounters with a value; the dashboard cephaly card reads it as no information. The in-range branch must REMOVE the cephaly warnings, adding nothing. ECD has no such gap (it always writes `NoECDMilstoneWarning`).
