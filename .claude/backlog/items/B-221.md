### B-221 — Prenatal: saving the Partner HIV test never re-runs the diagnosis assessment, so a discordant-partnership diagnosis reached through it is not persisted — CONFIRMED (orchestrator-read the branch vs its 9 siblings) · MED · tier 3 · both sites · R23 unit 7
- **Mechanism.** `Backend/Update.elm:3114-3126` `[ PrenatalPartnerHIVTestRevision _ data ]` calls only `processRevisionAndUpdatePrenatalLabsResults`. Every sibling single-revision lab branch (HIV `:3094`, HIVPCR `:3128`, Syphilis `:3148`, HepB `:3175`, Malaria `:3198`, Urine `:3230`, BloodGpRs `:3250`, Hemoglobin `:3273`, RBS `:3293`) additionally calls `processRevisionAndAssessPrenatal data.encounterId False` and appends its messages. But `generatePrenatalDiagnosesForNurse` reads `measurements.partnerHIVTest` (`Pages/Prenatal/Activity/Utils.elm:2320`, feeding `DiagnosisDiscordantPartnership{Initial,Recurrent}Phase`). History (agent-traced): branch written `c8a70a32d` (2024-01) when the partner test fed no diagnosis; partner-driven logic arrived `d3bb86fa8` (2024-10) and the branch was not updated.
- **Reachability.** Nurse saves the partner test (`Pages/Prenatal/Activity/Update.elm:~3191`; recurrent `RecurrentActivity/Update.elm:~937/~1829`) → SW returns the single revision → this branch. Lab tasks are freely ordered, so "partner test saved last (or alone)" is ordinary.
- **Impact.** `encounter.diagnoses` misses the discordant-partnership diagnosis. `resolveDiscordantPartnershipSet` (`Pages/Prenatal/Utils.elm:1821-1822`) gates the TDF3TC/PrEP medication set on `diagnosed diagnosis assembled` (= `EverySet.member … encounter.diagnoses`) → guidance not offered unless a later assessing revision fires in the same encounter. `generatePrenatalRecurrentPhaseCompletedMsgs` (`:~9226`) recomputes locally, so the app can hold Next Steps pending while the Next Steps page (built from the stale persisted set) shows nothing to do. Self-heals only on a later assessing revision.
- **Fix shape (first guess):** mirror the HIV-test branch — keep the labs-results update and add `processRevisionAndAssessPrenatal data.encounterId False`, concatenating both message lists.
