### B-265 — Reports recalculation ignores session and clinic edits, so a corrected session date or a re-categorised group leaves every attendee's stored bucket stale — READY · CONFIRMED (trigger lists verified; edit frequency unknown) · LOW · tier 4 · R25 unit 7
- **Mechanism.** The person blob freezes two values read from nodes that appear in neither trigger list: `hedley_reports.module:1274-1281` reads the session's `field_clinic` (→ `$group_type`) and `field_scheduled_date` (→ `$encounter_date`) into `$data['group_nutrition'][<group>]`. But `hedley_reports_get_triggering_encounter_types()` (:446) lists individual encounters only, `…_measurement_types()` (:467) lists measurements, and `hedley_reports_trigger_recalculation_by_edited_content` (:415) special-cases only `individual_participant` / `antenatal`. Neither `session` nor `clinic` appears anywhere.
- **Impact.** B-192's shape: a corrected session date, or a clinic moved from e.g. `pmtct` to `achi`, leaves every attendee's group bucket and date stale until some unrelated measurement of theirs is saved — never, for quiescent records. The Demographics report's per-group encounter rows read exactly those buckets, so the failure is a wrong *bucket* rather than a wrong number.
- ⚠ **The code path is certain; the frequency is not.** Neither node type is edited through any PWA flow — session dates and clinic group types would be changed in the Drupal admin UI, and whether that happens in practice is a question for the team, not the code. That question sizes the item.
- **Fix shape (guess).** Add `session` and `clinic` to the edit trigger, enqueuing recalculation for the affected people (a session's attendees; a clinic's every session's attendees). ⚠ The clinic case fans out widely and probably wants a batched path rather than one AQ item per person.
