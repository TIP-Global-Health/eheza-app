### B-394 — `healthy_start` is on in Rwanda production and is the one site feature no local or CI environment ever enables, so nothing gated on it is ever tested — READY · CONFIRMED (orchestrator read both lists and re-checked the live flags) · MED · tier 3 · R34 unit 4
- **Mechanism.** `hedley_admin_get_available_features()` lists ten features:
  ```php
  -- server/hedley/modules/custom/hedley_admin/hedley_admin.module:614-627
  function hedley_admin_get_available_features() {
    return [
      'family_nutrition', 'gps_coordinates', 'group_education', 'healthy_start',
      'hiv_management', 'ncda', 'report_to_whatsapp', 'stock_management_hc',
      'stock_management_village', 'tuberculosis_management',
    ];
  }
  ```
  The environment config enables nine of them, and `healthy_start` is the omission:
  ```yaml
  -- .ddev/config.local.yaml.example:55-63
      - exec: drush vset hedley_admin_feature_ncda_enabled 1
      - exec: drush vset hedley_admin_feature_stock_management_hc_enabled 1
      - exec: drush vset hedley_admin_feature_stock_management_village_enabled 1
      - exec: drush vset hedley_admin_feature_tuberculosis_management_enabled 1
      - exec: drush vset hedley_admin_feature_group_education_enabled 1
      - exec: drush vset hedley_admin_feature_report_to_whatsapp_enabled 1
      - exec: drush vset hedley_admin_feature_hiv_management_enabled 1
      - exec: drush vset hedley_admin_feature_gps_coordinates_enabled 1
      - exec: drush vset hedley_admin_feature_family_nutrition_enabled 1
  ```
  `variable_get(..., FALSE)` means absent = off. CI builds its config from that same file verbatim:
  ```bash
  -- ci-scripts/install_drupal.sh:9-11
  echo composer_version: "2" > .ddev/config.local.yaml
  cat .ddev/config.local.yaml.example >> .ddev/config.local.yaml
  ddev restart || { ddev logs; exit 1; }
  ```
- **Evidence (orchestrator live query, 2026-09-21).** `terminus remote:drush ihangane.live -- sql-query "SELECT name, value FROM variable WHERE name LIKE 'hedley_admin_feature%'"` returns `hedley_admin_feature_healthy_start_enabled i:1;` — on in Rwanda production, alongside group_education, hiv, ncda, whatsapp and tb.
- **Impact.** No CI job — simpletest, e2e job 1, e2e job 2, e2e reporting — and no developer's local environment ever runs a path gated on `healthyStartEnabled` (`client/src/elm/Backend/Utils.elm:408`), while Rwanda runs it in the field. The prenatal suite is the most heavily tested module in the repo and always runs the flag-OFF branch. With the flag on, nurse prenatal encounters gain an entire **Ultrasound** activity plus a gestational-weight-gain indicator and a different pre-pregnancy classification — none of it reachable in CI, and a spec that claims to "complete all activities" is not doing so on the configuration Rwanda actually runs. ⚠ This is the environment in which [[B-181]] (Ultrasound missing server-side) and [[B-268]] went unnoticed, and in which [[B-235]]'s inverted GWG verdict shipped.
- **Related.** B-081(b) is the same omission in CLAUDE.md's prose feature list — a documentation fix. This is the executable copy, and its consequence is test coverage.
- **Fix shape (guess).** Add the tenth vset. Decide first whether it should be on for every `EHEZA_SITE`, since it is Rwanda-only in production — turning it on unconditionally would change what the Burundi/Somalia e2e axis exercises too.
