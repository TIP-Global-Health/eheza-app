### B-370 — Login location selection: an assignment added to a nurse or CHW on the server never reaches the health-centre / village picker until Sign Out, because nurse updates are applied only once a health centre is already selected — ✅ IMPLEMENTED 2026-10-15, issue #2364, PR #2365, branch `B-370-picker-misses-new-assignment` (base `cc3e5ab96`, head `28ca86414`) — was READY · CONFIRMED (revision handler, `getLoggedInData` and both picker filters read by the orchestrator) · LOW · tier 4 · R32 unit 6 · DEPLOYED, all sites
- **Mechanism.**
  ```elm
  -- client/src/elm/App/Update.elm:1609-1621
  handleRevision model revision =
      case revision of
          Backend.Model.NurseRevision uuid data ->
              Maybe.andThen
                  (\( _, loggedIn ) ->
                      if Tuple.first loggedIn.nurse == uuid then
                          Just (UpdateNurseData ( uuid, data ))
                      ...
                  (getLoggedInData model)
  ```
  ```elm
  -- client/src/elm/App/Utils.elm:13-17
  getLoggedInData model =
      RemoteData.toMaybe model.configuration
          |> Maybe.andThen (.loggedIn >> RemoteData.toMaybe)
          |> Maybe.map2 (\healthCenterId loggedIn -> ( healthCenterId, loggedIn )) model.healthCenterId
  ```
  On the picker `model.healthCenterId` is `Nothing`, so the revision is dropped. The picker filters by the in-memory nurse:
  ```elm
  -- client/src/elm/Pages/PinCode/View.elm:527-534 (selectHeathCenterOptions; selectVillageOptions :550-557 the same)
          filtered =
              db.healthCenters
                  |> RemoteData.map
                      (Dict.filter (\uuid _ -> assignedToHealthCenter uuid nurse)
  ```
- **Reachability.** A nurse/CHW logs in and finds their HC/village missing (or an empty list); a supervisor adds the assignment; the general download stores the nurse record in IndexedDB but the logged-in nurse is not updated. Only Sign Out → PIN again (which reads the nurse from IndexedDB) shows it.
- **Impact.** Dead-end screen with a non-obvious workaround; no data touched. All sites, all roles. R11/R29's "unassignment enforced on next render" covers only the case where a location is already selected.
- **Fix shape (guess).** Match `NurseRevision` against `configured.loggedIn` directly, without requiring `healthCenterId`.
