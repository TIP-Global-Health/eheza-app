### B-452 — Prenatal obstetric history: correcting step 1 to a first pregnancy leaves the step-2 answers (previous preeclampsia, >10 years since delivery, C-section, past-delivery signs) on the encounter, and the preeclampsia-risk diagnoses still read them, so a primigravida is diagnosed high / moderate risk of preeclampsia from deliveries she never had — READY · VERIFIED (scout scratch elm-test through the real `generatePrenatalDiagnosesForNurse`; orchestrator read the save arm, the skip predicate, task completion, both readers and the report) · LOW-MED population (**13 live step-2 records on primigravida encounters on ihangane**) · ⭐ tier 1 (diagnosis determination) · DEPLOYED
- **Found R39 unit 1.** Writer side: a record the form no longer shows is never neutralised; reader side: both step-2 readers are status-blind to step 1.
- **Mechanism.** Step 2 is skipped when step 1 says gravida 01 / para 0000, and the step-1 save then emits only its own record:
```elm
-- client/src/elm/Pages/Prenatal/Activity/Update.elm:561-596 (SaveOBHistoryStep1)
                ( extraMsgs, updatedData ) =
                    if skipSecondStep then
                        ( generateHistoryMsgs nextTask, model.historyData )
                    else
                        ( [], ... { data | obstetricHistoryStep = ObstetricHistorySecondStep } )
                appMsgs =
                    model.historyData.obstetricFormFirstStep
                        |> toObstetricHistoryValueWithDefault measurement
                        |> Maybe.map (Backend.PrenatalEncounter.Model.SaveObstetricHistory personId measurementId >> ...)
```
`skipObstetricHistorySecondStep` (`Activity/Utils.elm:940-951`) is `gravida == "01" && para == "0000"`; `historyTaskCompleted Obstetric` (`:915-928`) then needs step 1 only, so the task reads complete. Nothing deletes or neutralises `measurements.obstetricHistoryStep2`. Both readers take the first step-2 record of `current :: previous` with no look at step 1:
```elm
-- client/src/elm/Pages/Prenatal/Activity/Utils.elm:2448-2456 (→ DiagnosisHighRiskOfPreeclampsia{Initial,Recurrent}Phase)
                byPreviousPreeclampsia =
                    List.filterMap (.obstetricHistoryStep2 >> getMeasurementValueFunc) allMeasurements
                        |> List.head
                        |> Maybe.map (\value -> EverySet.member ObstetricHistoryPreeclampsiaPreviousPregnancy value.signs)
-- :2564-2587 (→ DiagnosisModerateRiskOfPreeclampsia): MoreThan10Years, placenta abruption, low birthweight, SGA, intra-uterine death
```
The progress report prints the same record status-blind (`Pages/Prenatal/ProgressReport/View.elm:720-804`).
- **Reachability.** First nurse encounter (`expectHistoryTask Obstetric = nurseEncounterNotPerformed`), History stays editable until the encounter ends: enter counts → Save and next → answer step 2 → Save → reopen Obstetric → set the counts to 0 → Save (step 2 skipped). Step 2 is recorded only at the first nurse encounter, so `List.head` returns the stale record at every later nurse encounter of the pregnancy too. Since B-365 (#2249, deployed) `ObstetricHistoryRevision` re-runs the assessment on the correcting save itself.
- **Impact.** Nurse flow, all sites. Risk-of-preeclampsia diagnoses drive the warning popup, Aspirin (`Pages/Prenatal/Utils.elm:1854-1866`), the diagnoses list and the obstetric-history text on the report.
- **Evidence.** Scout scratch elm-test at EGA 20 w, NurseEncounter, step 1 all counts 0: step 2 `{PreeclampsiaPreviousPregnancy}` → `[DiagnosisHighRiskOfPreeclampsiaInitialPhase]`; step 2 `{MoreThan10Years}` → `[DiagnosisModerateRiskOfPreeclampsia]`; no step 2 → `[]`. Live ihangane 2026-10-07: 13 non-deleted step-2 records whose step 1 has every count at 0 and a non-`none` sign or a non-`neither` period (query in the R39 round record).
- **Fix shape (guess).** When `skipSecondStep` is true and a step-2 record exists for the encounter, also save the neutral step-2 value over its id (`signs = {NoObstetricHistoryStep2Sign}`, period `Neither`, delivery `NoPreviousDeliverySign`, no C-section reason) — this also keeps the server completion report (B-180) consistent; or make both readers and the report ignore step 2 when the paired step 1 is primigravida.
