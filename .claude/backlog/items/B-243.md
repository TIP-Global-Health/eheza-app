### B-243 — Dashboard nutrition: individual Nutrition encounters send weight-for-age under the stunting key, so the "# of Stunting" card shows underweight and height-for-age is dropped entirely — READY · CONFIRMED (helper + both callers + constants verified) · MED-HIGH · tier 3 · R25 unit 4
- **Mechanism.** `hedley_stats.module:1918` in `hedley_stats_add_zscore_age_for_bundle()`: `$alias = ($bundle == HEDLEY_ACTIVITY_WELL_CHILD_WEIGHT_CONTENT_TYPE) ? 'zscore_underweight' : 'zscore_stunting';`. The helper has two callers with different bundle families — `:1698-1704` passes `[well_child_height, well_child_weight]` (correct: height→stunting, weight→underweight) and `:2138-2143` passes `[nutrition_height, nutrition_weight]`. Neither nutrition constant equals `'well_child_weight'` (`hedley_activity.module:16,17,25,26` — verified), so **both** land in `zscore_stunting`, and because `nutrition_weight` is iterated second it overwrites the height value.
- **Net effect for individual Nutrition encounters.** `zscore_stunting` carries weight-for-age; `zscore_underweight` is never emitted at all (the string appears only at `:1918` and at `:2241`, the group path); height-for-age is lost.
- **Reachability.** `hedley_stats_get_nutrition_individual_data()` → `nutrition_individual_data` → `Backend/Dashboard/Decoder.elm:450-459` → `assembled.nutritionIndividualData` → `Pages/Dashboard/View.elm:2985-2999` → Dashboard → Pediatrics → Nutrition.
- **Impact.** `numberOfStunting` (`View.elm:3093-3094`, the "# of Stunting" card) reads `.zscoreStunting`, which for children whose only measurements come from individual Nutrition is really weight-for-age. `isGoodNutritionEncounter` (`:3150-3152`) tests `Maybe.Extra.values [zscoreStunting, zscoreUnderweight, zscoreWasting]`, so with underweight absent and stunting substituted a stunted-but-normal-weight child reads as good nutrition — which feeds `percentOfGoodNutrition` (`:3046`) and `numberOfDiagnosedMalnorished` (`:3122`). Group-session and well-child paths are correct, so the same child can be right or wrong depending on which programme measured them. Site-independent.
- **Fix shape (guess).** Make the alias depend on the measurement's role rather than one hard-coded bundle name — pass the alias in from the caller, or test membership in a weight-bundle list holding both `well_child_weight` and `nutrition_weight`.
