### B-516 — Release notes: no issue title is fetched for a PR from a `B-…` (or any non-numeric) branch, and GitHub API errors read as empty data — READY · CONFIRMED (merge log read) · LOW · tier 4 · side finding of B-410 (PR #2434, review round 2, findings 6 and 7)
- **Found 2026-10-28** in the review of #2434.
- **Mechanism.** The issue number is read from the merge line's branch name, which must start with digits:
  ```php
  -- server/RoboFile.php:376
        preg_match_all('!from [a-zA-Z-_0-9]+/([0-9]+)!', $line, $issue_matches);
  ```
  Of the last 30 merges into `develop`, 29 come from `B-…`, `TH-…`, `drupal-core-…`, `release-…` branches; one (`2147-hide-hiv-report-tab`) matches.
- **Second defect, same function.** `githubApiGet` decodes an error body (401/403/404) like data; the `!empty($pr_details->user)` check skips it silently, so contributors and line counts read as empty or zero.
- **Impact.** Every release's notes miss the issue titles for nearly all backlog PRs, on any remote.
- **Fix shape (guess).** Read the issue from the PR body's first-line `Fixes #N` via the PR API already called; fail loudly on an API error reply.
