### B-276 — Acute Illness malaria RDT edit: changing a saved non-positive result to Positive pre-answers "Currently pregnant?" as No — READY · CONFIRMED (anchors verified) · LOW-MED · tier 4 · R26 unit 3
- **Mechanism.** `fromMalariaTestingValue` (`Pages/AcuteIllness/Activity/Utils.elm:1560-1570`): `if saved == Just RapidTestPositiveAndPregnant then { rapidTestResult = Just RapidTestPositive, isPregnant = Just True } else { rapidTestResult = saved, isPregnant = Just False }` — it invents `isPregnant = Just False` for a saved Negative / Indeterminate / UnableToRun, which carry no pregnancy information. `SetRapidTestResult` deliberately clears `isPregnant` (`Update.elm:622`), but `malariaTestingFormWithDefault` (`:1584`) `or`s the invented `Just False` straight back, so the pregnancy section (`:496-501` → `isPregnantInputsAndTasks :519-530`, a `viewBoolInput`) renders with "No" pre-selected and counts as complete.
- **Reachability.** Fertile woman, saved non-positive RDT (e.g. entered wrongly), task reopened, result changed to Positive, Save. First entry (no saved value) correctly forces the question — `unwrap` short-circuits on `Nothing`.
- **Impact.** If the pre-selected "No" is not noticed, a pregnant woman is stored as `RapidTestPositive` → `DiagnosisMalariaUncomplicated` (Coartem) instead of `MalariaUncomplicatedAndPregnant` (referral). LOW-MED: the answer is visibly pre-selected. Both sites.
- **Sibling.** Same shape as the COVID form's `fromCovidTestingValue` (`:1898-1899`), whose ROUND-TRIP half was B-070 (implemented); this is the prefill half, which B-070 did not cover — check the COVID prefill too when building.
- **Fix shape (guess).** Derive `isPregnant` only from positive results (`Nothing` otherwise), or give `MalariaTestingForm` an `isPregnantDirty` flag set by `SetRapidTestResult`.
