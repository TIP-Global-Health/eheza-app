### B-519 — NCD labs: the labs entry is closed from the device's own copy, and "all completed" compares set sizes, so a copy behind its tests or holding a test no longer performed closes the entry at the wrong time — READY · CONFIRMED (code read) · LOW · tier 4 · side finding of B-493 (PR #2442, review round 2, findings 4 and 5)
- **Found 2026-10-29** in the review of #2442, which fixes the same shapes for Prenatal only.
- **Mechanism.** The NCD close decides from the entry's own sets by size and writes the device's copy back with only the date changed:
  ```elm
  -- client/src/elm/Pages/NCD/RecurrentActivity/Update.elm:58-67 (develop)
                                            ( performedTests, completedTests ) =
                                                labsResultsTestData currentDate results
                                        in
                                        if EverySet.size performedTests == EverySet.size completedTests then
                                            let
                                                updatedValue =
                                                    results.value
                                                        |> (\value ->
                                                                { value | resolutionDate = currentDate }
  ```
  The NCD "results added" path in `Backend/Update.elm` (`generateNCDLabsResultsAddedMsgs`) uses the same `EverySet.size updatedCompletedTests == EverySet.size updatedPerformedTests` check.
- **Impact.** Unmeasured. A completed test no longer performed (for example `{TestCreatinine}` completed, `{TestRandomBloodSugar}` performed and pending) makes the sizes match, so the entry is resolved while a test waits; an entry behind its tests stays open or is written back without them.
- **Fix shape (guess).** A set check like Prenatal's `allLabsCompleted`, and completions read from the NCD test measurements, as #2442 does for Prenatal. Check NCD's own "do not update if already set" guard first.
