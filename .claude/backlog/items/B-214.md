### B-214 — Child progress report: "the last Well Child encounter" is whichever sorts first by UUID, so the Next Appointment pane can show a past visit's dates — ✅ IMPLEMENTED · CONFIRMED (orchestrator-read at anchor + Dexie query + sibling sorts) · MED · tier 3 · both sites · R23 unit 2
- **Mechanism.** `Pages/WellChild/ProgressReport/View.elm:369-374` `lastWellChildEncounterId = … getWellChildEncountersForParticipant db >> (List.head >> Maybe.map Tuple.first)`. That helper is `getParticipantEncountersByEncounterType` (`Backend/NutritionEncounter/Utils.elm:350-360`) — a plain `Dict.toList`, no sort. The dict is `Dict.fromList` over the IndexedDB result (`Backend/Update.elm:853-862`); vendored `AssocList.insert` appends, and the Dexie query (`nodes.js:~1087`, `where('[type+individual_participant]').anyOf(tuples)`, no `sortBy`) returns compound-index-then-primary-key order = encounter UUID order. Every `WellChildEncounterRevision` refetches, so it stays UUID order. Every OTHER "latest" consumer sorts first: `resolveDateOfLastNutritionAssessment` (`:841/:850`), `generatePartitionedWarningEntries` (`:878`), `GlobalCaseManagement/View.elm:~1576`, `resoloveLastScheduledImmunizationVisitDate` (`Measurement/Utils.elm:9186+`, via `generatePreviousMeasurements` DESC). `assembleProgresReportData` is the copy not updated.
- **Downstream.** `maybeAssembled` (`:376-382`) is built for that arbitrary encounter; `individualWellChildMeasurementsWithDates` (`:434-441`) = `(thatEncounter.startDate, …) :: previousMeasurementsWithDates`, head ≠ latest. `viewNextAppointmentPane` (`:1549-1552`) reads `List.head individualWellChildMeasurements |> .nextVisit`, so the Immunisation / Pediatric Visit dates come from whichever encounter sorts first (probability ≈1/n of being the real latest). Secondary: `generateECDMilestonesWithStatus` (`:1072-1095`) `Dict.fromList` over the same unsorted list — same-window encounters resolve by UUID, minor.
- **Not affected (checked):** immunisation history (`generateVaccinationProgressDictsForWellChild` folds ALL encounters), growth charts + scorecard (bucketed by date), end-encounter gating (`:157-175` uses the real `id`).
- **Reachability.** `assembleProgresReportData` from `viewContent` (`:468`) for every initiator; pane renders in `ModeActiveDiagnosis` (`:531-535`) and in the WhatsApp report (`ComponentWellChildNextAppointment`).
- **Fix shape (first guess):** sort with `sortEncounterTuplesDesc` before `List.head` at `:369-374`, or take the head of `generateIndividualWellChildMeasurementsForChild` (already DESC).

- ⛔ **`reportData.wellChildEncounters` (`:427`) was deliberately LEFT UNSORTED, and sorting it would have been a regression.** It feeds `viewECDPane` → `generateECDMilestonesWithStatus`, which does `Dict.fromList` over `(milestone, status)` pairs; vendored `AssocList.fromList` is `List.foldl insert`, so the **last** entry for a key wins.
