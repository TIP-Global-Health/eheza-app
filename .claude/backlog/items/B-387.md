### B-387 — The new duplicate-English check documents a guarantee it does not implement: its exemption list is unbounded, so an already-exempt string can gain any number of new ids silently — READY · CONFIRMED (orchestrator read the loop, the exemption file and the commit message) · LOW · tier 4 · R33 unit 3 · CI guard rail, no user impact
- **Mechanism.** `ci-scripts/test_translations.js` skips an exempted English outright, with no count and no comparison against the previous state:
  ```js
  // ci-scripts/test_translations.js:170-173
      if (toFold.has(english)) {
        used.add(english);
        continue;
      }
  ```
  `ci-scripts/translations_to_fold.txt` is an ordinary text file (102 lines today). The only error the check raises about it is for an entry that is *no longer* duplicated (`:191`), so the list can only be pruned — never bounded. Nothing in the file reads git or `origin/develop`.
- **The documented guarantee does not exist.** Commit `8a0099761`'s message states: *"`ci-scripts/translations_to_fold.txt` lists the 197 strings still written out twice; the check makes that list shrink and refuses additions."* It makes the list shrink. **There is no mechanism that refuses additions** — a new id writing an already-listed English passes CI silently, and so does a new line added to the file.
- **Three further gaps** (scout-measured, orchestrator confirmed the shapes in the source):
  1. Today `"None of the above"` is written under 9 ids, `"Hepatitis B"` 7, `"Vitals"` / `"Positive"` / `"Infection"` 6 each — all exempt, all unbounded.
  2. **106 records are silently skipped, not reported.** `START = /^(\s*)\{ english = "((?:[^"\\]|\\.)*)"$/` with `if (!start) { return; }` drops every English built with `++` — 100 client, 6 server. Deliberate per the file's own comment ("An english built at run time from pieces cannot be compared"), but a real hole: e.g. `client/src/elm/Translate.elm:6773` and `:6780` both hold `{ english = "Missed ECD Milestone" ++ suffix_`.
  3. **The two copies are compared independently.** `byEnglish` is built inside `for (const file of FILES)` (`:122`, `:143`), so a string written in both `Translate.elm` files is never flagged — which is exactly the drift in [[B-386]].
- **Latent, not currently failing.** The comment tracker counts `{-`/`-}` inside string literals (`:73`); no translation string contains either today. A record whose `english` is not the first field, or whose `Just "…"` wraps a line, fails `START`/`FIELD`; none exist today — commit `2afaa9003` fixed that class by reordering `Dashboards` and making an unreadable record a hard failure. The check currently reports zero unreadable records.
- **Fix shape (guess).** If the "list only shrinks" guarantee is wanted it has to be enforced — compare the file against `origin/develop`'s copy in the check, or store a per-string id count. Cross-file comparison would be a separate mode, since the two copies legitimately translate some strings differently and cannot simply be merged into one map.
