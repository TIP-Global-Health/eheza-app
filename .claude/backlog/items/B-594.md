### B-594 — Prenatal: the two-hour blood-pressure recheck is scheduled only at the FIRST nurse visit, so a borderline reading (140–159 / 90–109) at a later visit gets no recheck and no hypertension diagnosis — READY · MED-HIGH · **tier 1 (standing rule: diagnosis determination)** ⚠ intent question for the user · CONFIRMED by reading (orchestrator read the guard, its three consumers and both spec issues; not run) · NOT sized · DEPLOYED all sites since 2024-06 (guard present on `origin/main`) · R55 unit 3
- **Mechanism.** Saving vitals with a borderline reading asks for the recheck:
  ```elm
  -- client/src/elm/Backend/Update.elm:2254-2260
                                                                -- When we suspect hypertension, we'll try to schedule vitals recheck.
                                                                -- generatePrenatalLabsTestAddedMsgs will schedule only if needed.
                                                                if
                                                                    Pages.Prenatal.Utils.marginalBloodPressureCondition dia sys
                                                                then
                                                                    Backend.Measurement.Model.TestNoteRunToday
  ```
  The builder refuses whenever ANY earlier nurse encounter exists, diagnosed or not:
  ```elm
  -- client/src/elm/Backend/Update.elm:9046-9052 (generatePrenatalLabsTestAddedMsgs)
                if
                    -- We allow Vitals recheck only during initial encounter.
                    -- At subsequent encounter, no need to retake blood preasure.
                    (test == Backend.Measurement.Model.TestVitalsRecheck)
                        && (not <| List.isEmpty assembled.nursePreviousEncountersData)
                then
                    []
  ```
  Without `TestVitalsRecheck` on the labs entry there is no Wait task (`Pages/Prenatal/Activity/Utils.elm:547-563`, `performedTests − completedTests`), no second phase (`Pages/Prenatal/Encounter/Utils.elm:1043-1052`, same two sets) and no Case Management entry. Both after-recheck diagnoses need the repeated values:
  ```elm
  -- client/src/elm/Pages/Prenatal/Activity/Utils.elm:3418-3427 (repeatedTestForMarginalBloodPressure)
                Maybe.map2 (\dia sys -> dia >= 90 || sys >= 140)
                    value.diaRepeated
                    value.sysRepeated
  ```
  So only an immediate reading of 160 / 110 or above diagnoses hypertension after the first visit; no methyldopa, and no after-recheck moderate preeclampsia either.
- **The app's own recurrent rule disagrees with the guard** — it skips the recheck only after a diagnosis:
  ```elm
  -- client/src/elm/Pages/Prenatal/RecurrentActivity/Utils.elm:737-743 (expectExaminationTask)
          ExaminationVitals ->
              -- Hypertension is a chronic diagnosis for whole duration
              -- of pregnancy. If diagnised, we do not need to recheck the BP.
              -- Measurement taken at initial phase of encounter is sufficient.
              (not <| diagnosedHypertensionPreviously assembled)
                  && (not <| diagnosedAnyOf hierarchalBloodPressureDiagnosesInitialPhase assembled)
  ```
  A later visit therefore does get the recheck when some other test happens to open the recurrent phase.
- **Reachability.** Nurse, second or later antenatal visit → Examination → Vitals 150/95 → Save. Gestational hypertension appears from week 20, which is mostly later visits.
