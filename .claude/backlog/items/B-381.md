### B-381 — Child Scoreboard registration: the birth-date calendar offers neither today nor a date that keeps the child searchable, so a newborn cannot be registered and a child registered on the earliest offered day vanishes from the Child Scoreboard search — READY · CONFIRMED (orchestrator read both bounds, the age predicate, the selector gate and the widget) · MED-LOW · tier 3 · R33 unit 6 · DEPLOYED, `ncda` sites (ihangane)
- **Mechanism.** The Child Scoreboard origin is the only one of the eight whose upper bound is not `today`, and the only child-expecting one whose lower bound carries no `+1 day`:
  ```elm
  -- client/src/elm/Pages/Person/View.elm:624-631
                          ChildScoreboardEncounter ->
                              { goBackPage = UserPage (IndividualEncounterParticipantsPage ChildScoreboardEncounter)
                              , expectedAge = ExpectChild
                              , expectedGender = ExpectMaleOrFemale
                              , birthDateSelectorFrom = Date.add Years -2 today
                              , birthDateSelectorTo = Date.add Days -1 today
                              , title = Translate.People
                              }
  ```
  Both ends are wrong by one day, in opposite directions.
- **(a) Today is unselectable.** The pair feeds `DateSelectorConfig` verbatim (`Pages/Person/View.elm:844-845`) and every day cell is gated by
  ```elm
  -- client/src/elm/DateSelector/Selector.elm:357
                                              else if not (Date.isBetween minimum maximum date) || isInvertedMinMax then
                                                  Disabled
  ```
  `Date.isBetween` is inclusive at both ends, so `maximum = today - 1` disables today. This is not CSS-only — a `Disabled` cell gets `property "time" = Json.Encode.null` (`Selector.elm:375-380`) and the `tbody` handler decodes `["target","time"]` as an int, so the tap does not register.
- **(b) The earliest offered day is already too old.** The search filter is `isChw && isChildUnderAgeOf2 currentDate person` (`Pages/IndividualEncounterParticipants/View.elm:93`), and
  ```elm
  -- client/src/elm/Backend/Person/Utils.elm:96-100
  isChildUnderAgeOf : Int -> NominalDate -> Person -> Bool
  isChildUnderAgeOf years currentDate person =
      ageInYears currentDate person
          |> Maybe.map (\age -> age < years)
          |> Maybe.withDefault False
  ```
  `Date.add Years -2 today` gives `ageInYears == 2`, which fails `< 2`. The child is not blocked at creation — `Backend/Update.elm:4468` navigates straight to the participant page — but never appears in the Child Scoreboard search again.
- **Why this is a copy-adapt slip, not intent.** The two sibling lower bounds that are correct carry the guard explicitly: `Pages/Person/View.elm:667` and `:771` both read `Date.add Years -13 today |> Date.add Days 1`. Child Scoreboard has no `+1` on `dateFrom` and a `-1` on `dateTo` that no sibling has (orchestrator grepped all eight pairs: 611, 638, 650, 668, 677, 686, 748, 772 all end at `today`; 629 is the only `Date.add Days -1 today`).
- **Reachability / impact.** Birth date is a required field whose only input is the calendar — a `div` with `onClick <| SetDateSelectorState (Just dateSelectorConfig)` and no text entry (`Pages/Person/View.elm:849-863`). So a nurse registering a child born today must enter a wrong date or abandon the registration. Path: Clinical → Individual Encounter Types (CHW + `ncda` flag) → Child Scoreboard → participants → Register new participant.
- **Sizing.** Same-day-of-birth registration is real: 87 `person` nodes on ihangane.live since 2024-01-01 have `field_birth_date` equal to their own node creation date. Those came through flows that allow `today`; this flow would have pushed each to a wrong date. `ncda` is on for ihangane only.
- **Not a re-find.** B-256 covers the `-13 years` members of this family (`:685`, `:588`, `:710`) and names neither the `-2 years` bound nor the `Days -1` upper bound; Child Scoreboard is not in its list. B-310 is the server-side scorecard denominator. No backlog row mentions `birthDateSelector`.
- **Fix shape (guess).** Lower bound `|> Date.add Days 1`, upper bound `today` — or better, derive both from `isChildUnderAgeOf2` so they cannot drift again, which is the same remark B-256 already makes for the 13-year bounds.
