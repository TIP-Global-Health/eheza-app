### B-230 — Prenatal diagnoses: `gonorrhea-continued` is encoded and stored but the client decoder has no branch for it, so the diagnosis vanishes from the encounter on every re-read — ✅ IMPLEMENTED · CONFIRMED (anchors + producer verified) · MED · tier 3 · R24 unit 4
- **Mechanism.** `Backend/PrenatalEncounter/Encoder.elm:293-294` emits `"gonorrhea-continued"` for `DiagnosisGonorrheaContinued`; `Backend/PrenatalEncounter/Decoder.elm:283-298` decodes `candidiasis-continued`, `trichomonas-or-bv-continued`, `urinary-tract-infection-continued`, `pelvic-pain-continued` — but only `"gonorrhea"`, never `"gonorrhea-continued"`. `prenatal_diagnoses` / `past_prenatal_diagnoses` are read with `decodeListDroppingUnknown` (`Decoder.elm:26`; `Utils/Json.elm:79-83` = `oneOf [Just, Nothing]` + filterMap), so the unknown string is silently dropped instead of failing the batch. Drupal accepts it (`hedley_prenatal.features.field_base.inc` lists `gonorrhea-continued`) and `hedley_reports.module:10382` maps it, so the server side is whole — only the client loses it. Introduced with the continued diagnoses in `e8b22dbbc` (2022-05-22); identical on `origin/main`.
- **Reachability.** `Pages/Prenatal/Activity/Utils.elm:3098` `matchSymptomsPrenatalDiagnosis DiagnosisGonorrheaContinued = gonorrheaDiagnosed && diagnosedPreviously DiagnosisGonorrhea`, in `resolveSymptomsDiagnoses` (:3566) for every non-postpartum nurse encounter → set on the encounter via `SetPrenatalDiagnoses`, uploaded, stored. Then every decode — the same device's IndexedDB read on the next page load, and every other device's download — drops it.
- **Impact.** Consumers that see nothing: `diagnosesCausingHospitalReferralByImmediateDiagnoses` (`Pages/Prenatal/Utils.elm:269` — hospital referral logic), the progress report diagnosis list (`Pages/Prenatal/ProgressReport/View.elm:~3125`), and `diagnosedPreviously` in later encounters (so a THIRD gonorrhea encounter re-derives "continued" from `DiagnosisGonorrhea` history rather than the dropped record — masks the loss in that one path). Nothing is lost server-side; a decoder fix restores existing records on next download. All sites.
