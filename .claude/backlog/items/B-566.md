### B-566 — Nutrition (individual, CHW): reopening a Height or Weight already marked "unable to take" after a reload shows the box ticked and Save enabled, and Save does nothing — READY · LOW · tier 4 · CONFIRMED (every hop read by the orchestrator on 69ff78c1d; scout scratch elm-test 3/3 in its worktree) · CHW only (height both sites, weight Burundi) · DEPLOYED · R52 unit 5
- **Mechanism.** The View hydrates the form from the encounter's skip flag, the Save handler reads the RAW form for the not-taken check and the HYDRATED form for the value, and on a fresh page model the two disagree:
  ```elm
  -- client/src/elm/Measurement/Utils.elm:760-772 (heightFormWithDefault; weight twin :848-860)
      let
          isSkipped =

          { height = Nothing
          , heightDirty = False

  ```
  ```elm
  -- client/src/elm/Pages/Nutrition/Activity/Update.elm:119-160 (SaveHeight; SaveWeight twin :327-368)
          SaveHeight skippedForms personId saved ->
              let
                  form_ =
                      model.heightData.form

                      if form_.measurementNotTaken == Just True then

                      else
                          ...

                              |> unwrap
                                  []

  ```
  With `emptyHeightForm` (`measurementNotTaken = Nothing`) and `SkippedHeight` on the encounter: the View (`Pages/Nutrition/Activity/View.elm:249-272`) renders the box ticked, hides the input, counts 1/1 tasks and enables Save; `PreSaveHeight` (`Update.elm:62-67`) hydrates and finds nothing out of range; `SaveHeight` takes the `else` branch (raw `Nothing`), `toHeightValueWithDefault` re-hydrates to `height = Nothing`, `toHeightValue` → `Nothing` → `appMsgs = []`. No save, no navigation, no message. The page model lives in `nutritionActivityPages`, which `App/Update.elm:701-706` only ever inserts into — never reset on navigation — so in the same session the raw form still holds `Just True` and Save works; the dead button needs a fresh model.
- **Reachability.** CHW Nutrition encounter (checkbox rendered `if isChw`, `Measurement/View.elm:4358-4374`; weight `if isChw && site == SiteBurundi`, `:4624-4628`): skip Height → the activity moves to Completed (`activityCompleted` via `SkippedHeight`, `Pages/Nutrition/Activity/Utils.elm:100-103`) → the app reloads (self-refresh after a long sync, re-login, version click) or the flag arrives from another device → reopen Height → Save is enabled and dead.
