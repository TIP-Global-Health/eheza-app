### B-288 — NCD: diabetes found from a point-of-care blood-sugar reading at the initial phase gets no medication or referral task, because the initial-phase rules assume `DiagnosisDiabetesRecurrent` cannot exist yet — ✅ IMPLEMENTED 2026-09-08 (issue #2219, PR #2220, branch `B-288-point-of-care-diabetes-tasks`, base `B-286-ncd-staging-own-diagnoses` @475bc3b97) · CONFIRMED (diagnosis path + all four initial-phase gates verified) · MED · tier 1 · R26 unit 5
- **Mechanism.** The NCD RBS form asks "immediate result?" and takes the reading (`Measurement/Utils.elm:5457-5490`; `Activity/Update.elm:1270` `PreSaveRandomBloodSugarTest` gates on `immediateResult == Just True`). That save is an `NCDRandomBloodSugarTestRevision` → `processRevisionAndAssessNCD` → `matchNCDDiagnosis DiagnosisDiabetesRecurrent` (`Pages/NCD/Utils.elm:219-235`, `diabetesBySugarCount`) → the encounter now carries `DiagnosisDiabetesRecurrent` AT THE INITIAL PHASE. But every initial-phase rule keys on `DiagnosisDiabetesInitial` (co-morbidities) only: `medicateForDiabetes NCDEncounterPhaseInitial = diagnosed DiagnosisDiabetesInitial || diagnosedPreviouslyWithDiabetes` (`:578-580`); `referForDiabetes … Initial` (`:970-972`); `medicateForHypertension Initial` Stage-1 arm (`:605`); `expectNextStepsTask TaskHealthEducation` (`Activity/Utils.elm:145`, `not <| diagnosedAnyOf [ Renal, DiabetesInitial ]`). The code states the assumption (`:726-727` *"which can happen only on recurrent phase of encounter"*; `:603-604`). `git log -S` dates `medicateForDiabetes` to `eca6862f7` and the immediate-result option to the later universal-form work (`3c206091a`/`bbc76b4e1`) — a gate written before the option existed.
- **Why the recurrent page does not rescue it.** The recurrent-phase rules handle `DiagnosisDiabetesRecurrent`, but that page exists only behind a labs-results Case Management entry, and an immediate RBS result never CREATES one: `resultsAdded = isJust sugarCount` (`Backend/Update.elm:3572`) routes to `generateNCDLabsResultsAddedMsgs`, which only updates an existing entry (`:9421-9424`, `Maybe.andThen … assembled.measurements.labsResults`).
- **Reachability.** Any encounter where RBS is read on the spot and no other test went to the lab. At a FIRST encounter the yearly tests usually create an entry, so the task appears — oddly — in the recurrent phase. At follow-ups within 12 months typically only RBS (always expected) and HbA1c (immediate, never in the labs system) run, so a new diabetic found there gets nothing until the next visit, when `diagnosedPreviouslyWithDiabetes` finally medicates.
- **Impact.** A patient leaves with a diabetes diagnosis on the record and no treatment/referral step offered; `expectActivity NextSteps` (`Activity/Utils.elm:75-80`) is simply false and End Encounter is enabled. A co-existing new Stage 1 gets health education instead of medication. Both sites. Independent of B-056 (declined — that is the referral's hypertension gate, not the phase gate).
- **Fix shape (guess).** Treat `DiagnosisDiabetesRecurrent` present at the initial phase (equivalently `labTestWithImmediateResult .randomBloodSugarTest`, as prenatal does) like `DiagnosisDiabetesInitial` in the four initial-phase rules; completion already shares `recommendedTreatmentMeasurementTaken`, so the recurrent task would show as done.
