### B-339 — NCD diagnosis: re-scoring an older encounter after a later one exists reads the LATER encounter's stage (and diabetes/renal) as its history — a lab result entered for encounter A after encounter B was started rewrites A's hypertension stage to B's, and drops A's diabetes/renal finding when B already has it — ✅ IMPLEMENTED (issue #2240, PR #2241, branch `B-339-ncd-history-before-encounter`, base `1bd37a26d`, commit `c0ae3b50b`, 2026-09-14) · CONFIRMED (history builder, staging, both filter sites, the revision trigger and the pre-#2216 line read by the orchestrator) · MED-LOW · tier 1 (diagnosis rule) · R30 unit 3 · ⚠ the stage half is INTRODUCED by #2216 (B-286), merged, NOT deployed — live-sized: 1 lab result on ihangane saved after a later encounter of the same participant existed
- **Mechanism.** `generatePreviousEncountersData` (`client/src/elm/Pages/NCD/Utils.elm:78-102`) returns every NCD encounter of the participant except the one being scored — including encounters that started AFTER it — sorted newest first:
  ```elm
  -- client/src/elm/Pages/NCD/Utils.elm:78-102
  generatePreviousEncountersData currentEncounterId participantId db =
      getNCDEncountersForParticipant db participantId
          |> List.filterMap
              (\( encounterId, encounter ) ->
                  if currentEncounterId == Just encounterId then
                      Nothing
                  ...
          |> List.sortWith sortByStartDateDesc
  ```
  Since #2216 staging reads that list directly:
  ```elm
  -- client/src/elm/Pages/NCD/Utils.elm:121-127
          currentHypertensionCondition =
              ...
              resolveHypertensionCondition assembled.previousEncountersData
  ```
  and `resolveHypertensionCondition` takes the first entry carrying a hypertension stage — B, when B is later. Before #2216 the call was `resolveCurrentHypertensionCondition assembled`, which consed the encounter's OWN stored diagnoses onto the head (`git show 62b029b9d:client/src/elm/Pages/NCD/Utils.elm:320-328`), so A's own stage masked B. `filterDiagnosesOfDeterminedConditions` (`:182-202`) reads the same unfiltered list for `diagnosedPreviouslyWithDiabetes` / `diagnosedPreviously DiagnosisRenalComplications` — that half pre-dates #2216. The date-limited filter exists and is used by other readers in the same file (`filterPreviousEncountersDataToDate encounterDate assembled.previousEncountersData`, `:1013`, `:1081`; defined `Pages/Utils.elm:269-274`, strict `LT`), but not by generation.
