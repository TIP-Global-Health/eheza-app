### B-627 — Village import script: running the same file again creates every village a second time, each with its own CHW group and participations — READY · CONFIRMED by reading (orchestrator read the script and the insert hook; nothing run) · LOW · tier 4 · R61 unit 2 · production script, all sites, not sized (no evidence it has happened)
- **Mechanism.** `migrate-villages.php` creates a node for every row with no check that the village exists, and it carries on after three kinds of skipped row — so a partly successful run is a normal outcome.
  ```php
  -- server/hedley/modules/custom/hedley_migrate/scripts/migrate-villages.php:30-33, 39-45, 50-53, 65-71
    if (count($row) < 6) {
      drush_print('Skipping a row with fewer than six columns: ' . implode(',', $row));
      continue;
    }
  ...
      if (empty($health_center_id)) {
        drush_print("Could not resolve health center $health_center_name");
        drush_print("Skipping creation of $village_name village");
        continue;
      }
  ...
    $node = entity_create('node', [
      'type' => 'village',
      'uid' => 1,
    ]);
  ...
    try {
      $wrapper->save();
    }
    catch (Exception $e) {
      drush_print("Skipping creation of $village_name village: " . $e->getMessage());
      continue;
    }
  ```
- **Each insert does more than add a village.** `hedley_chw_process_new_village()` creates a clinic and enrols the residents:
  ```php
  -- server/hedley/modules/custom/hedley_chw/hedley_chw.module:87-97
    $clinic_node = entity_create('node', [
      'type' => 'clinic',
      'uid' => $node->uid,
    ]);
    ...
    $clinic_wrapper->title->set("$village_name CHW group");
    $clinic_wrapper->field_health_center->set($health_center_id);
    $clinic_wrapper->field_village_ref->set($village_id);
    $clinic_wrapper->field_group_type->set('chw');
    $clinic_wrapper->save();
  ```
- **Reachability.** An operator runs `drush scr … --file=X.csv` on a live site, sees skipped rows (a misspelt health center, a blank field — the refusal added with [[B-388]]), corrects the file and runs it again. Every row that succeeded the first time is created again; the twin villages and CHW groups sync to every device of the site.
- **Not the declined class.** "Continue past bad data" in the import is declined; this is about the repeat run, which the existing skip-and-continue invites.
- **Sizing.** None. A count of villages sharing all five location names and the health center, per site, would show whether it has happened.
- **Fix shape (guess).** Skip a row whose five names and health center already exist, and print that it was skipped. The script also does not trim names (noted under [[B-389]]).
